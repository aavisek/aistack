## Why this matters
Classes let a program keep related data and behavior together. Instead of passing separate values through many functions, an object can represent one meaningful thing and expose the operations that belong to it.

## What you will build
A `BankAccount` class with account data, methods, and two independent account objects.

## Before you start
Use Python 3.10 or newer. Create `bank_account.py` and run it with `python3 bank_account.py` on macOS/Linux or `py -3 bank_account.py` in Windows PowerShell.

## Step 1: Define a class
The class body describes what an object of that type can do. A method receives the object as its first parameter; the conventional name is `self`.

```python title="bank_account.py" file
class BankAccount:
    def deposit(self, amount):
        self.balance += amount

    def summary(self):
        return f"{self.owner}: ${self.balance}"


account = BankAccount()
account.owner = "Mina"
account.balance = 100
account.deposit(25)
print(account.summary())
```

```bash title="Terminal" verify="run"
python3 bank_account.py
```

```text title="Expected output"
Mina: $125
```

## Step 2: Create multiple objects
Calling the class creates another object. Each instance has its own attributes, so changing one account does not change the other.

```python title="two_accounts.py" file
class BankAccount:
    def summary(self):
        return f"{self.owner}: ${self.balance}"


first = BankAccount()
first.owner, first.balance = "Mina", 125
second = BankAccount()
second.owner, second.balance = "Omar", 80
print(first.summary())
print(second.summary())
print(first is second)
```

```bash title="Terminal" verify="run"
python3 two_accounts.py
```

```text title="Expected output"
Mina: $125
Omar: $80
False
```

## Step 3: Keep behavior with the data
Methods can validate input and update the object's state. Returning a clear result makes the class easy to use from other code.

```python title="safe_account.py" file
class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def withdraw(self, amount):
        if amount > self.balance:
            return False
        self.balance -= amount
        return True


account = BankAccount("Mina", 125)
print(account.withdraw(40), account.balance)
print(account.withdraw(100), account.balance)
```

```bash title="Terminal" verify="run"
python3 safe_account.py
```

```text title="Expected output"
True 85
False 85
```

## Step 4: Inspect an object's state
Instance attributes are stored on the object. `vars()` is useful while learning, but public methods are usually a better long-term interface.

```python title="inspect_account.py" file
class BankAccount:
    def __init__(self, owner):
        self.owner = owner
        self.balance = 0


account = BankAccount("Mina")
account.balance = 25
print(vars(account))
print(account.owner, account.balance)
```

```bash title="Terminal" verify="run"
python3 inspect_account.py
```

```text title="Expected output"
{'owner': 'Mina', 'balance': 25}
Mina 25
```

## How it works
`class BankAccount:` creates a type. Calling `BankAccount()` creates an instance. Attributes store state on that instance, while methods describe operations. Dot notation selects an attribute or method from a particular object.

## Common errors
### Calling a method without an object
`BankAccount.summary()` has no instance to use. Call `account.summary()` instead.

### Forgetting `self`
Instance methods need `self` as their first parameter so they can access instance attributes.

### Sharing accidental state
Do not put per-object values in class attributes unless sharing is intentional.
