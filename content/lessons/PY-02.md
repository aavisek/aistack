## Why this matters
Numeric and Boolean expressions sit inside everyday application logic: prices, counters, ranges, flags, and conditions. Python's operators look familiar, but details such as negative floor division, floating-point rounding, and how `and` returns values can affect real results.

## What you will build
A small Python reference script that prints numeric types, safe comparisons, Boolean results, and a formatted value. Along the way, you will learn how to choose exact decimal arithmetic when appropriate.

## Before you start
Use Python 3.10 or newer and open a terminal in a new folder. Create `numbers_booleans_operators.py`. You can run it with `python3 numbers_booleans_operators.py` on macOS/Linux or `py -3 numbers_booleans_operators.py` in Windows PowerShell.

## Step 1: Recognize Python's number types
Python supports integers (`int`), binary floating-point numbers (`float`), complex numbers (`complex`), and Booleans (`bool`). A Boolean is also an integer subtype, so `isinstance(True, int)` is true even though code should normally treat flags as Booleans.

```python title="numbers_booleans_operators.py" file
whole = 42
million = 1_000_000
hex_value = 0xFF
ratio = 3.14
scientific = 1e3
imaginary = 3 + 4j
ready = True

print(type(whole).__name__, type(ratio).__name__, type(imaginary).__name__)
print(hex_value, million, scientific)
print(isinstance(ready, bool), isinstance(ready, int))
```

```text title="Expected output"
int float complex
255 1000000 1000.0
True True
```

Underscores make long integer literals easier to read. A leading-zero decimal such as `007` is invalid syntax; use `7`. `bool` is a subclass of `int`, so prefer `isinstance(value, bool)` when a real Boolean is required.

## Step 2: Convert values and use integer arithmetic
Conversions can be useful, but they do not always round. `int(3.9)` truncates toward zero. Integer division with `/` returns a float, while `//` rounds down toward negative infinity; `%` follows the divisor's sign.

```python title="numbers_booleans_operators.py" file
print(int(3.9), int(-3.7), int("ff", 16))
print(5 / 2, 5 // 2, -7 // 2, -7 % 3)
print(divmod(-7, 2))
print(2 ** 3 ** 2, -2 ** 2, (-2) ** 2)
```

```text title="Expected output"
3 -3 255
2.5 2 -4 2
(-4, 1)
512 -4 4
```

Exponentiation associates from the right, so `2 ** 3 ** 2` means `2 ** (3 ** 2)`. Unary minus has lower precedence than exponentiation, which is why parentheses matter in `(-2) ** 2`.

## Step 3: Handle floating-point results carefully
Most decimal fractions cannot be represented exactly as binary floating-point values. Compare approximate results with `math.isclose`, and avoid using `float` for exact money calculations.

```python title="numbers_booleans_operators.py" file
import math
from decimal import Decimal
from fractions import Fraction

total = 0.1 + 0.2
print(total)
print(total == 0.3)
print(math.isclose(total, 0.3))
print(round(2.5), round(3.5))
print(Decimal("0.1") + Decimal("0.2"))
print(Fraction(1, 3) + Fraction(1, 6))
```

```text title="Expected output"
0.30000000000000004
False
True
2 4
0.3
1/2
```

Python's `round` uses ties-to-even for exact halfway cases. Build `Decimal` values from strings, not floats, to avoid carrying a float's approximation into the decimal value. `Fraction` is useful when an exact rational ratio is the clearest representation.

## Step 4: Read Boolean values and truthiness
Conditions treat empty containers, zero, `None`, and `False` as falsy. Most other objects—including non-empty strings such as `"False"`—are truthy. The operators `and` and `or` short-circuit and return one of their operands, not necessarily a `bool`.

```python title="numbers_booleans_operators.py" file
items = []
label = ""

print(bool(items), bool("False"), bool(" "))
print(items or ["default"])
print(3 and 4, [] and "unused")
print(all([]), any([]))
```

```text title="Expected output"
False True True
['default']
4 []
True False
```

`not` always returns a Boolean. `and` stops at the first falsy operand; `or` stops at the first truthy operand. This makes expressions such as `items or fallback` useful, while also making it important to remember that the returned value may be a list, string, or number.

## Step 5: Compare values and write clear conditions
Use `==` for value equality, `is` for identity (especially `is None`), and `in` for membership. Chained comparisons are concise and evaluate the middle expression only once.

```python title="numbers_booleans_operators.py" file
age = 32
items = [1, 2, 3]
missing = None

print(18 <= age < 65)
print(2 in items, missing is None)
print(1 == 1.0 == True)
print("10" < "9")
```

```text title="Expected output"
True
True True
True
True
```

Strings compare lexicographically, so `"10" < "9"` is true as text. Use `is` to test for `None`, not to compare numbers or strings. Avoid conditions such as `if value == 1 or 2`; write `if value in (1, 2)` instead.

## Step 6: Use arithmetic and bitwise operators deliberately
Arithmetic includes `+`, `-`, `*`, `/`, `//`, `%`, `**`, and matrix multiplication `@` for types that define it. Bitwise operators (`&`, `|`, `^`, `~`, `<<`, `>>`) work on integer bits and can be useful for flags and masks.

```python title="numbers_booleans_operators.py" file
permissions = 0b0101
write_flag = 0b0010

print(5 & 3, 5 | 3, 5 ^ 3)
print(5 << 2, -5 >> 1)
print(format(10, "08b"), f"{255:#x}")
print(permissions | write_flag)
```

```text title="Expected output"
1 7 6
20 -3
00001010 0xff
7
```

Python integers have arbitrary precision, so `~x` produces a signed integer rather than a fixed-width bit pattern. Mask explicitly when you need a fixed width. Parentheses are helpful when mixing bitwise operators with comparisons.

## Step 7: Put the rules together
This example checks an input before dividing, uses a chained comparison for the accepted range, and formats the result for display.

```python title="numbers_booleans_operators.py" file
import math

numerator = 22
denominator = 7

if denominator != 0:
    quotient = numerator / denominator
    in_range = 3 < quotient < 4
    print(f"quotient={quotient:.2f}")
    print(f"in range: {in_range}")
    print(math.isclose(quotient, 22 / 7))
else:
    print("cannot divide by zero")
```

```text title="Expected output"
quotient=3.14
in range: True
True
```

Formatting changes how a number is displayed, not the underlying value. Use `:.2f` to display two digits after the decimal point. Keep full precision during calculations and format the result at the point where it is shown.

## How it works
Python evaluates expressions according to precedence: grouping and calls bind tightly, then exponentiation, unary operators, multiplication/division, addition/subtraction, shifts, bitwise operators, comparisons, `not`, `and`, and `or`. Most binary operators associate left to right, but `**` associates right to left. Use parentheses whenever they make the intent easier to see.

Division by zero raises `ZeroDivisionError`; invalid conversions can raise `ValueError`; operations on incompatible types can raise `TypeError`; and very large float operations may overflow. Python's `math` functions use radians for trigonometry.

## Common errors
### Expecting `//` to truncate toward zero
`-7 // 2` is `-4`, because floor division rounds down. Use `int(-7 / 2)` only when truncation toward zero is specifically desired.

### Comparing floats with exact equality
`0.1 + 0.2 == 0.3` is false because the binary approximations differ. Use `math.isclose` for approximate comparisons or `Decimal` for decimal arithmetic requirements.

### Assuming `and` and `or` always return Booleans
They return one of their operands. Use `bool(expression)` if you specifically need a Boolean result.

### Testing identity instead of equality
Use `value == expected` for a value comparison and `value is None` for the `None` singleton. Do not rely on `value is 1000`.

### Writing an always-true disjunction
`value == 1 or 2` is true because `2` is truthy. Use `value in (1, 2)` to test either value.

## Recap
- `/` returns a float, `//` floors, and binary floats may need approximate comparison.
- `and` and `or` short-circuit and return operands; use `is None` for the `None` singleton.
- Parentheses clarify precedence, and `Decimal` is preferable when exact decimal arithmetic is needed.
