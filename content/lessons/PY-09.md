## Why this matters
Python lets your own classes behave like built-in types: `a + b`, `a == b`, `len(a)`, `a[0]`, and `sorted(items)` all work once the class defines the matching special methods. Done well, this makes code read naturally. Done badly, it produces surprising bugs such as unhashable objects or `TypeError` messages that appear at the wrong time. The same skills help with `bytearray`, Python's mutable binary buffer, which you meet when you build network packets, read files, or edit raw data in place.

## What you will build
Small, standalone Python scripts that teach a `Vector` and a `Version` class to use operators, show how reflected and in-place operators work, and explain hashing. You then compare `bytes` with `bytearray`, edit a buffer in place, convert between text, integers, and bytes, and finish with a `ByteBuffer` class that combines both ideas.

## Before you start
Use Python 3.10 or newer and create each named file in one practice folder, because a few scripts import an earlier file. Every example is run with `python3 filename.py` on macOS/Linux, or with `py -3 filename.py` in Windows PowerShell.

You should be comfortable with defining classes and `__init__`, with string formatting and slicing from PY-03, and with list indexing, slicing, and in-place methods from PY-04. Mutability from PY-02 matters here: `bytes` is immutable, while `bytearray` is mutable like a list.

## Step 1: See how an operator calls a method
When Python evaluates `a + b`, it calls `a.__add__(b)`. If that method is missing or returns `NotImplemented`, Python tries the reflected method `b.__radd__(a)`. If both give up, Python raises `TypeError` itself. This is why an unsupported operand should return `NotImplemented` instead of raising an error.

```python title="dunder_dispatch.py" file
class Money:
    def __init__(self, cents):
        self.cents = cents

    def __repr__(self):
        return f"Money({self.cents})"

    def __add__(self, other):
        print("Money.__add__ called")
        if not isinstance(other, Money):
            return NotImplemented
        return Money(self.cents + other.cents)

    def __radd__(self, other):
        print("Money.__radd__ called")
        if not isinstance(other, int):
            return NotImplemented
        return Money(self.cents + other)


a = Money(250)
b = Money(100)
print(a + b)
print(a.__add__(b))
print(a.__add__("x"))
print(50 + a)

try:
    a + "x"
except TypeError as error:
    print("TypeError:", error)
```

```bash title="Terminal" verify="run"
python3 dunder_dispatch.py
```

```text title="Expected output"

Money(350)
Money.__add__ called
Money(350)
Money.__add__ called
NotImplemented
Money.__radd__ called
Money(300)
Money.__add__ called
TypeError: unsupported operand type(s) for +: 'Money' and 'str'
```

`50 + a` first asks `int.__add__`, which declines, so Python calls `a.__radd__(50)`. For `a + "x"`, `str` has no reflected method that accepts a `Money`, so Python raises the `TypeError`.

## Step 2: Build a Vector class
A 2-D `Vector` shows the most common overloads. Binary operators return a new object, `__rmul__ = __mul__` makes `3 * v` work, and `__neg__` and `__abs__` serve `-v` and `abs(v)`. The class also defines `__eq__`, `__hash__`, `__bool__`, and `__getitem__`, which the next step uses.

```python title="vector.py" file
class Vector:
    """A 2-D vector that works with the usual operators."""

    def __init__(self, x, y):
        self.x, self.y = x, y

    def __repr__(self):  # what the REPL and repr() show
        return f"Vector({self.x}, {self.y})"

    def __add__(self, other):  # v + w
        if not isinstance(other, Vector):
            return NotImplemented  # let Python try the other side / raise TypeError
        return Vector(self.x + other.x, self.y + other.y)

    def __sub__(self, other):  # v - w
        if not isinstance(other, Vector):
            return NotImplemented
        return Vector(self.x - other.x, self.y - other.y)

    def __mul__(self, k):  # v * 3 (scalar multiplication)
        if not isinstance(k, (int, float)):
            return NotImplemented
        return Vector(self.x * k, self.y * k)

    __rmul__ = __mul__  # 3 * v (reflected version)

    def __neg__(self):  # -v
        return Vector(-self.x, -self.y)

    def __abs__(self):  # abs(v) = length
        return (self.x ** 2 + self.y ** 2) ** 0.5

    def __eq__(self, other):  # v == w
        if not isinstance(other, Vector):
            return NotImplemented
        return (self.x, self.y) == (other.x, other.y)

    def __hash__(self):  # required again once __eq__ is defined
        return hash((self.x, self.y))

    def __bool__(self):  # the zero vector is falsy
        return bool(self.x or self.y)

    def __getitem__(self, i):  # v[0], v[1], and unpacking
        return (self.x, self.y)[i]


if __name__ == "__main__":
    v = Vector(3, 4)
    w = Vector(1, 2)
    print(v + w)
    print(v - w)
    print(v * 2)
    print(2 * v)
    print(-v)
    print(abs(v))
```

## Step 3: Compare, test, index, and unpack
Equality, truthiness, indexing, and hashing work through their own special methods. `__ne__` is derived from `__eq__`, so `!=` needs no code. Because `__getitem__` accepts 0 and 1 and then raises `IndexError`, unpacking works. When `__eq__` returns `NotImplemented` for a tuple, Python falls back to identity, so the result is `False`.

```python title="vector_more.py" file
print({v: "a point"}[Vector(3, 4)])

try:
    v + 5

print(v)
```

## Step 4: Order objects with @total_ordering
Writing all six comparison methods is repetitive. Define `__eq__` and one ordering method such as `__lt__`, and `functools.total_ordering` generates `<=`, `>`, and `>=`. Once a class can be ordered, `sorted()`, `max()`, and `min()` work on it.

```python title="version.py" file
from functools import total_ordering


@total_ordering
class Version:
    def __init__(self, major, minor):
        self.major, self.minor = major, minor

    def __eq__(self, other):
        return (self.major, self.minor) == (other.major, other.minor)

    def __lt__(self, other):
        return (self.major, self.minor) < (other.major, other.minor)

    def __repr__(self):
        return f"v{self.major}.{self.minor}"


print(Version(3, 12) < Version(3, 13))
print(Version(3, 13) >= Version(3, 13))
print(Version(3, 13) > Version(3, 9))
print(Version(3, 9) <= Version(3, 9))
print(sorted([Version(3, 13), Version(2, 7), Version(3, 9)]))
print(max(Version(3, 13), Version(3, 9)))
```

## Step 5: Use in-place operators and sum()
`a += b` uses `__iadd__` when it exists, and otherwise falls back to `a = a + b`. An in-place method must change `self` and return `self`. To let `sum()` work on your objects, add `__radd__` that accepts `0`, because `sum` starts with `0 + first`.

```python title="inplace_sum.py" file
class Total:
    def __init__(self, value):
        self.value = value

    def __repr__(self):
        return f"Total({self.value})"

    def __add__(self, other):
        if not isinstance(other, Total):
            return NotImplemented
        return Total(self.value + other.value)

    def __radd__(self, other):  # sum() starts from 0 + first
        if other == 0:
            return self
        return NotImplemented


class Counter:
    def __init__(self, n):
        self.n = n

    def __repr__(self):
        return f"Counter({self.n})"

    def __iadd__(self, step):  # in place: change self and return self
        self.n += step
        return self


t1 = Total(5)
t2 = t1
t1 += Total(2)
print(t1, t2, t1 is t2)

c1 = Counter(1)
c2 = c1
c1 += 4
print(c1, c2, c1 is c2)

print(sum([Total(1), Total(2), Total(3)]))
```

```bash title="Terminal" verify="run"

```

```text title="Expected output"

Counter(5) Counter(5) True
Total(6)
```

`Total` has no `__iadd__`, so `t1 += ...` built a new object and `t2` kept the old value. `Counter` changed in place, so both names saw the change.

## Step 6: Keep equality and hashing consistent
Defining `__eq__` without `__hash__` sets `__hash__` to `None`, which makes instances unhashable: they cannot be set members or dictionary keys. Either define both so equal objects hash the same, or leave the class unhashable on purpose, as you would for a mutable object.

```python title="hashable.py" file
class Plain:
    def __init__(self, n):
        self.n = n


class Equal:
    def __init__(self, n):
        self.n = n

    def __eq__(self, other):
        return isinstance(other, Equal) and self.n == other.n


class EqualHash(Equal):
    def __hash__(self):
        return hash(self.n)


print(len({Plain(1), Plain(1)}))
print(Equal(1) == Equal(1))

try:
    {Equal(1): "x"}
except TypeError as error:
    print("TypeError:", error)

print(len({EqualHash(1), EqualHash(1)}))
```

```bash title="Terminal" verify="run"
python3 hashable.py
```

```text title="Expected output"

True
TypeError: unhashable type: 'Equal'
1
```

`Plain` uses identity for both equality and hashing, so two instances stay separate. `EqualHash` treats equal values as one set member.

## Step 7: Support len(), in, loops, calls, and str()
Many everyday features are protocols, each backed by a special method: `len()` uses `__len__`, `in` uses `__contains__`, `for` uses `__iter__`, `x[i]` uses `__getitem__`, `x[i] = v` and `del x[i]` use `__setitem__` and `__delitem__`, `x(...)` uses `__call__`, and `str()` uses `__str__`. A class with only `__len__` is falsy when its length is 0.

```python title="protocols.py" file
class Playlist:
    def __init__(self, *songs):
        self.songs = list(songs)

    def __repr__(self):
        return f"Playlist({', '.join(self.songs)})"

    def __str__(self):
        return f"{len(self)} songs"

    def __len__(self):
        return len(self.songs)

    def __contains__(self, song):
        return song in self.songs

    def __iter__(self):
        return iter(self.songs)

    def __setitem__(self, i, song):
        self.songs[i] = song

    def __delitem__(self, i):
        del self.songs[i]

    def __getitem__(self, i):
        return self.songs[i]

    def __call__(self, i):
        return f"Now playing {self.songs[i]}"


p = Playlist("Intro", "Verse", "Outro")
print(len(p), "Verse" in p, "Solo" in p)
print([s.upper() for s in p])
p[1] = "Chorus"
del p[0]
print(p, str(p), repr(p))
print(p(0))
print(bool(Playlist()), bool(p))
```


`print(p)` uses `__str__`, while `repr(p)` uses `__repr__`. Defining `__getitem__` together with `__len__` also makes a class behave like a sequence.

## Step 8: Compare bytes and bytearray
`bytes` is an immutable sequence of integers from 0 to 255, and `bytearray` is the same thing but mutable. A `bytes` object is hashable, so it can be a dictionary key; a `bytearray` is not. Indexing either one gives an `int`. Text needs an explicit encoding to become bytes, and `decode()` reverses it.

## Step 10: Use methods, hex, integers, and struct
`bytearray` has many string-like methods, and they return new `bytearray` objects. `hex(" ")` makes a readable dump, `bytes(data)` freezes a copy, and `reverse()` changes the buffer in place. Integers convert with `to_bytes()` and `int.from_bytes()`, where the byte order is `"big"` or `"little"`. The `struct` module packs and unpacks fixed binary layouts.

## Step 11: Avoid copies and spot the gotchas
A `memoryview` is a zero-copy window onto a buffer, so writing through it changes the original `bytearray`. `readinto()` fills an existing buffer instead of allocating a new one. This step also shows the three classic gotchas: a size versus a one-item list, an `int` versus a one-byte slice, and mixing `str` with `bytes`.

```python title="bytes_views.py" file

print(chunk)

print(bytearray(5), bytearray([5]))
print(b"A"[0], b"A"[0:1])

try:
    b"a" + "b"
except TypeError as error:
```

## Step 12: Wrap a bytearray in a class
Now combine both halves of the lesson. A small `Buffer` class stores a `bytearray` and teaches Python `repr()`, `len()`, indexing, slicing, and item assignment. `__getitem__` returns an `int` for an index and a new `Buffer` for a slice, and invalid values raise the same `ValueError` as a plain `bytearray`.

```python title="buffer_basics.py" file
class Buffer:
    def __init__(self, data=b""):
        self._data = bytearray(data)

    def __repr__(self):
        return f"Buffer({self._data.hex(' ')})"

    def __len__(self):
        return len(self._data)

    def __getitem__(self, i):
        part = self._data[i]
        return part if isinstance(i, int) else Buffer(part)

    def __setitem__(self, i, value):
        self._data[i] = value


buf = Buffer(b"Hi!")
print(buf)
print(len(buf))
print(buf[0], buf[0:2])
buf[0] = 104
print(buf)

try:
    buf[0] = 300
except ValueError as error:
    print("ValueError:", error)
```

## How it works
Python turns an operator into a method call on the left operand: `a + b` becomes `type(a).__add__(a, b)`. If the method is missing or returns `NotImplemented`, Python tries the reflected method on the right operand, such as `__radd__`. In-place forms such as `__iadd__` are tried first for `+=` and fall back to the plain operator. Python looks these methods up on the class, not on the instance.

| You write | Python calls |
| --- | --- |
| `+ - * / // % ** @` | `__add__ __sub__ __mul__ __truediv__ __floordiv__ __mod__ __pow__ __matmul__` |
| `& \| ^ << >>` | `__and__ __or__ __xor__ __lshift__ __rshift__` |
| Reflected and in-place forms | `__radd__`, `__iadd__`, and the same `r` and `i` prefix for every operator above |
| `-x +x ~x abs(x)` | `__neg__ __pos__ __invert__ __abs__` |
| `== != < <= > >=` | `__eq__ __ne__ __lt__ __le__ __gt__ __ge__` |
| `len(x)`, `v in x`, `for v in x` | `__len__`, `__contains__`, `__iter__` and `__next__` |
| `x[i]`, `x[i] = v`, `del x[i]` | `__getitem__`, `__setitem__`, `__delitem__` |
| `str(x)`, `repr(x)`, `hash(x)` | `__str__`, `__repr__`, `__hash__` |
| `bool(x)`, `x(...)`, `with x:` | `__bool__` (else `__len__`), `__call__`, `__enter__` and `__exit__` |

Follow a few rules of thumb. Binary operators return a new object; only in-place methods change `self`, and they return `self`. Return `NotImplemented` for an unsupported operand instead of raising. Always define `__repr__`. Define `__eq__` and `__hash__` together, or leave a mutable class unhashable. You cannot overload `and`, `or`, `not`, `is`, assignment `=`, or attribute access `.`, and you cannot invent new operators, so keep each operator's meaning natural.

Binary data follows the same idea of mutability. `bytes` is an immutable sequence of integers from 0 to 255, so it is hashable and suits constants, keys, and data you only read. `bytearray` is the mutable twin for buffers you build, edit, or fill in place. A `memoryview` and `readinto()` let you work on a buffer without copying it.

## Common errors
### `TypeError: unsupported operand type(s) for +: 'Vector' and 'int'`
Your `__add__` returned `NotImplemented` and the other side had no reflected method. Either convert the operand first (`v + Vector(5, 5)`) or add support for the extra type in `__add__` and `__radd__`.

### `TypeError: unhashable type: 'Equal'`
Defining `__eq__` without `__hash__` removes the default hash. Add `__hash__` that uses the same fields as `__eq__`, or accept that the class cannot be a dictionary key or set member.

### `TypeError: unsupported operand type(s) for +: 'int' and 'Total'` inside `sum()`
`sum()` starts from `0`, so it computes `0 + first`. Add `__radd__` that returns `self` when the other operand is `0`, or call `sum(items, Total(0))`.

### `ValueError: byte must be in range(0, 256)`
A `bytearray` item must be an integer from 0 to 255. Reduce the value with `% 256` or use `& 0xFF` before assigning it.

### `TypeError: can't concat str to bytes`
`bytes` and `str` never mix. Use `text.encode("utf-8")` to get bytes, or `data.decode("utf-8")` to get text.

### `bytearray(5)` is not `bytearray([5])`
A single integer argument is a length, so `bytearray(5)` is five zero bytes. A list is a sequence of values, so `bytearray([5])` is one byte holding 5.

## Recap
- Operators call special methods such as `__add__`, `__eq__`, and `__getitem__`; return `NotImplemented` for unsupported operands, keep `__eq__` and `__hash__` consistent, and always define `__repr__`.
- `@total_ordering`, `__radd__`, and in-place methods that return `self` round out a class that works with `sorted()`, `sum()`, and `+=`.
- `bytes` is immutable and hashable, `bytearray` is mutable, items are integers from 0 to 255, and text needs `encode()` and `decode()` to cross over.

## Final practice: ByteBuffer
The cheat sheet ends with one program that wraps a `bytearray` in a class and teaches it `+`, `+=`, `^`, `==`, `len()`, indexing, slicing, and `bytes()`. Create `byte_buffer.py` and run it.

```python title="byte_buffer.py" file
class ByteBuffer:
    """A tiny mutable buffer built on bytearray."""

    def __init__(self, data=b""):
        self._data = bytearray(data)

    def __repr__(self):  # ByteBuffer(02 05 ...)
        return f"ByteBuffer({self._data.hex(' ')})"

    def __len__(self):  # len(buf)
        return len(self._data)

    def __getitem__(self, i):  # buf[0] or buf[2:7]
        part = self._data[i]
        return part if isinstance(i, int) else ByteBuffer(part)

    def __setitem__(self, i, value):  # buf[-1] = 0x74
        self._data[i] = value

    def __add__(self, other):  # buf + buf -> new buffer
        if not isinstance(other, ByteBuffer):
            return NotImplemented
        return ByteBuffer(self._data + other._data)

    def __iadd__(self, other):  # buf += b"..." -> in place
        self._data.extend(other._data if isinstance(other, ByteBuffer) else other)
        return self

    def __xor__(self, key):  # buf ^ 0x5A -> XOR every byte
        return ByteBuffer(b ^ key for b in self._data)

    def __eq__(self, other):  # buf == buf
        return isinstance(other, ByteBuffer) and self._data == other._data

    __hash__ = None  # mutable, so deliberately unhashable

    def __bytes__(self):  # bytes(buf)
        return bytes(self._data)


packet = ByteBuffer(b"\x02\x05") + ByteBuffer(b"HELLO")  # header + payload
print("packet     :", packet)
print("length     :", len(packet))
print("first byte :", packet[0])
print("payload    :", bytes(packet[2:7]))
packet += b"\x00"  # reserve a checksum byte
packet[-1] = sum(bytes(packet[2:7])) % 256  # fill it in
print("with csum  :", packet)
scrambled = packet ^ 0x5A  # XOR "encrypt"
print("scrambled  :", scrambled)
print("round trip :", (scrambled ^ 0x5A) == packet)
```

```bash title="Terminal" verify="run"
python3 byte_buffer.py
```

```text title="Expected output"
length     : 7
first byte : 2
payload    : b'HELLO'
with csum  : ByteBuffer(02 05 48 45 4c 4c 4f 74)
scrambled  : ByteBuffer(58 5f 12 1f 16 16 15 2e)
round trip : True
```

- `ByteBuffer + ByteBuffer` returns a new buffer, while `packet += b"\x00"` extends the same buffer in place and returns `self`.
- `__getitem__` returns an `int` for an index and a new `ByteBuffer` for a slice, which is why `bytes(packet[2:7])` prints `b'HELLO'`.
- The checksum `0x74` is the sum of the payload bytes modulo 256: `72 + 69 + 76 + 76 + 79 = 372`, and `372 % 256 = 116`, which is `0x74`.
- XOR with the same key twice restores the original, so `(scrambled ^ 0x5A) == packet` is `True`. This is a teaching example, not real encryption.
- `__hash__ = None` makes the mutable buffer deliberately unhashable, which is the safe choice for an object whose contents can change.
