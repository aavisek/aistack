## Why this matters
Dictionaries store data by name instead of by position: a customer's name and city, a word count, a settings file, or a JSON response from a web service. Looking up a value by key is fast, and the code reads like the data it describes. A few rules about keys, missing values, and copies prevent the most common dictionary bugs.

## What you will build
Small, standalone Python scripts that create dictionaries, read and change them, merge and loop over them, apply counting and grouping patterns, copy them safely, and convert them to JSON. You finish with a customer profile program that prints its dictionary after nine tasks.

## Before you start
Use Python 3.10 or newer and create each named file in a practice folder. Every example is independent. Run each file with `python3 filename.py` on macOS/Linux or `py -3 filename.py` in Windows PowerShell.

A dictionary (`dict`) maps unique, hashable keys to values of any type, and it remembers the order in which keys were inserted. Like lists from PY-04, dictionaries are mutable, so the aliasing and in-place changes from PY-01 apply to them as well. Keys are looked up directly, so lookup stays fast even for large dictionaries.

## Step 1: Create dictionaries
A dictionary can be written as a literal, built with `dict()` from keyword arguments, pairs, or two parallel sequences, filled with one starting value by `dict.fromkeys()`, or produced by a dict comprehension. Empty braces `{}` make an empty dictionary, not an empty set.

```python title="dict_create.py" file
person = {"name": "Asha", "age": 28}
print(person)
print(dict(name="Asha", age=28))
print(dict([("a", 1), ("b", 2)]))
print(dict(zip(["x", "y"], [10, 20])))
print(dict.fromkeys(["a", "b", "c"], 0))
print({n: n ** 2 for n in range(1, 5)})

empty = {}
print(empty, type(empty).__name__, len(empty))
print(person == dict(name="Asha", age=28))
```

```bash title="Terminal" verify="run"
python3 dict_create.py
```

```text title="Expected output"
{'name': 'Asha', 'age': 28}
{'name': 'Asha', 'age': 28}
{'a': 1, 'b': 2}
{'x': 10, 'y': 20}
{'a': 0, 'b': 0, 'c': 0}
{1: 1, 2: 4, 3: 9, 4: 16}
{} dict 0
True
```

The keyword form `dict(name="Asha")` only works for string keys that are valid names. Since Python 3.7 a dictionary keeps insertion order, so the pairs print in the order they were added.

## Step 2: Choose valid keys
Keys must be unique and hashable. Strings, numbers, booleans, tuples of hashable items, and frozensets work. Lists, dictionaries, and sets do not, and using one raises `TypeError`. Values can be any object, and they may repeat.

```python title="dict_keys_rules.py" file
print({("lat", "lon"): "pair", frozenset({1}): "frozen"})

try:
    {[1, 2]: "x"}
except TypeError as error:
    print("TypeError:", error)

try:
    {(1, [2]): "x"}
except TypeError as error:
    print("TypeError:", error)

mixed = {1: "int", 1.0: "float", True: "bool"}
print(mixed, len(mixed))

print({"a": 1, "a": 2})
print({"x": [1, 2], "y": [1, 2], "z": {"inner": 1}})
```

```bash title="Terminal" verify="run"
python3 dict_keys_rules.py
```

```text title="Expected output"
{('lat', 'lon'): 'pair', frozenset({1}): 'frozen'}
TypeError: unhashable type: 'list'
TypeError: unhashable type: 'list'
{1: 'bool'} 1
{'a': 2}
{'x': [1, 2], 'y': [1, 2], 'z': {'inner': 1}}
```

`1`, `1.0`, and `True` are equal and hash alike, so they count as one key: the first key object stays and the last value wins. A repeated key in a literal also keeps only the last value.

## Step 3: Read values
`d[k]` returns the value but raises `KeyError` when the key is missing. `d.get(k)` returns `None` instead, and `d.get(k, default)` returns your fallback. `in` tests keys only, never values, and `setdefault()` reads a key or inserts it when it is missing.

```python title="dict_read.py" file
d = {"a": 1, "b": 2, "c": 3}

print(d["a"])
try:
    d["z"]
except KeyError as error:
    print("KeyError:", error)

print(d.get("z"))
print(d.get("z", 0))
print("b" in d, "z" not in d)
print(2 in d, 2 in d.values())
print(len(d))

print(d.setdefault("z", 26))
print(d.setdefault("a", 99))
print(d)
```

```bash title="Terminal" verify="run"
python3 dict_read.py
```

```text title="Expected output"
1
KeyError: 'z'
None
0
True True
False True
3
26
1
{'a': 1, 'b': 2, 'c': 3, 'z': 26}
```

`setdefault("a", 99)` leaves the existing value alone and returns it. Use `get()` when a missing key is normal, and `d[k]` when a missing key is a real error you want to see.

## Step 4: Add, update, and remove pairs
Assigning to `d[k]` adds a new key or overwrites an existing one. `del d[k]` removes a key and raises `KeyError` if it is absent. `pop(k)` removes a key and returns its value, and `pop(k, default)` avoids the error. `popitem()` removes and returns the last inserted pair, and `clear()` empties the dictionary.

```python title="dict_change.py" file
stock = {"apple": 5, "pear": 2}
stock["kiwi"] = 7
stock["apple"] += 1
stock["fig"] = 1
print(stock)

del stock["fig"]
print(stock.pop("kiwi"))
print(stock.pop("nope", None))
print(stock.popitem())
print(stock)

try:
    del stock["nope"]
except KeyError as error:
    print("KeyError:", error)

stock.clear()
print(stock, len(stock))
```

```bash title="Terminal" verify="run"
python3 dict_change.py
```

```text title="Expected output"
{'apple': 6, 'pear': 2, 'kiwi': 7, 'fig': 1}
7
None
('pear', 2)
{'apple': 6}
KeyError: 'nope'
{} 0
```

`popitem()` is last-in, first-out since Python 3.7, and it raises `KeyError` on an empty dictionary. Unlike `get()`, deleting a missing key is an error unless you use `pop(k, default)`.

## Step 5: Merge dictionaries
`d.update(other)` merges in place, and `d.update(k=v)` accepts keyword arguments. On a clash the value from `other` wins. Python 3.9 added `d | other`, which builds a new dictionary and leaves both inputs untouched, and `d |= other`, which works like `update()`.

```python title="dict_merge.py" file
base = {"apple": 6, "pear": 2}
extra = {"pear": 10, "fig": 1}

merged = base | extra
print(merged)
print(base, extra)

base.update(extra)
print(base)

base.update(plum=3)
print(base)

settings = {"theme": "light", "size": 12}
settings |= {"theme": "dark"}
print(settings)
```

```bash title="Terminal" verify="run"
python3 dict_merge.py
```

```text title="Expected output"
{'apple': 6, 'pear': 10, 'fig': 1}
{'apple': 6, 'pear': 2} {'pear': 10, 'fig': 1}
{'apple': 6, 'pear': 10, 'fig': 1}
{'apple': 6, 'pear': 10, 'fig': 1, 'plum': 3}
{'theme': 'dark', 'size': 12}
```

The `|` operator needs Python 3.9 or newer; with older versions use `{**a, **b}` or `update()`. Existing keys keep their original position, so `pear` stays in the second slot after it is overwritten.

## Step 6: Loop and use views
`d.keys()`, `d.values()`, and `d.items()` return live view objects: they always reflect the current contents. Looping over a dictionary directly gives its keys, and `items()` gives `(key, value)` pairs you can unpack in a `for` loop.

```python title="dict_loops.py" file
d = {"a": 1, "b": 2, "c": 3}

print(d.keys())
print(d.values())
print(d.items())

for key, value in d.items():
    print(key, "->", value)

print(list(d))
print(sum(d.values()))

view = d.keys()
d["d"] = 4
print(view)
print(list(d.items())[0])
```

```bash title="Terminal" verify="run"
python3 dict_loops.py
```

```text title="Expected output"

dict_values([1, 2, 3])
dict_items([('a', 1), ('b', 2), ('c', 3)])
a -> 1
b -> 2
c -> 3
['a', 'b', 'c']
6
dict_keys(['a', 'b', 'c', 'd'])
('a', 1)
```

The `view` variable showed the new key `d` without being recreated, which is what live means. Wrap a view in `list()` when you need a fixed snapshot or an indexable sequence.

## Step 7: Sort, search, invert, and filter
Because `items()` yields pairs, you can sort a dictionary by value, find the key with the largest value, swap keys and values, or keep only some pairs. Each of these builds a new object; the original dictionary is unchanged.

```python title="dict_recipes.py" file
d = {"a": 1, "b": 2, "c": 3}

print(sorted(d.items(), key=lambda kv: kv[1], reverse=True))
print(max(d, key=d.get))
print({v: k for k, v in d.items()})
print({k: v for k, v in d.items() if v > 1})
print(d)

print({v: k for k, v in {"x": 1, "y": 1}.items()})
```

```bash title="Terminal" verify="run"
python3 dict_recipes.py
```

```text title="Expected output"
[('c', 3), ('b', 2), ('a', 1)]
c
{1: 'a', 2: 'b', 3: 'c'}
{'b': 2, 'c': 3}
{'a': 1, 'b': 2, 'c': 3}
{1: 'y'}
```

Inverting needs unique, hashable values. In the last line both keys had the value `1`, so one pair was lost. `sorted()` returns a list of pairs, not a dictionary; wrap it in `dict()` if you need a dictionary back.

## Step 8: Count, group, and nest
Counting and grouping are the two most common dictionary jobs. `freq.get(w, 0) + 1` counts without a `KeyError`, and `groups.setdefault(key, []).append(item)` creates each list on first use. Values can themselves be dictionaries, and chained `get()` calls read them safely.

```python title="dict_patterns.py" file
words = ["to", "be", "or", "not", "to", "be"]
freq = {}
for w in words:
    freq[w] = freq.get(w, 0) + 1
print(freq)

groups = {}
for w in ["apple", "avocado", "banana", "blueberry", "cherry"]:
    groups.setdefault(w[0], []).append(w)
print(groups)

user = {"id": 7, "address": {"city": "Pune", "geo": {"lat": 18.5}}}
print(user["address"]["geo"]["lat"])
print(user.get("profile", {}).get("bio", "n/a"))
```

```bash title="Terminal" verify="run"
python3 dict_patterns.py
```

```text title="Expected output"
{'to': 2, 'be': 2, 'or': 1, 'not': 1}
{'a': ['apple', 'avocado'], 'b': ['banana', 'blueberry'], 'c': ['cherry']}
18.5
n/a
```

`user["profile"]["bio"]` would raise `KeyError`, so `user.get("profile", {})` supplies an empty dictionary to read from. The standard library's `collections.Counter` and `defaultdict` do counting and grouping more cleanly, and the next cheat sheet covers them.

## Step 9: Copy dictionaries and convert to JSON
`b = a` is an alias, as it was for lists. `d.copy()` and `dict(d)` make a shallow copy, so nested objects are still shared, and `copy.deepcopy()` makes a fully independent one. `json.dumps()` turns a dictionary into a JSON string, and `json.loads()` reads it back.

```python title="dict_copy_json.py" file
import copy
import json

orig = {"tags": ["a"], "n": 1}
alias = orig
shallow = orig.copy()
deep = copy.deepcopy(orig)

orig["tags"].append("b")
orig["n"] = 2
print(alias is orig, shallow is orig)
print(shallow["tags"], shallow["n"])
print(deep["tags"], deep["n"])

payload = json.dumps({"name": "John", "vip": True, "score": None})
print(payload)
print(json.loads(payload)["vip"])
```

```bash title="Terminal" verify="run"
python3 dict_copy_json.py
```

```text title="Expected output"
True False
['a', 'b'] 1
['a'] 1
{"name": "John", "vip": true, "score": null}
True
```

The shallow copy got its own top level, so `n` did not change, but it shares the inner list. JSON writes `True` as `true` and `None` as `null`, and `json.loads()` converts them back to Python values.

## Step 10: Avoid the common dictionary gotchas
Never add or delete keys while looping over the same dictionary: loop over `list(d)` instead. `dict.fromkeys(keys, [])` shares one list between all keys, so build one list per key with a comprehension. Finally, `==` ignores key order.

```python title="dict_gotchas.py" file
tmp = {"a": 1, "b": 2}
try:
    for k in tmp:
        del tmp[k]
except RuntimeError as error:
    print("RuntimeError:", error)

tmp = {"a": 1, "b": 2}
for k in list(tmp):
    del tmp[k]
print(tmp)

shared = dict.fromkeys(["a", "b"], [])
shared["a"].append(1)
print(shared)

safe = {k: [] for k in ["a", "b"]}
safe["a"].append(1)
print(safe)

print({"a": 1, "b": 2} == {"b": 2, "a": 1})
```

```bash title="Terminal" verify="run"
python3 dict_gotchas.py
```

```text title="Expected output"
RuntimeError: dictionary changed size during iteration
{}
{'a': [1], 'b': [1]}
{'a': [1], 'b': []}
True
```

The loop over `list(tmp)` works because the list is a separate snapshot of the keys. Changing a value for an existing key during a loop is fine; adding or removing a key is not.

## How it works
A dictionary stores each key's hash so it can jump straight to the matching pair, which makes lookup fast on average. That is why keys must be hashable and unique, and why `1`, `1.0`, and `True` collapse into one key. Insertion order is kept, so loops, views, and `popitem()` follow the order the keys were added.

Reading with `d[k]` fails loudly with `KeyError`, while `get()` and `setdefault()` handle missing keys. `update()`, `|=`, `pop()`, `popitem()`, `del`, and `clear()` change the dictionary in place. `|`, `copy()`, comprehensions, and `sorted()` create new objects. The views `keys()`, `values()`, and `items()` stay linked to the dictionary, and a dictionary is mutable, so `b = a` is an alias and `copy()` is only shallow.

## Common errors
### `KeyError: 'z'`
`d["z"]` raises this error when the key is missing. Use `d.get("z")` or `d.get("z", default)`, or test with `if "z" in d:` first.

### `TypeError: unhashable type: 'list'`
Lists, dictionaries, and sets cannot be keys. Use a tuple instead of a list, or a `frozenset` instead of a set.

### `RuntimeError: dictionary changed size during iteration`
You added or deleted a key inside a loop over the same dictionary. Loop over `list(d)` or `list(d.items())` so the loop reads a snapshot while you change the dictionary.

### `2 in d` is `False` even though 2 is a value
`in` tests keys only. Use `2 in d.values()` to search the values.

### Every key shares the same list
`dict.fromkeys(keys, [])` stores one list under all the keys. Use `{k: [] for k in keys}` to give each key its own list.

### Changing a copy also changes the original
`d.copy()` and `dict(d)` are shallow, so nested lists and dictionaries are shared. Use `copy.deepcopy(d)` when the copy must be fully independent.

## Recap
- A dictionary maps unique, hashable keys to any values in insertion order; `d[k]` raises `KeyError`, while `get()` and `setdefault()` handle missing keys, and `in` tests keys only.
- Change a dictionary with assignment, `update()`, `|=`, `del`, `pop()`, `popitem()`, and `clear()`; `|`, `copy()`, comprehensions, and `sorted()` build new objects, and `keys()`, `values()`, and `items()` are live views.
- Never change the key set while looping over it, build one value per key instead of sharing one with `fromkeys()`, and use `deepcopy()` when nested values must be independent.

## Final practice: Customer Profile Management
The cheat sheet ends with one CRM program that covers nine dictionary tasks, followed by a bonus with friendlier output. Create `customer_profile.py`; it prints the dictionary after each operation so you can watch it change. Step 7 removes `phone`, because it was the last pair inserted before the final update.

```python title="customer_profile.py" file
# Customer profile management (CRM)
# 1. Create the dictionary and print it
customer = {"name": "John Doe", "age": 32, "city": "New York"}
print("1.", customer)

# 2. Add email and phone, then print
customer["email"] = "john.doe@example.com"
customer["phone"] = "+1-555-0100"
print("2.", customer)

# 3. Print the name and city values
print("3. Name:", customer["name"], "| City:", customer["city"])

# 4. Does the key "email" exist?
print("4. 'email' exists:", "email" in customer)

# 5. Delete the age field and print
del customer["age"]
print("5.", customer)

# 6. Keys, values and items
print("6. Keys: ", customer.keys())
print("   Values:", customer.values())
print("   Items: ", customer.items())

# 7. Remove and print the last inserted key-value pair
last_pair = customer.popitem()
print("7. Removed:", last_pair)

# 8. .get() on a key that does not exist returns None instead of an error
print("8. Membership:", customer.get("membership"))

# 9. Update with a new field and print the final dictionary
customer.update({"address": "221B Baker Street"})
print("9. Final:", customer)

# Bonus: friendlier output
print("Membership:", customer.get("membership", "Not a member"))
for field, value in customer.items():
    print(f"{field:>8}: {value}")
print("Fields stored:", len(customer))
```
