## Why this matters
Lists, tuples, and dicts handle most jobs, but some patterns keep coming back: records with named fields, queues, frequency tables, grouping, caches, and layered settings. The `collections` module in the standard library ships a ready-made container for each one, so you write less code and avoid slow or error-prone workarounds.

## What you will build
Small, standalone Python scripts that use `namedtuple`, `deque`, `Counter`, `defaultdict`, `OrderedDict`, `ChainMap`, and the `User*` wrappers, plus a tiny LRU cache. You finish with one program that counts words, groups them by length, ranks them, and keeps a sliding window.

## Before you start
Use Python 3.10 or newer and create each named file in a practice folder. Every example is independent, and nothing needs installing because `collections` is part of the standard library. Run each file with `python3 filename.py` on macOS/Linux or `py -3 filename.py` in Windows PowerShell.

These types build on the tuples, lists, sets, and dicts from earlier lessons (PY-04 to PY-06). Import only what you need with `from collections import ...`. The cheat sheet shows interactive `>>>` sessions; the scripts here use `print()` so the output is the same on every run. Printed forms of `OrderedDict` and `defaultdict` changed between Python versions, so the scripts print plain lists and dicts instead.

## Step 1: Meet the collections family
Each type solves one problem. `namedtuple` makes light records, `deque` is a fast two-ended queue, `Counter` counts, `defaultdict` creates missing values, `OrderedDict` has order-aware methods, `ChainMap` layers dicts, and `UserDict`, `UserList`, and `UserString` are safe base classes for customising `dict`, `list`, and `str`.

```python title="family.py" file
from collections import (ChainMap, Counter, OrderedDict, UserDict, UserList,
                         UserString, defaultdict, deque, namedtuple)

Point = namedtuple("Point", "x y")
print("Point is a tuple:", issubclass(Point, tuple))

for cls in (deque, Counter, defaultdict, OrderedDict, ChainMap, UserDict, UserList, UserString):
    print(f"{cls.__name__:<12} dict subclass: {issubclass(cls, dict)}")

print("deque is a list:", issubclass(deque, list))
```


`Counter`, `defaultdict`, and `OrderedDict` are real `dict` subclasses, so every dict method still works. `deque` is not a list, which is why its operations differ. `ChainMap` and the `User*` classes wrap another object rather than inheriting from it.

## Step 2: namedtuple, a tuple with names
`namedtuple(name, fields)` builds a new tuple class. The fields can be a list or one space-separated string. You read a field by name or by position and still unpack it like a tuple. `_asdict()` converts to a dict, `_replace()` returns a changed copy, `_fields` lists the names, and `defaults=` fills the rightmost fields. Assigning to a field raises `AttributeError` because tuples are immutable.

```python title="named_tuple.py" file
from collections import namedtuple

Point = namedtuple("Point", ["x", "y"])
p = Point(3, 4)
print(p)
print(p.x, p[1])
x, y = p
print(x, y)
print(Point(y=1, x=2))
print(p == (3, 4), isinstance(p, tuple))

print(p._asdict())
moved = p._replace(x=10)
print(moved, p)
print(Point._fields)

Employee = namedtuple("Employee", "name role", defaults=["Engineer"])
print(Employee("Ravi"))
print(Employee("Mia", "Manager"))

try:
    p.x = 99
except AttributeError:
    print("AttributeError: fields are read-only")
```

```bash title="Terminal" verify="run"
python3 named_tuple.py
```

## Step 3: deque, a two-ended queue
A `deque` adds and removes at both ends in constant time. `append()` and `pop()` work on the right, `appendleft()` and `popleft()` on the left, and `rotate(n)` turns the items right by `n` steps (a negative number turns left). A list pays a cost proportional to its length for `pop(0)` and `insert(0, x)` because every item shifts. Indexing into the middle of a deque is also proportional to its length, so use a list for random access.

```python title="deque_basics.py" file
from collections import deque

q = deque([1, 2, 3])
q.append(4)
q.appendleft(0)
print(q)

print(q.pop(), q.popleft())
print(q)

q.rotate(1)
print(q)
q.rotate(-1)
print(q)

queue = deque()
queue.append("job1")
queue.append("job2")
print(queue.popleft(), len(queue))

try:
    deque().pop()
except IndexError as error:
    print("IndexError:", error)
```

```bash title="Terminal" verify="run"
python3 deque_basics.py
```

```text title="Expected output"
deque([0, 1, 2, 3, 4])
4 0
deque([1, 2, 3])
deque([3, 1, 2])
deque([1, 2, 3])
job1 1
IndexError: pop from an empty deque
```

Adding with `append()` and removing with `popleft()` gives a first-in, first-out queue. Adding and removing at the same end gives a stack. Popping from an empty deque raises `IndexError`.

## Step 4: Bound a deque with maxlen
`deque(maxlen=n)` keeps at most `n` items. Once it is full, adding to one end silently drops an item from the other end. That is ideal for "the last N values", such as a sliding window over readings.

```python title="deque_window.py" file
from collections import deque

last3 = deque(maxlen=3)
for n in range(6):
    last3.append(n)
print(last3)
print(last3.maxlen, len(last3))

window = deque(maxlen=3)
for reading in [10, 20, 30, 40, 50]:
    window.append(reading)
    print(reading, list(window), sum(window) / len(window))

print(deque(range(5), maxlen=2))
```

```bash title="Terminal" verify="run"
python3 deque_window.py
```

```text title="Expected output"

3 3
10 [10] 10.0
20 [10, 20] 15.0
30 [10, 20, 30] 20.0
40 [20, 30, 40] 30.0
50 [30, 40, 50] 40.0
deque([3, 4], maxlen=2)
```

Items that fall off are discarded without an error. The window average only uses the items still inside it, so the first two averages cover fewer than three readings. The same trimming happens when you build a bounded deque from an iterable.

## Step 5: Counter, count anything hashable
`Counter` is a dict subclass that maps each item to how many times it appeared. `most_common(n)` returns the top `n` as `(item, count)` pairs, and equal counts keep first-seen order. A missing item counts as `0` without raising `KeyError`. `update()` adds to the counts instead of replacing them, and `sum(c.values())` gives the total.

```python title="counter_basics.py" file
from collections import Counter

c = Counter("mississippi")
print(c)
print(c.most_common(2))
print(c["s"], c["z"])
print("z" in c)

c.update("ssss")
print(c["s"])
print(c.most_common(1))
print(sum(c.values()), c.total())

print(Counter(["red", "blue", "red"]))
```

```bash title="Terminal" verify="run"
python3 counter_basics.py
```

```text title="Expected output"

False
8
[('s', 8)]
15
Counter({'red': 2, 'blue': 1})
```

Looking up `c["z"]` returns `0` but does not add the key. `Counter.total()` needs Python 3.10 or newer; `sum(c.values())` works in every version. You can build a `Counter` from any iterable of hashable items, such as a string or a list of words.

## Step 6: Counter arithmetic
Counters behave like multisets. `+` adds counts, and `-` subtracts them but keeps only positive results, so zero and negative counts disappear. `&` keeps the smaller count and `|` the larger. `elements()` expands a counter back into repeated items. The `subtract()` method is different from `-`: it changes the counter in place and keeps negative counts.

```python title="counter_math.py" file
from collections import Counter

a = Counter(a=3, b=1)
b = Counter(a=1, b=5)

print(a + b)
print(a - b)
print(a & b)
print(a | b)
print(list(Counter(a=2, b=1).elements()))

d = Counter(a=3, b=1)
d.subtract(b)
print(d)
```

```bash title="Terminal" verify="run"
python3 counter_math.py
```

```text title="Expected output"

Counter({'a': 1, 'b': 1})
Counter({'b': 5, 'a': 3})
['a', 'a', 'b']
Counter({'a': 2, 'b': -4})
```

In `a - b`, the key `b` would be `1 - 5 = -4`, so it is dropped. Use `subtract()` when you need to see the negative counts.

## Step 7: defaultdict, no more KeyError
`defaultdict(factory)` calls a zero-argument factory such as `list`, `int`, `set`, or `lambda: "N/A"` when you read a missing key, then stores and returns the result. That makes grouping with `list` and counting with `int` one-liners. Reading a missing key creates it, so use `.get()` or `in` when you only want to look.

```python title="default_dict.py" file
from collections import defaultdict

by_len = defaultdict(list)
for w in ["tea", "cup", "water", "pot", "plate"]:
    by_len[len(w)].append(w)
print(dict(by_len))

hits = defaultdict(int)
for ch in "banana":
    hits[ch] += 1
print(dict(hits))

print(hits["zzz"])
print("zzz" in hits)
print(hits.get("qqq"))
print("qqq" in hits)

info = defaultdict(lambda: "N/A")
print(info["city"])

nested = defaultdict(lambda: defaultdict(int))
nested["2026"]["Nov"] += 5
print(dict(nested["2026"]))

try:
    {}["missing"]
except KeyError as error:
    print("plain dict KeyError:", error)
```

The lookup `hits["zzz"]` silently added the key `"zzz"`, which can hide typos. `.get("qqq")` returned `None` and left the dict unchanged. A nested `defaultdict` creates both levels on first use.

## Step 8: OrderedDict, an order-aware dict
Plain dicts remember insertion order since Python 3.7. `OrderedDict` still adds `move_to_end(key)`, `popitem(last=False)` to pop from the front (first in, first out), and an `==` that cares about order. Comparing two `OrderedDict` objects is order-sensitive, while comparing plain dicts, or an `OrderedDict` with a plain dict, is not.

```python title="ordered_dict.py" file
from collections import OrderedDict

od = OrderedDict(a=1, b=2, c=3)
od.move_to_end("a")
print(list(od.items()))

od.move_to_end("c", last=False)
print(list(od))

print(od.popitem(last=False))
print(list(od))

print(OrderedDict(a=1, b=2) == OrderedDict(b=2, a=1))
print({"a": 1, "b": 2} == {"b": 2, "a": 1})
print(OrderedDict(a=1, b=2) == {"b": 2, "a": 1})
```

```bash title="Terminal" verify="run"
python3 ordered_dict.py
```

```text title="Expected output"

['c', 'b', 'a']
('c', 3)
['b', 'a']
False
True
True
```

`move_to_end("a")` sends a key to the back, and `last=False` sends it to the front. `popitem()` with no argument removes the last item instead. These moves are what make an `OrderedDict` a good base for an LRU cache.

## Step 9: Build an LRU cache
An LRU (least recently used) cache holds a fixed number of entries and evicts the one that has gone unused the longest. Keep the most recently used key at the end of an `OrderedDict`: every `get` or `put` calls `move_to_end()`, and going over capacity calls `popitem(last=False)` to drop the front.

```python title="lru_cache.py" file
from collections import OrderedDict


class LRUCache:
    def __init__(self, capacity):
        self.capacity = capacity
        self.data = OrderedDict()

    def get(self, key):
        if key not in self.data:
            return None
        self.data.move_to_end(key)  # mark as most recently used
        return self.data[key]

    def put(self, key, value):
        self.data[key] = value
        self.data.move_to_end(key)
        if len(self.data) > self.capacity:
            self.data.popitem(last=False)  # evict the least recently used


cache = LRUCache(2)
cache.put("a", 1)
cache.put("b", 2)
cache.get("a")  # touch "a": "b" is now the oldest
cache.put("c", 3)  # over capacity: "b" is evicted
print("Cache keys:", list(cache.data))
print("b is cached?", cache.get("b") is not None)
```

```bash title="Terminal" verify="run"
python3 lru_cache.py
```

```text title="Expected output"

b is cached? False
```

Reading `"a"` moved it behind `"b"`, so `"b"` was at the front when `"c"` pushed the cache over its capacity of 2. `get()` returns `None` for a missing key, so a stored value of `None` would look like a miss; the standard `functools.lru_cache` in Step 12 handles that for you.

## Step 10: ChainMap, layered lookups
`ChainMap(first, second, ...)` is one view over several dicts, and nothing is copied. A lookup searches the maps from left to right and returns the first match, which suits settings where the command line beats a config file, which beats the defaults. Writes and deletes only affect the first map. `.maps` lists the underlying dicts, and `new_child()` adds a new first layer.

```python title="chain_map.py" file
from collections import ChainMap

defaults = {"theme": "light", "lang": "en"}
user = {"theme": "dark"}
cfg = ChainMap(user, defaults)

print(cfg["theme"], cfg["lang"])
cfg["font"] = 12
print(user)
print(defaults)
print(cfg.maps)
print(list(cfg), len(cfg))

override = cfg.new_child({"theme": "blue"})
print(override["theme"], cfg["theme"])

try:
    cfg["color"]
except KeyError as error:
    print("KeyError:", error)
```

```bash title="Terminal" verify="run"
python3 chain_map.py
```

```text title="Expected output"

{'theme': 'dark', 'font': 12}
{'theme': 'light', 'lang': 'en'}

['theme', 'lang', 'font'] 3
dark
blue dark
KeyError: 'color'
```

Setting `cfg["font"]` changed only `user`, and `defaults` stayed untouched. Because the maps are shared rather than copied, later changes to `user` or `defaults` show up through `cfg` immediately.

## Step 11: UserDict, UserList, and UserString
Subclassing the built-in `dict` or `list` can silently bypass your overrides. For example, `dict.update()` is implemented in C and does not call your `__setitem__`. The `User*` wrappers are written in Python and keep their data in a `.data` attribute, so every operation goes through your code. Use them when you customise `dict`, `list`, or `str` behaviour.

```python title="user_dict.py" file
from collections import UserDict


class LoudDict(dict):
    def __setitem__(self, k, v):
        super().__setitem__(k, v.upper())


class LoudUserDict(UserDict):
    def __setitem__(self, k, v):
        super().__setitem__(k, v.upper())


a = LoudDict()
a["x"] = "hi"
a.update(y="yo")  # bypasses __setitem__
print(a)

b = LoudUserDict()
b["x"] = "hi"
b.update(y="yo")  # goes through __setitem__
print(b)
print(type(b.data).__name__)
```

```bash title="Terminal" verify="run"
python3 user_dict.py
```

```text title="Expected output"
{'x': 'HI', 'y': 'yo'}
{'x': 'HI', 'y': 'YO'}
dict
```

The plain `dict` subclass uppercased `"hi"` but not `"yo"`, because `update()` skipped the override. `LoudUserDict` uppercased both. `UserList` and `UserString` follow the same idea for lists and strings.

## Step 12: Also worth knowing
Several other standard-library tools overlap with `collections`. `heapq` turns a list into a min-heap priority queue. `dataclasses.dataclass` builds mutable record classes with type hints, and `typing.NamedTuple` is `namedtuple` written as a class. `functools.lru_cache` memoises a pure function in one line. `enum.Enum` and `itertools` cover named constants and iterator building blocks, and `collections.abc` holds abstract base classes such as `Mapping` and `Sequence`.

```python title="also_worth_knowing.py" file
import heapq
from dataclasses import dataclass
from functools import lru_cache
from typing import NamedTuple

h = [5, 1, 4]
heapq.heapify(h)
heapq.heappush(h, 0)
print(heapq.heappop(h))
print(h[0])


@dataclass
class Item:
    name: str
    qty: int = 1


print(Item("pen", 3))
item = Item("cup")
item.qty = 5
print(item)


class Coord(NamedTuple):
    lat: float
    lon: float


print(Coord(1.5, 2.5))


@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)


print(fib(30), fib.cache_info().hits)
```

```bash title="Terminal" verify="run"
python3 also_worth_knowing.py
```

```text title="Expected output"
0
1
Item(name='pen', qty=3)
Item(name='cup', qty=5)
Coord(lat=1.5, lon=2.5)
832040 28
```

`heappop()` always returns the smallest item, and `h[0]` is the next smallest. Unlike a namedtuple, a dataclass instance can be changed after it is created.

## How it works
Each type adds one capability to a built-in idea. `namedtuple` creates a tuple subclass with named properties, so it stays immutable and light. `deque` is a doubly linked list of blocks, which makes both ends cheap and the middle slow. `Counter`, `defaultdict`, and `OrderedDict` are dict subclasses: they keep the hash-table lookups and add counting, a missing-key factory, and order-aware methods. `defaultdict` creates a value in its `__missing__` hook, while `Counter` returns `0` from its own `__missing__` without storing it.

`ChainMap` stores a list of dicts in `.maps` and walks them on each lookup, so it never copies data and writes go to `maps[0]`. The `User*` classes hold a regular `dict`, `list`, or `str` in `.data` and implement each operation in Python, which is why overrides always run. The three typical gotchas are: reading a `defaultdict` key creates it, `Counter` subtraction drops non-positive counts, and subclassing a built-in `dict` skips overrides in methods like `update()`.

## Common errors
### `AttributeError` when assigning to a namedtuple field
A namedtuple is a tuple, so `p.x = 99` fails. Build a changed copy with `p = p._replace(x=99)`, or use a `dataclass` when you need a mutable record.

### `Counter` subtraction loses a key
`Counter(a=3, b=1) - Counter(a=1, b=5)` keeps only `a` because `-` drops zero and negative counts. Call `subtract()` on the counter when you need to keep negative values.

### A `defaultdict` fills up with keys you only read
`hits["zzz"]` calls the factory and stores the key, so `"zzz" in hits` becomes `True`. Use `hits.get("zzz")` or test with `in` when you only want to look.

### `IndexError: pop from an empty deque`
`pop()` and `popleft()` raise `IndexError` when there is nothing to remove. Check `if q:` first, because an empty deque is falsy.

### A dict subclass ignores your `__setitem__`
`update()` and `setdefault()` on a built-in `dict` subclass do not call your override. Subclass `UserDict` instead so every operation goes through your code.

### `KeyError` from a `ChainMap` that has the key in a deeper map
Lookups search every map, but `del cfg["key"]` and `cfg.pop("key")` only touch the first map. If the key lives only in a later map, they raise `KeyError`.

## Recap
- Reach for `namedtuple` for light immutable records, `deque` for queues and sliding windows, and `Counter` for frequency tables and top-N results.
- `defaultdict` creates missing values (and creates the key on a read), `OrderedDict` adds `move_to_end()` and `popitem(last=False)` for LRU caches, and `ChainMap` layers dicts with writes going to the first map.
- Subclass `UserDict`, `UserList`, or `UserString` instead of the built-ins when overrides must run for every operation.

## Final practice: Collections demo
The cheat sheet ends with one program that combines four of these types. Create `collections_demo.py`; it counts words, groups the distinct words by length, ranks the top three as records, and keeps the last three words.

```python title="collections_demo.py" file
from collections import Counter, defaultdict, deque, namedtuple

text = "the quick brown fox jumps over the lazy dog the end"
words = text.split()

freq = Counter(words)  # how often does each word appear?
print("Top 2 words:", freq.most_common(2))

by_length = defaultdict(list)  # group the distinct words by length
for word in sorted(set(words)):
    by_length[len(word)].append(word)
print("Words by length:", dict(by_length))

Word = namedtuple("Word", "text count")  # readable records
ranked = [Word(w, n) for w, n in freq.most_common(3)]
print("Ranked:", ranked)

recent = deque(words, maxlen=3)  # keep only the last three words
print("Last three words:", list(recent))
```

```bash title="Terminal" verify="run"
python3 collections_demo.py
```

```text title="Expected output"
Top 2 words: [('the', 3), ('quick', 1)]
Words by length: {5: ['brown', 'jumps', 'quick'], 3: ['dog', 'end', 'fox', 'the'], 4: ['lazy', 'over']}
Ranked: [Word(text='the', count=3), Word(text='quick', count=1), Word(text='brown', count=1)]
Last three words: ['dog', 'the', 'end']
```

- `Counter.most_common()` lists equal counts in first-seen order, so `quick` and `brown` follow `the` in the order they appear in the text.
- Looping over `sorted(set(words))` makes the grouping deterministic, because a set has no fixed order, and the keys of `by_length` appear in the order the first word of each length is met.
- `deque(words, maxlen=3)` keeps only the last three items of the whole sentence.
