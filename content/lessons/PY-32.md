## Why this matters
Object-oriented design is more than writing classes. Encapsulation, abstraction, inheritance, and polymorphism help you control change, hide implementation details, reuse contracts, and substitute compatible objects.

## What you will build
A notification system that demonstrates all four pillars without forcing every behavior into one class.

## Before you start
Create `oop_pillars.py` and run it with Python 3.10 or newer.

## Step 1: Encapsulate state
Keep the recipient behind a property so validation is centralized.

```python title="oop_pillars.py" file
class Notification:
    def __init__(self, recipient):
        self.recipient = recipient

    @property
    def recipient(self):
        return self._recipient

    @recipient.setter
    def recipient(self, value):
        if not value:
            raise ValueError("recipient required")
        self._recipient = value
```

## Step 2: Abstract a common contract
The base class defines the operation that every notification must provide.

```python title="notification_contract.py" file
from abc import ABC, abstractmethod


class Notification(ABC):
    def __init__(self, recipient):
        self.recipient = recipient

    @abstractmethod
    def send(self, message):
        raise NotImplementedError


class EmailNotification(Notification):
    def send(self, message):
        return f"email to {self.recipient}: {message}"
```

## Step 3: Inherit and specialize
The concrete class inherits the recipient setup and supplies the missing behavior.

```python title="inheritance.py" file
from abc import ABC, abstractmethod


class Notification(ABC):
    def __init__(self, recipient):
        self.recipient = recipient

    @abstractmethod
    def send(self, message):
        raise NotImplementedError


class EmailNotification(Notification):
    def send(self, message):
        return f"email to {self.recipient}: {message}"


class SmsNotification(Notification):
    def send(self, message):
        return f"sms to {self.recipient}: {message}"


for channel in [EmailNotification("mina@example.com"), SmsNotification("+1555")]:
    print(channel.send("Ready"))
```

```bash title="Terminal" verify="run"
python3 inheritance.py
```

```text title="Expected output"

sms to +1555: Ready
```

## Step 4: Use polymorphism
The caller can use the shared `send` contract without checking concrete types.

```python title="polymorphism.py" file
class Email:
    def send(self, message):
        return "email:" + message


class Sms:
    def send(self, message):
        return "sms:" + message


def notify(channels, message):
    for channel in channels:
        print(channel.send(message))


notify([Email(), Sms()], "deployed")
```

```bash title="Terminal" verify="run"
python3 polymorphism.py
```

```text title="Expected output"
email:deployed
sms:deployed
```

## How it works
Encapsulation controls state through methods or properties. Abstraction defines what clients can rely on. Inheritance reuses or specializes an implementation. Polymorphism lets compatible objects respond to the same operation. Composition is often preferable when reuse does not represent a true subtype relationship.

## Common errors
### Calling inheritance reuse when composition fits better
A notification service that “has” a sender may be composition, not inheritance.

### Hiding everything with underscores
Encapsulation is about a stable boundary, not pretending Python has private memory.

### Checking every concrete type
Type checks defeat polymorphism; call the shared contract instead.

## Recap
- The four pillars solve different design problems.
- Interfaces matter more than concrete types at call sites.
- Prefer the simplest relationship that models the domain.
