## Why this matters
Object-oriented Python combines a small set of rules: objects hold state, methods provide behavior, and lookup follows the class hierarchy. A compact reference makes it easier to choose the right feature while designing a program.

## What you will build
A single reference script that demonstrates the most commonly used OOP syntax.

## Before you start
Create `oop_reference.py` and run it with Python 3.10 or newer.

## Step 1: Define and construct
Use `__init__` for required state and a normal method for behavior.

```python title="oop_reference.py" file
class User:
    platform = "learning"

    def __init__(self, name):
        self.name = name

    def greet(self):
        return f"Hello, {self.name}"


user = User("Mina")
print(user.greet(), user.platform)
```

```bash title="Terminal" verify="run"
python3 oop_reference.py
```

```text title="Expected output"
Hello, Mina learning
```

## Step 2: Choose the method type
Instance methods use object state, class methods receive the class, and static methods are related helpers.

```python title="method_types.py" file
class User:
    def __init__(self, name):
        self.name = name

    @classmethod
    def guest(cls):
        return cls("guest")

    @staticmethod
    def valid_name(name):
        return bool(name.strip())


print(User.guest().name)
print(User.valid_name("Mina"))
```

```bash title="Terminal" verify="run"
python3 method_types.py
```

```text title="Expected output"
guest
True
```

## Step 3: Protect values with a property
Properties keep callers on a simple attribute interface while enforcing rules.

```python title="property_reference.py" file
class Account:
    def __init__(self, balance=0):
        self.balance = balance

    @property
    def balance(self):
        return self._balance

    @balance.setter
    def balance(self, value):
        if value < 0:
            raise ValueError("negative balance")
        self._balance = value


account = Account(10)
account.balance = 20
print(account.balance)
```

```bash title="Terminal" verify="run"
python3 property_reference.py
```

```text title="Expected output"
20
```

## Step 4: Extend behavior with inheritance
Use `super()` when a subclass adds to an inherited implementation.

```python title="inheritance_reference.py" file
class Base:
    def label(self):
        return "base"


class Child(Base):
    def label(self):
        return super().label() + "/child"


print(Child().label())
print([class_.__name__ for class_ in Child.mro()])
```

```bash title="Terminal" verify="run"
python3 inheritance_reference.py
```

```text title="Expected output"
base/child
['Child', 'Base', 'object']
```

## How it works
The core choices are: instance attributes for per-object state, class attributes for deliberate shared values, `__init__` for invariants, properties for controlled access, class methods for class-aware factories, static methods for stateless helpers, and `super()` for cooperative inheritance.

## Common errors
### Choosing a feature because it sounds advanced
Prefer a plain function or attribute when it already expresses the design clearly.

### Sharing mutable class state accidentally
Initialize mutable per-object values in `__init__`.

### Calling a base implementation directly by habit
Use `super()` when the hierarchy should cooperate.
