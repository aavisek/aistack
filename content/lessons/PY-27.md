## Why this matters
Inheritance lets a specialized class reuse a general one, but accessing inherited behavior has choices. Direct class calls, `super()`, and ordinary instance lookup have different meanings and maintenance trade-offs.

## What you will build
An `Employee` base class and a `Manager` subclass that compares three access styles.

## Before you start
Create `base_access.py` and run it with Python 3.10 or newer.

## Step 1: Use ordinary instance lookup
If the subclass does not replace a method, the instance finds the inherited method.

```python title="base_access.py" file
class Employee:
    def badge(self):
        return f"employee:{self.name}"


class Manager(Employee):
    pass


manager = Manager()
manager.name = "Mina"
print(manager.badge())
```

```bash title="Terminal" verify="run"
python3 base_access.py
```

```text title="Expected output"
employee:Mina
```

## Step 2: Call the base class directly
Calling `Employee.badge(manager)` supplies the subclass instance explicitly. This names one specific base implementation.

```python title="direct_base_call.py" file
class Employee:
    def badge(self):
        return f"employee:{self.name}"


class Manager(Employee):
    def badge(self):
        return "manager/" + Employee.badge(self)


manager = Manager()
manager.name = "Mina"
print(manager.badge())
```

```bash title="Terminal" verify="run"
python3 direct_base_call.py
```

```text title="Expected output"
manager/employee:Mina
```

## Step 3: Prefer super()
`super()` asks Python to continue lookup after the current class. It avoids spelling the base class and cooperates with multiple inheritance.

```python title="super_call.py" file
class Employee:
    def badge(self):
        return f"employee:{self.name}"


class Manager(Employee):
    def badge(self):
        return "manager/" + super().badge()


manager = Manager()
manager.name = "Mina"
print(manager.badge())
```

```bash title="Terminal" verify="run"
python3 super_call.py
```

```text title="Expected output"
manager/employee:Mina
```

## Step 4: Compare the choices
Use ordinary lookup for inherited behavior, `super()` to extend cooperative behavior, and a direct base call only when intentionally naming one implementation.

```python title="access_summary.py" file
class Base:
    def value(self):
        return "base"


class Child(Base):
    def inherited(self):
        return self.value()

    def cooperative(self):
        return super().value()

    def explicit(self):
        return Base.value(self)


child = Child()
print(child.inherited(), child.cooperative(), child.explicit())
```

```bash title="Terminal" verify="run"
python3 access_summary.py
```

```text title="Expected output"
base base base
```

## How it works
Instance lookup follows the method resolution order. A direct `Base.method(self)` bypasses normal cooperative lookup. Zero-argument `super()` uses the current class and instance context to continue through the MRO.

## Common errors
### Calling `super()` outside a method
Zero-argument `super()` needs compiler-provided context and normally belongs inside a method.

### Calling the base class when multiple inheritance is expected
Direct calls can skip sibling classes. Use `super()` for cooperative designs.

### Forgetting the instance in a direct call
`Base.method(self)` is required because the class access is not bound.

## Recap
- Inherited methods can be reached through normal lookup.
- Direct base calls are explicit but can bypass the MRO.
- `super()` is the maintainable choice for cooperative overrides.
