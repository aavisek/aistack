## Why this matters
A property lets an object expose attribute-style access while validating, computing, or protecting the value behind it. This keeps callers simple without giving up control over invariants.

## What you will build
A `Product` class with a validated `price` property and a read-only computed label.

## Before you start
Create `properties.py` and run it with Python 3.10 or newer.

## Step 1: Add a getter
The getter runs when the property is read.

```python title="properties.py" file
class Product:
    def __init__(self, name, cents):
        self.name = name
        self._cents = cents

    @property
    def price(self):
        return self._cents / 100


product = Product("Notebook", 1250)
print(product.price)
```

```bash title="Terminal" verify="run"
python3 properties.py
```

```text title="Expected output"
12.5
```

## Step 2: Add a setter
The setter validates assignments while callers keep using `product.price = value`.

```python title="validated_price.py" file
class Product:
    def __init__(self, name, price):
        self.name = name
        self.price = price

    @property
    def price(self):
        return self._cents / 100

    @price.setter
    def price(self, value):
        if value < 0:
            raise ValueError("price cannot be negative")
        self._cents = round(value * 100)


product = Product("Notebook", 12.5)
product.price = 15
print(product.price)
try:
    product.price = -1
except ValueError as error:
    print(error)
```

```bash title="Terminal" verify="run"
python3 validated_price.py
```

```text title="Expected output"
15.0
price cannot be negative
```

## Step 3: Create a read-only property
Without a setter, callers can read a computed value but cannot assign it.

```python title="read_only.py" file
class Product:
    def __init__(self, name, price):
        self.name = name
        self._price = price

    @property
    def label(self):
        return f"{self.name}: ${self._price:.2f}"


product = Product("Notebook", 12.5)
print(product.label)
try:
    product.label = "changed"
except AttributeError:
    print("label is read-only")
```

```bash title="Terminal" verify="run"
python3 read_only.py
```

```text title="Expected output"
Notebook: $12.50
label is read-only
```

## Step 4: Keep storage separate
Use a backing attribute such as `_price` or `_cents`; the property name itself calls the getter and would recurse if it assigned to itself.

```python title="backing_attribute.py" file
class Score:
    def __init__(self, value):
        self.value = value

    @property
    def value(self):
        return self._value

    @value.setter
    def value(self, new_value):
        if not 0 <= new_value <= 100:
            raise ValueError("score must be 0..100")
        self._value = new_value


score = Score(80)
score.value = 95
print(score.value)
```

```bash title="Terminal" verify="run"
python3 backing_attribute.py
```

```text title="Expected output"
95
```

## How it works
`property` is a descriptor. The getter, setter, and optional deleter define what happens for attribute access. A property is a good compatibility layer when validation or computation is part of the public contract.

## Verify against the requirements
- [x] A getter supports attribute-style reads → Step 1
- [x] A setter validates attribute-style writes → Step 2
- [x] A property can be read-only and computed → Step 3

## Common errors
### Assigning to the property inside its setter
Use a backing name such as `_value` to avoid infinite recursion.

### Exposing internal storage as public API
Keep `_value` internal and let the property enforce the invariant.

### Using a property for every trivial attribute
A plain attribute is clearer when no behavior or validation is needed.

## Recap
- Properties preserve simple attribute syntax with controlled behavior.
- Getters read and setters validate or transform values.
- Backing attributes prevent recursive property access.
