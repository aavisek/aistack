## Why this matters
HTTP is the set of rules a browser, phone, or program uses to ask another computer for something. REST is a common way to organize those requests around named resources. Think of a request as a library slip: it names the book, says what action you want, and may include a note.

## What you will build
You will inspect real HTTP responses, compare common methods and status codes, create a Postman collection with eight requests, save a request log in `NOTES.md`, and run the collection with Newman.

## Step 1: Read a GET request
GET asks a server to return information. A URL is the address of a resource; `?topic=books` is a query parameter, which adds a filter or option.

```bash tab="macOS / Linux" title="Terminal" verify="manual" manual review required 2026-10-18 Linux
curl -i "https://httpbin.org/get?topic=books"
```

```powershell tab="Windows PowerShell" title="Terminal" verify="manual" manual review required 2026-10-18 Windows
Invoke-RestMethod -Uri "https://httpbin.org/get?topic=books" -Method Get
```

```text title="Expected output"
HTTP/2 200
content-type: application/json
"args": { "topic": "books" }
```

The `-i` switch asks curl to include response headers. A header is named metadata sent with a request or response; `Content-Type` says how to read the body.

> **Checkpoint:** the returned JSON contains `"topic": "books"`.

## Step 2: Compare path, query, header, and body
A path parameter identifies a resource, a query parameter adds options, a header carries request metadata, and a JSON body carries structured input.

```bash tab="macOS / Linux" title="Terminal" verify="manual" manual review required 2026-10-18 Linux
curl -i "https://httpbin.org/anything/users/42?view=full" -H "X-Lesson-Token: demo-token"
curl -i "https://httpbin.org/post" -H "Content-Type: application/json" -d '{"name":"Ada","role":"reader"}'
```

```powershell tab="Windows PowerShell" title="Terminal" verify="manual" manual review required 2026-10-18 Windows
Invoke-RestMethod -Uri "https://httpbin.org/anything/users/42?view=full" -Headers @{ "X-Lesson-Token" = "demo-token" } -Method Get
$body = @{ name = "Ada"; role = "reader" } | ConvertTo-Json
Invoke-RestMethod -Uri "https://httpbin.org/post" -ContentType "application/json" -Body $body -Method Post
```

```text title="Expected output"
The first JSON contains url .../anything/users/42?view=full and X-Lesson-Token.
The second JSON contains the submitted name and role.
```

> **Warning:** `demo-token` is a made-up practice value. Never paste a real password or token into a public request service.

## Step 3: Send each common method
HTTP methods describe the requested action. POST submits or creates data; PUT replaces a resource; PATCH changes selected fields; DELETE asks to remove a resource.

```bash tab="macOS / Linux" title="Terminal" verify="manual" manual review required 2026-10-18 Linux
curl -i "https://httpbin.org/get"
curl -i "https://httpbin.org/post" -H "Content-Type: application/json" -d '{"title":"First note"}'
curl -i "https://httpbin.org/put" -H "Content-Type: application/json" -d '{"id":1,"title":"Replacement"}'
curl -i "https://httpbin.org/patch" -H "Content-Type: application/json" -d '{"title":"Edited"}'
curl -i -X DELETE "https://httpbin.org/delete"
```

```powershell tab="Windows PowerShell" title="Terminal" verify="manual" manual review required 2026-10-18 Windows
Invoke-RestMethod -Uri "https://httpbin.org/get" -Method Get
$body = @{ title = "First note" } | ConvertTo-Json
Invoke-RestMethod -Uri "https://httpbin.org/post" -ContentType "application/json" -Body $body -Method Post
$body = @{ id = 1; title = "Replacement" } | ConvertTo-Json
Invoke-RestMethod -Uri "https://httpbin.org/put" -ContentType "application/json" -Body $body -Method Put
$body = @{ title = "Edited" } | ConvertTo-Json
Invoke-RestMethod -Uri "https://httpbin.org/patch" -ContentType "application/json" -Body $body -Method Patch
Invoke-RestMethod -Uri "https://httpbin.org/delete" -Method Delete
```

```text title="Expected output"
GET, POST, PUT, PATCH, and DELETE each return an HTTP/2 200 response from httpbin.
The JSON response describes the method and body that httpbin received.
```

Repeat the same PUT request twice and compare its echoed method and body. Repeat the POST request too. The practice service echoes requests rather than storing them, so this proves the request is repeatable, not a real database mutation.

> **Checkpoint:** the output for each request reports the intended method.

## Step 4: Inspect status-code classes
A status code is a three-digit response that summarizes what happened. The first digit groups the meaning: 2 means success, 3 means redirect, 4 means a client-side problem, and 5 means a server-side problem.

```bash title="Terminal" verify="manual" manual review required 2026-10-18 Linux
for code in 200 201 204 301 400 401 403 404 429 500; do
  curl -s -o /dev/null -w "$code -> %{http_code}\n" "https://httpbin.org/status/$code"
done
```

```powershell title="Terminal" verify="manual" manual review required 2026-10-18 Windows
200,201,204,301,400,401,403,404,429,500 | ForEach-Object {
  curl.exe -s -o NUL -w "$_ -> %{http_code}`n" "https://httpbin.org/status/$_"
}
```

```text title="Expected output"
200 -> 200
201 -> 201
204 -> 204
301 -> 301
400 -> 400
401 -> 401
403 -> 403
404 -> 404
429 -> 429
500 -> 500
```

For a redirect with a `Location` header, request the endpoint with `curl -i` and inspect the response headers rather than following the redirect automatically.

> **Checkpoint:** each left-hand number matches the returned status.

## Step 5: Make an eight-request Postman collection
A collection groups requests; an environment stores reusable values such as a base URL.

1. Open Postman and choose **New → Collection**.
2. Name it `FD-02 HTTP and REST`.
3. Choose **Environments → Create environment**, name it `FD-02 local`, and add `baseUrl` with value `https://httpbin.org` and `token` with value `demo-token`.
4. Add the eight requests in the collection file below.
5. For the `Bearer token echo` request, set **Authorization → Bearer Token** to `{{token}}`; select `FD-02 local` in the environment menu.
6. Save both. Export the environment as `fd-02-http-rest.postman_environment.json` and the collection via **View more actions → Export → Collection v2.1**.

```text title="Expected output"
The collection is named FD-02 HTTP and REST and is ready for its eight requests.
```

> **Tip:** Postman collection variables use double braces, such as `{{baseUrl}}`, so you can change the host once without editing every request.

## Step 8: Compare repeating PUT and POST
Idempotent means repeating the same request has the same intended effect as doing it once. Repeat the same PUT URL and body twice, then repeat the same POST URL and body twice. Compare the method and request body in the echoed response.

```bash tab="macOS / Linux" title="Terminal" verify="manual" manual review required 2026-10-18 Linux
curl -s "https://httpbin.org/put" -H "Content-Type: application/json" -d '{"id":1,"title":"Replacement"}'
curl -s "https://httpbin.org/put" -H "Content-Type: application/json" -d '{"id":1,"title":"Replacement"}'
curl -s "https://httpbin.org/post" -H "Content-Type: application/json" -d '{"title":"First note"}'
curl -s "https://httpbin.org/post" -H "Content-Type: application/json" -d '{"title":"First note"}'
```

```powershell tab="Windows PowerShell" title="Terminal" verify="manual" manual review required 2026-10-18 Windows
$put = @{ id = 1; title = "Replacement" } | ConvertTo-Json
Invoke-RestMethod -Uri "https://httpbin.org/put" -ContentType "application/json" -Body $put -Method Put
Invoke-RestMethod -Uri "https://httpbin.org/put" -ContentType "application/json" -Body $put -Method Put
$post = @{ title = "First note" } | ConvertTo-Json
Invoke-RestMethod -Uri "https://httpbin.org/post" -ContentType "application/json" -Body $post -Method Post
Invoke-RestMethod -Uri "https://httpbin.org/post" -ContentType "application/json" -Body $post -Method Post
```

```text title="Expected output"
The first two responses both echo method PUT and the same JSON body.
The last two responses both echo method POST and the same JSON body.
```

> **Note:** httpbin is an echo service, not a database. The method definitions explain the intended idempotency; this practice call verifies that you repeated the exact request rather than observing stored records.

## How it works
The client sends a method, URL, headers, and sometimes a body. The server returns a status, headers, and sometimes a body. REST keeps URLs focused on nouns and uses the method to describe the action.

```text title="Request and response"
Client  -- method + URL + headers + body -->  Server
Client  <-- status + headers + body --------  Server
```

## Common errors
### `curl: (6) Could not resolve host`
The computer cannot find the host name. Check the internet connection, then retry the exact URL.

### `curl: (3) URL rejected: Malformed input to a URL function`
The URL contains unescaped spaces or punctuation. Put it in quotes and encode spaces as `%20`.

### `401 Unauthorized`
The server did not receive valid authentication. Check the Authorization tab and confirm the demo token variable is selected.

### `429 Too Many Requests`
The practice server is limiting repeated requests. Wait before trying again; do not run a tight retry loop.

## Recap
- HTTP requests combine a method, URL, headers, and sometimes a body.
- Status codes summarize the result; response headers describe the response.
- REST uses resource names in URLs and methods to describe actions.
