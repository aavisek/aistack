## Why this matters
Multiple inheritance is useful for combining focused behaviors, but Python needs a deterministic rule for choosing methods. The method resolution order (MRO) is that rule and is also what makes cooperative `super()` calls work.

## What you will build
A small diamond hierarchy and a cooperative chain that prints its MRO.

## Before you start
Create `mro.py` and run it with Python 3.10 or newer.

## Step 1: Inspect a simple MRO
Every class has an ordered search path available through `__mro__` or `mro()`.

```python title="mro.py" file
class Root:
    pass


class Left(Root):
    pass


class Right(Root):
    pass


class Diamond(Left, Right):
    pass


print([class_.__name__ for class_ in Diamond.__mro__])
```

```bash title="Terminal" verify="run"
python3 mro.py
```

```text title="Expected output"
['Diamond', 'Left', 'Right', 'Root', 'object']
```

## Step 2: See which method wins
Python selects the first class in the MRO that defines the requested method.

```python title="method_order.py" file
class Root:
    def label(self):
        return "root"


class Left(Root):
    def label(self):
        return "left"


class Right(Root):
    def label(self):
        return "right"


class Diamond(Left, Right):
    pass


print(Diamond().label())
```

```bash title="Terminal" verify="run"
python3 method_order.py
```

```text title="Expected output"
left
```

## Step 3: Make methods cooperate
Each method calls `super()` once, allowing every class in the MRO to participate.

```python title="cooperative_mro.py" file
class Root:
    def label(self):
        return ["root"]


class Left(Root):
    def label(self):
        return ["left"] + super().label()


class Right(Root):
    def label(self):
        return ["right"] + super().label()


class Diamond(Left, Right):
    def label(self):
        return ["diamond"] + super().label()


print(Diamond().label())
```

```bash title="Terminal" verify="run"
python3 cooperative_mro.py
```

```text title="Expected output"
['diamond', 'left', 'right', 'root']
```

## Step 4: Respect consistent hierarchies
Python rejects inheritance graphs whose ordering cannot be made consistent. Keep mixins focused and ensure their methods use compatible signatures.

```python title="mro_summary.py" file
class LoggingMixin:
    def run(self):
        return ["log"] + super().run()


class Core:
    def run(self):
        return ["core"]


class Service(LoggingMixin, Core):
    pass


service = Service()
print(service.run())
print([class_.__name__ for class_ in Service.mro()])
```

```bash title="Terminal" verify="run"
python3 mro_summary.py
```

```text title="Expected output"
['log', 'core']
['Service', 'LoggingMixin', 'Core', 'object']
```

## How it works
Python calculates a C3 linearization for the class hierarchy. The resulting order includes the class, its bases, and `object` without repeating a class. `super()` follows that order rather than simply calling one textual parent.

## Common errors
### Assuming super means “my parent”
It means “continue after this class in the MRO.”

### Forgetting compatible method signatures
Cooperative methods should accept and forward compatible arguments.

### Building deep, unrelated inheritance trees
Prefer composition when the relationship is not truly an “is-a” relationship.
