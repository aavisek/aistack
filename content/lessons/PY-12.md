## Why this matters
Real programs decide things: approve or reject, accept or ask for review. A loan checker shows the habits that make those decisions easy to read and test: validate first, reject on hard rules with early returns, then let a score choose between tiers. It also shows where decision bugs hide, which is on the edges, such as an age of exactly 21 or a ratio of exactly 0.50.

## What you will build
Small, standalone Python scripts that test an age range with a chained comparison, format numbers with f-strings, apply four hard rules, map a credit score to three outcomes, test every boundary, collect all failure reasons, and validate text input. You finish with a `check_loan()` function that prints a decision for six applicants. The rules are illustrative only.

## Before you start
Use Python 3.10 or newer and create each named file in a practice folder. Every example is independent. Run each file with `python3 filename.py` on macOS/Linux or `py -3 filename.py` in Windows PowerShell.

The rules are these. Age must be 21 to 60, monthly income at least 25000, the debt ratio (monthly EMI divided by income) at most 0.50, and the loan at most 20 times monthly income. Then the score picks the outcome: 750 or more is approved at 9.5%, 650 to 749 at 11.5%, 600 to 649 goes to manual review, and below 600 is rejected. This lesson builds on the `if`/`elif`/`else` statements from PY-10 and the string handling from PY-03.

## Step 1: Chained comparisons and named constants
Python lets you chain comparisons, so `21 <= age <= 60` reads exactly like the business rule and means `21 <= age and age <= 60`. To reject, put `not` in front; comparisons bind tighter than `not`, so no parentheses are needed. Policy numbers belong in named constants so a policy change is a one-line edit.

```python title="chained.py" file
MIN_AGE = 21
MAX_AGE = 60

for age in [20, 21, 40, 60, 61]:
    print(age, 21 <= age <= 60, MIN_AGE <= age <= MAX_AGE)

print(not 21 <= 19 <= 60)
print(21 <= 19 <= 60, (21 <= 19) <= 60)
```

```bash title="Terminal" verify="run"
python3 chained.py
```

```text title="Expected output"
20 False False
21 True True
40 True True
60 True True
61 False False
True
False True
```

Both limits are inclusive because `<=` accepts equal values. The last line is a trap: adding parentheses compares `False` with 60 and gives `True`, so never add them inside a chain.

## Step 2: Format numbers with f-strings
A decision message often shows a ratio or an amount. Inside an f-string, a format spec after the colon controls the result: `:.0%` multiplies by 100 and shows a percent with no decimals, `:,` adds thousands separators, `:.1f` and `:.2f` fix the decimals, and `:>6` right-aligns in a width of six.

```python title="fstrings.py" file
print(f"{0.1667:.0%}")
print(f"{800000:,}")
print(f"{9.5:.1f}%")
print(f"{3.14159:.2f}")
print(f"{42:>6}")
print(repr(f"{42:>6}"))

dti = 20000 / 30000
income = 30000
print(f"DTI {dti:.0%} and max loan {20 * income:,}")
print(f"{20 * 30000.0:,}")
```

```bash title="Terminal" verify="run"
python3 fstrings.py
```

```text title="Expected output"
17%
800,000
9.5%
3.14
    42
'    42'
DTI 67% and max loan 600,000
600,000.0
```

`repr()` shows that `:>6` adds four leading spaces. Rounding only changes how the value is displayed, not the value. Note that a float such as `30000.0` keeps its `.0` in the output, so keep money as whole integers when you can.

## Step 3: Hard rules with early return
A hard rule rejects the applicant immediately. Write each rule as its own `if` that returns a message, so the failure text sits right beside its test. This function returns the failure text, or `None` when every hard rule passes. The order matters: the income check runs before `emi / income`, so the division never sees zero.

```python title="hard_rules.py" file
MIN_AGE = 21
MAX_AGE = 60
MIN_INCOME = 25000
MAX_DTI = 0.5
MAX_MULTIPLE = 20


def hard_rule_failure(age, income, emi, amount):
    if not MIN_AGE <= age <= MAX_AGE:
        return "age must be 21-60"
    if income < MIN_INCOME:
        return "income below 25,000"
    dti = emi / income
    if dti > MAX_DTI:
        return f"DTI {dti:.0%} > 50%"
    if amount > MAX_MULTIPLE * income:
        return f"max loan {MAX_MULTIPLE * income:,}"
    return None


print(hard_rule_failure(30, 60000, 10000, 800000))
print(hard_rule_failure(19, 50000, 0, 100000))
print(hard_rule_failure(30, 20000, 0, 100000))
print(hard_rule_failure(40, 30000, 20000, 100000))
print(hard_rule_failure(30, 30000, 0, 900000))
```

```bash title="Terminal" verify="run"
python3 hard_rules.py
```

```text title="Expected output"
None
age must be 21-60
income below 25,000
DTI 67% > 50%
max loan 600,000
```

The debt-to-income ratio (DTI) is the monthly EMI divided by monthly income. A function that reaches its end without `return` also gives `None`, but the explicit `return None` makes the intent clear. Each `if` runs only if the earlier rules passed, so the flat layout needs no `else`.

## Step 4: Score tiers with if/elif
Once the hard rules pass, the score chooses the outcome. An `if`/`elif` chain stops at the first true test, so test the highest threshold first. The second function shows what happens when the order is wrong.

```python title="tiers.py" file
def score_outcome(score):
    if score >= 750:
        return "Approved at 9.5%"
    elif score >= 650:
        return "Approved at 11.5%"
    elif score >= 600:
        return "Manual review"
    return "Rejected: score below 600"


def wrong_order(score):
    if score >= 600:
        return "Manual review"
    elif score >= 650:
        return "Approved at 11.5%"
    elif score >= 750:
        return "Approved at 9.5%"
    return "Rejected: score below 600"


for score in [780, 750, 700, 650, 620, 600, 599]:
    print(score, score_outcome(score))

print(wrong_order(780))
```

```bash title="Terminal" verify="run"
python3 tiers.py
```

```text title="Expected output"
780 Approved at 9.5%
750 Approved at 9.5%
700 Approved at 11.5%
650 Approved at 11.5%
620 Manual review
600 Manual review
599 Rejected: score below 600
Manual review
```

In `wrong_order`, a score of 780 is already `>= 600`, so the first branch wins and the better tiers are unreachable. In the correct version, a score of exactly 750, 650, or 600 lands in the better tier because the tests use `>=`. The final `return` is the default for everything below 600.

## Step 5: Assemble check_loan with named constants
Now combine the hard rules and the tiers in one function. The constants appear in the messages through f-strings, so the text can never disagree with the rule. The cases below fail several rules at once, and only the first failing message is returned.

```python title="assemble.py" file
MIN_AGE = 21
MAX_AGE = 60
MIN_INCOME = 25000
MAX_DTI = 0.5
MAX_MULTIPLE = 20


def check_loan(age, income, score, emi, amount):
    if not MIN_AGE <= age <= MAX_AGE:
        return f"Rejected: age must be {MIN_AGE}-{MAX_AGE}"
    if income < MIN_INCOME:
        return f"Rejected: income below {MIN_INCOME:,}"
    dti = emi / income
    if dti > MAX_DTI:
        return f"Rejected: DTI {dti:.0%} > {MAX_DTI:.0%}"
    if amount > MAX_MULTIPLE * income:
        return f"Rejected: max loan {MAX_MULTIPLE * income:,}"
    if score >= 750:
        return "Approved at 9.5%"
    elif score >= 650:
        return "Approved at 11.5%"
    elif score >= 600:
        return "Manual review"
    return "Rejected: score below 600"


print(check_loan(19, 20000, 500, 30000, 900000))
print(check_loan(30, 20000, 500, 30000, 900000))
print(check_loan(30, 0, 700, 0, 0))
print(check_loan(30, 30000, 500, 20000, 900000))
print(check_loan(30, 30000, 500, 0, 900000))
print(check_loan(30, 30000, 500, 0, 100000))
```


The first case also has low income, a high ratio, and a big amount, but the age rule fires first. The third case has an income of zero and still does not crash, because the income rule returns before the division. The last case passes all four hard rules, so the score decides.

## Step 6: Test the boundaries
Most bugs hide on the edges, so test each limit exactly, one below and one above. Age 21 and 60 are accepted because `<=` is inclusive. Income exactly 25000 is accepted because the rejection test `<` is strict, and a DTI of exactly 0.50 is accepted because `>` is strict. Scores of 750, 650, and 600 land in the better tier.

```python title="boundaries.py" file
def check_loan(age, income, score, emi, amount):
    if not 21 <= age <= 60:
        return "Rejected: age must be 21-60"
    if income < 25000:
        return "Rejected: income below 25,000"
    dti = emi / income
    if dti > 0.5:
        return f"Rejected: DTI {dti:.0%} > 50%"
    if amount > 20 * income:
        return f"Rejected: max loan {20 * income:,}"
    if score >= 750:
        return "Approved at 9.5%"
    elif score >= 650:
        return "Approved at 11.5%"
    elif score >= 600:
        return "Manual review"
    return "Rejected: score below 600"


for age in [20, 21, 60, 61]:
    print("age", age, "->", check_loan(age, 60000, 780, 0, 100000))

print("income 24999 ->", check_loan(30, 24999, 780, 0, 100000))
print("income 25000 ->", check_loan(30, 25000, 780, 0, 100000))
print("DTI 0.50 ->", check_loan(30, 40000, 780, 20000, 100000))
print("DTI 0.51 ->", check_loan(30, 40000, 780, 20400, 100000))
print("amount 500000 ->", check_loan(30, 25000, 780, 0, 500000))
print("amount 500001 ->", check_loan(30, 25000, 780, 0, 500001))

for score in [750, 749, 650, 649, 600, 599]:
    print("score", score, "->", check_loan(30, 60000, score, 0, 100000))
```


Changing `>` to `>=` or `<` to `<=` would flip exactly one line here, which is why edge tests catch off-by-one mistakes. The DTI of 20000 / 40000 is exactly 0.5 in floating point, so the strict test accepts it.

## Step 7: Collect every reason
Early return stops at the first failure. When an applicant needs to know everything that is wrong, gather the failures in a list instead. An empty list means no problems, and an empty list is falsy, so `if found:` tests for trouble.

```python title="reasons.py" file
def reasons(age, income, score):
    why = []
    if not 21 <= age <= 60:
        why.append("age")
    if income < 25000:
        why.append("income")
    if score < 600:
        why.append("credit score")
    return why


print(reasons(19, 20000, 580))
print(reasons(30, 50000, 700))

found = reasons(61, 30000, 590)
if found:
    print("Rejected:", ", ".join(found))
print(len(reasons(19, 20000, 580)), bool(reasons(30, 50000, 700)))
```

```bash title="Terminal" verify="run"
python3 reasons.py
```

```text title="Expected output"
['age', 'income', 'credit score']
[]
Rejected: age, credit score
3 False
```

Every `if` here is independent, so none uses `elif` or `return`. `", ".join(found)` turns the list into readable text, as in PY-03. Use early return for the cheapest, clearest single answer, and a list when the caller needs the full picture.

## Step 8: A chained ternary for tiers
When each branch of an `if`/`elif` chain only returns a value, a chained conditional expression is a compact alternative. It reads `value if test else other`, and `else` can start another one. Wrap the whole expression in parentheses so it can span lines.

```python title="tier.py" file
def tier(score):
    return ("A" if score >= 750 else
            "B" if score >= 650 else
            "C" if score >= 600 else "D")


def tier_if(score):
    if score >= 750:
        return "A"
    elif score >= 650:
        return "B"
    elif score >= 600:
        return "C"
    return "D"


print(tier(780), tier(700), tier(620), tier(500))
print(tier(750), tier(649))
print(all(tier(s) == tier_if(s) for s in range(0, 901)))
```

```bash title="Terminal" verify="run"
python3 tier.py
```

```text title="Expected output"
A B C D
A C
True
```

The same rule applies: the highest threshold comes first. The last line proves that both versions agree for every score from 0 to 900. Prefer `if`/`elif` when a branch needs several statements, because a long ternary is harder to read.

## Step 9: Validate input before using it
Text typed by a user arrives as a string, and `int("abc")` raises `ValueError`. Check with `isdigit()` first. The program must stay deterministic, so this version loops over fixed test strings instead of calling `input()`. In a live program the text would come from `input("Age: ")`.

```python title="validate.py" file
def check_age_text(text):
    if not text.isdigit():
        return "Digits only, please"
    elif int(text) < 21:
        return "Too young for this loan"
    else:
        return "Age accepted"


for text in ["25", "19", "abc", "-5", "2.5", "", " 30"]:
    print(repr(text), "->", check_age_text(text))

print("\u00b2".isdigit(), "\u00b2".isdecimal(), "25".isdecimal())
```

```bash title="Terminal" verify="run"
python3 validate.py
```

```text title="Expected output"
'25' -> Age accepted
'19' -> Too young for this loan
'abc' -> Digits only, please
'-5' -> Digits only, please
'2.5' -> Digits only, please
'' -> Digits only, please
' 30' -> Digits only, please
True False True
```

`isdigit()` rejects `"abc"`, `"-5"`, `"2.5"`, the empty string, and text with spaces, so `int()` never crashes on them. The `if`/`elif`/`else` order is validate, then rule, then accept. The last line is a gotcha: the superscript two counts as a digit, yet `int()` cannot convert it, so `isdecimal()` is the stricter choice. Trim spaces first with `strip()` if you want `" 30"` accepted.

## How it works
The checker is a decision pipeline: validate the input, apply the hard rules in order, then choose a tier. Each hard rule is an `if` that returns, so Python leaves the function at the first failure and the later code runs only for applicants who passed everything before it. The chained comparison `21 <= age <= 60` is evaluated left to right and short-circuits, and `not` applies to the whole chain.

An `if`/`elif` chain tests conditions top to bottom and runs only the first branch whose test is true, which is why the highest threshold goes first. The boundary cases come from the operators: `<=` and `>=` include the limit, while `<` and `>` exclude it. F-string format specs change only how a value is displayed. Keeping thresholds in named constants makes policy changes one-line edits. This is a learning model, not financial advice, because real lenders weigh many more factors.

## Common errors
### `ZeroDivisionError: division by zero`
`emi / income` fails when income is `0`. Keep the income check before the division, as in Step 5, so a zero income is rejected before the ratio is computed.

### `ValueError: invalid literal for int() with base 10: 'abc'`
`int()` cannot convert text that is not a whole number. Test with `isdigit()` first, or wrap the call in `try`/`except ValueError`. Remember that `"-5"` and `"2.5"` also fail `isdigit()`.

### A good score gets the wrong tier
When `score >= 600` is tested before `score >= 750`, every passing score stops at the first branch. In an `if`/`elif` chain, test the highest threshold first.

### Limit values are accepted or rejected wrongly
Writing `income <= 25000` instead of `income < 25000` rejects an applicant who exactly meets the minimum. Match each operator to the rule wording and test the edges, one below and one above.

### An f-string prints `6700%` or `600,000.0`
A spec must match the value: `:,` and `:.2f` need numbers, and `:.0%` expects a ratio such as `0.67`, not `67`. A float also keeps its decimal part, so `f"{600000.0:,}"` prints `600,000.0`.

### Parentheses break a chained comparison
`(21 <= age) <= 60` compares a `bool` with 60 and is always true for a valid age check. Write `21 <= age <= 60` without parentheses.

## Recap
- Validate input first, then apply hard rules with early returns, then pick a tier; a chained comparison such as `21 <= age <= 60` reads like the rule.
- In an `if`/`elif` chain test the highest threshold first, match `<`, `<=`, `>`, and `>=` to the rule wording, and check every limit one below and one above.
- Use f-string specs such as `:.0%`, `:,`, and `:.1f` for output, `isdigit()` before `int()`, and named constants for policy numbers.

## Final practice: Loan Eligibility Checker
The cheat sheet's program puts every piece together in one function. Create `loan_eligibility.py`; it prints a decision for six applicants.

```python title="loan_eligibility.py" file
def check_loan(age, income, score, emi, amount):
    if not 21 <= age <= 60:
        return "Rejected: age must be 21-60"
    if income < 25000:
        return "Rejected: income below 25,000"
    dti = emi / income  # debt-to-income
    if dti > 0.5:
        return f"Rejected: DTI {dti:.0%} > 50%"
    if amount > 20 * income:
        return f"Rejected: max loan {20 * income:,}"
    if score >= 750:
        return "Approved at 9.5%"
    elif score >= 650:
        return "Approved at 11.5%"
    elif score >= 600:
        return "Manual review"
    return "Rejected: score below 600"


print(check_loan(30, 60000, 780, 10000, 800000))
print(check_loan(35, 40000, 700, 5000, 500000))
print(check_loan(28, 30000, 620, 0, 300000))
print(check_loan(19, 50000, 800, 0, 100000))
print(check_loan(40, 30000, 700, 20000, 100000))
print(check_loan(30, 30000, 800, 0, 900000))
```

```bash title="Terminal" verify="run"
python3 loan_eligibility.py
```

```text title="Expected output"
Approved at 9.5%
Approved at 11.5%
Manual review
Rejected: age must be 21-60
Rejected: DTI 67% > 50%
Rejected: max loan 600,000
```

- Applicant 1 passes every hard rule and scores 780, so the first tier applies; applicant 2 scores 700, which is the 650 to 749 tier, and applicant 3 scores 620, which needs manual review.
- Applicant 4 is 19 years old, so the first rule rejects despite the score of 800.
- Applicant 5 has an EMI of 20000 against an income of 30000, a DTI of 67%, so the ratio rule rejects before the score is read.
- Applicant 6 asks for 900000 but can borrow at most 20 times 30000, which is 600,000, so the amount rule rejects even though the score is 800.
