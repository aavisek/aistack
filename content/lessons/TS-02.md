## Why this matters
In TS-01 you added two numbers directly. A function lets you give those instructions a name and reuse them with different numbers. Types describe what goes in and what comes back.

Think of a function as a small calculator: give it two numbers, and it gives you one answer.

## What you will build
First, write and call one addition function. Then build a small calculator with addition, subtraction, multiplication, and division.

**First session:** finish Steps 1–4 and practice calling the functions.

**Second session:** Steps 5–10 explain errors, reusable files, other function styles, and automated tests. There is no need to learn every style today.

## Step 2: Write and call your first function
Create `src/first-add.ts`. Read the function one piece at a time:

- `function` begins a function definition.
- `add` is its name.
- `a` and `b` are inputs, called **parameters**. Each must be a number.
- `: number` after `)` says the function returns a number.
- `return a + b` sends the answer back to the caller.

```ts title="src/first-add.ts" file
function add(a: number, b: number): number {
  return a + b;
}

console.log(add(2, 3));
console.log(add(10, 4));
```

```bash title="Terminal" verify="manual" manual review required 2026-10-18 Linux
npm run build
node dist/first-add.js
```

```text title="Expected output"
5
14
```

`add(2, 3)` **calls** the function. The supplied values, called arguments, become `a = 2` and `b = 3`. Defining the function alone does not run it.

## Step 4: Subtract, multiply, and divide
The structure stays the same; only the operation changes. `-` subtracts, `*` multiplies, and `/` divides.

Parameter order matters: `subtract(10, 4)` means 10 minus 4, not the other way around.

```ts title="src/operations.ts" file

  return a - b;

function multiply(a: number, b: number): number {
  return a * b;
```

## Step 5: Build the safer reusable calculator
Create `src/math.ts` with the complete file below. `export` lets other files use a function.

Two safety rules are new:

- `requireNumbers` checks the actual values using `typeof`. `||` means "or"; `!==` means "is not equal to".
- `throw` stops the function and reports an error. The division check uses `===`, meaning "is equal to".

`unknown` means the checking helper must inspect its inputs before making assumptions. `void` means the helper returns no answer; it only checks.

```ts title="src/math.ts" file
function requireNumbers(a: unknown, b: unknown): void {
  if (typeof a !== "number" || typeof b !== "number") {
    throw new TypeError("Both inputs must be numbers");
  }
}

export function add(a: number, b: number): number {
  requireNumbers(a, b);
  return a + b;
}

export function subtract(a: number, b: number): number {
  requireNumbers(a, b);
  return a - b;
}

export function multiply(a: number, b: number): number {
  requireNumbers(a, b);
  return a * b;
}

export function divide(a: number, b: number): number {
  requireNumbers(a, b);
  if (b === 0) {
    throw new Error("Division by zero");
  }
  return a / b;
}
```

The earlier files were stepping stones. Use `math.ts` for the remaining examples and tests. This exercise checks input types and zero divisors; it does not add a separate rule for special numeric values such as `NaN`.

## Step 6: Use the calculator and handle an error
`import` brings in the exported functions. The path ends in `.js` because Node will run the compiled file; TypeScript finds the `.ts` source when building.

`try` runs an operation that may fail. `catch` receives its error. `error instanceof Error` checks that we can safely read its message. An unexpected non-Error value is rethrown rather than hidden.

```ts title="src/calculator.ts" file
import { add, subtract, multiply, divide } from "./math.js";

console.log(add(2, 3));
console.log(subtract(10, 4));
console.log(multiply(3, 4));
console.log(divide(12, 3));

try {
  console.log(divide(10, 0));
} catch (error) {
  if (!(error instanceof Error)) {
    throw error;
  }
  console.log(error.message);
}

console.log("The program can continue.");
```


## Step 8: Recognize two other function styles
You do not have to use these yet. Both perform the same addition as Step 2:

- A **function expression** stores a function in a variable.
- An **arrow function** uses `=>` instead of the `function` keyword.

Both still show `: number` as their return type. The braces hold instructions; `return` sends back the result.

```ts title="src/function-styles.ts" file
const addExpression = function (a: number, b: number): number {
  return a + b;
};

const addArrow = (a: number, b: number): number => {
  return a + b;
};

console.log(addExpression(2, 3));
console.log(addArrow(2, 3));
```

## Step 9: Keep the deliberate type error separate
As in TS-01, `@ts-expect-error` documents an intentionally invalid line. The compiler must find an error on the next line, or it reports that the comment is unnecessary.

Create this file as a compiler test. **Do not run it:** the invalid call would throw the runtime `TypeError` too.

```ts title="src/type-checks.ts" file
import { add } from "./math.js";

// @ts-expect-error A text argument must be rejected by the compiler.

```


## Step 10: Test correct answers and rejected inputs
Save this JavaScript test file. Tests call the compiled functions and compare answers with `assert.equal`.

`assert.throws` checks an operation that should fail. The `() =>` wrapper delays that operation until the test tool calls it.

The wrong-type test is deliberately **JavaScript**, so it really bypasses TypeScript's static checks without using a type cast. It proves that the runtime guard protects JavaScript callers.

```js title="test/math.test.js" file
import test from "node:test";
import assert from "node:assert/strict";
import { add, subtract, multiply, divide } from "../dist/math.js";

test("ordinary numbers", () => {
  assert.equal(add(2, 3), 5);
  assert.equal(subtract(10, 4), 6);
  assert.equal(multiply(3, 4), 12);
  assert.equal(divide(12, 3), 4);
});

test("negative numbers", () => {
  assert.equal(add(-2, -3), -5);
  assert.equal(subtract(-2, 3), -5);
  assert.equal(multiply(-2, 3), -6);
  assert.equal(divide(-6, 2), -3);
});

test("decimal numbers", () => {
  assert.equal(add(1.5, 2.5), 4);
  assert.equal(subtract(2.5, 1.5), 1);
  assert.equal(multiply(1.5, 2), 3);
  assert.equal(divide(7.5, 2.5), 3);
});

test("division by zero throws the required error", () => {
  assert.throws(() => divide(1, 0), {
    name: "Error",
    message: "Division by zero"
  });
});

test("a JavaScript caller cannot pass text as a number", () => {
  assert.throws(() => add("1", 2), {
    name: "TypeError",
    message: "Both inputs must be numbers"
  });
  assert.throws(() => add(1, "2"), TypeError);
  assert.throws(() => subtract("1", 2), TypeError);
  assert.throws(() => multiply(1, "2"), TypeError);
  assert.throws(() => divide("6", 2), TypeError);
});
```

```bash title="Terminal" verify="manual" manual review required 2026-10-18 Linux
npm run check
npm test
```

```text title="Expected output"
The type check succeeds.
tests 5
pass 5
fail 0
```

These decimals are chosen to give exact results. Some decimal calculations, such as `0.1 + 0.2`, need approximate comparisons because of how JavaScript stores numbers.

## How it works
For `add(2, 3)`, TypeScript checks that the inputs are numbers. At runtime, our reusable `add` also checks their actual types. Then it returns `2 + 3`.

| Word | Meaning | Example |
| --- | --- | --- |
| Parameter | An input name in the function definition | `a: number` |
| Argument | A value supplied when calling | `2` in `add(2, 3)` |
| Return type | The kind of answer produced | `: number` after `)` |
| Return value | The actual answer | `5` |
| Runtime guard | A check while the program is running | `typeof a !== "number"` |

Types help before execution; runtime checks still matter for untyped callers. Neither replaces the other.

## Common errors
### Nothing appears after defining a function
Defining a function does not call it. Use `console.log(add(2, 3))` to call it and display the returned result.
### Argument of type string is not assignable to parameter of type number
Remove quotation marks if you intended a number. `"2"` is text, while `2` is numeric.
### I logged the answer inside the function but cannot use it elsewhere
Use `return` to send the answer back. Use `console.log` at the call site to display it.
### Division by zero stops my program
Wrap the call in `try/catch` as shown in Step 6, or avoid zero as a divisor. The reusable function intentionally rejects it.
### Cannot find module dist/math.js
Save `src/math.ts`, run `npm run build`, and run commands from the project folder.

## Recap
- A function names reusable instructions; parameters are inputs and return supplies the answer.
- Type annotations check calls before execution, while runtime guards protect untyped callers too.
- Start with simple calls, then add error handling and tests one idea at a time.
