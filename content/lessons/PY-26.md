## Why this matters
Objects are safer when they are valid immediately after construction. `__init__` gives every instance a predictable starting state and validates the data needed by its methods.

## What you will build
A `Temperature` class with required and default constructor arguments plus validation.

## Before you start
Create `temperature.py` and run it with Python 3.10 or newer.

## Step 1: Initialize required state
Python calls `__init__` after it creates the instance.

```python title="temperature.py" file
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius

    def fahrenheit(self):
        return self.celsius * 9 / 5 + 32


temperature = Temperature(20)
print(temperature.celsius)
print(temperature.fahrenheit())
```

```bash title="Terminal" verify="run"
python3 temperature.py
```

```text title="Expected output"
20
68.0
```

## Step 2: Use defaults
Default arguments make common construction concise while still allowing overrides.

```python title="defaults.py" file
class Temperature:
    def __init__(self, celsius=0):
        self.celsius = celsius


print(Temperature().celsius)
print(Temperature(25).celsius)
```

```bash title="Terminal" verify="run"
python3 defaults.py
```

```text title="Expected output"
0
25
```

## Step 3: Validate at the boundary
Reject invalid values in the constructor so later methods can rely on the invariant.

```python title="validated.py" file
class Temperature:
    def __init__(self, celsius):
        if celsius < -273.15:
            raise ValueError("below absolute zero")
        self.celsius = celsius


print(Temperature(-273.15).celsius)
try:
    Temperature(-300)
except ValueError as error:
    print(error)
```

```bash title="Terminal" verify="run"
python3 validated.py
```

```text title="Expected output"
-273.15
below absolute zero
```

## Step 4: Understand return values
`__init__` initializes an existing instance and must return `None`. Return useful data from a separate method.

```python title="init_return.py" file
class Label:
    def __init__(self, text):
        self.text = text


label = Label("ready")
print(label.text)
print(label.__init__("updated"))
print(label.text)
```

```bash title="Terminal" verify="run"
python3 init_return.py
```

```text title="Expected output"
ready
None
updated
```

## How it works
Calling a class creates an instance and then invokes `__init__` to configure it. `__init__` is not the allocator and is not a general factory; it should initialize the instance and return `None`. Use `@classmethod` or a separate function for alternate construction.

## Common errors
### Forgetting to initialize an attribute
Every method that expects `self.celsius` should be able to rely on the constructor.

### Returning a value from `__init__`
Python raises `TypeError` if `__init__` returns anything other than `None`.

### Using a mutable default argument
Use `None` and create a fresh list inside `__init__` when each object needs its own list.
