## Why this matters
Import styles, module search paths, and the `__name__ == "__main__"` guard determine how Python code runs as a script or library.

## What you will build
A runnable set of examples about python imports.

## Before you start
Create each named script in a Python 3.10+ environment and run the commands below.

## Step 1: Import a module namespace

```python title="py_46_1.py" file
import statistics
print(statistics.mean([2, 4, 6]))
```

```bash title="Terminal" verify="run"
python3 py_46_1.py
```

```text title="Expected output"
4
```

## Step 2: Use a main guard

```python title="py_46_2.py" file
def main():
    print("running as a script")

if __name__ == "__main__":
    main()
```

```bash title="Terminal" verify="run"
python3 py_46_2.py
```

```text title="Expected output"
running as a script
```

## Step 3: Inspect the module name

```python title="py_46_3.py" file
import sys
print(sys.modules[__name__].__name__)
```

```bash title="Terminal" verify="run"
python3 py_46_3.py
```

```text title="Expected output"
__main__
```

## Step 4: Avoid wildcard imports

```python title="py_46_4.py" file
from math import pi
print(round(pi, 2))
```

```bash title="Terminal" verify="run"
python3 py_46_4.py
```

```text title="Expected output"
3.14
```

## How it works
A namespace import keeps the source module visible.
The main guard prevents work during import.
Explicit imports make dependencies reviewable.

## Common errors
### Repeating code instead of extracting a function
Give a helper one responsibility and return its result.

### Confusing a return value with printed output
Use `return` for callers and `print` only at the boundary.

### Hiding state or dependencies
Prefer explicit parameters and imports over surprising global behavior.
