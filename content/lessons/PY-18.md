## Why this matters
Real loops rarely run from the first item to the last without interruption. You stop a search the moment you find a match, skip records that are blank, and give up after a fixed number of retries. `break`, `continue`, and the little-known `else` clause on a loop give you exact control over those moments, and they replace many clumsy flag variables.

## What you will build
Small, standalone Python scripts that stop a loop early, skip one pass, leave a placeholder body, run a fallback when nothing was found, escape nested loops, and avoid the classic `while` and `else` mistakes. You finish with an order-desk program that combines all of these ideas.

## Before you start
Use Python 3.10 or newer and create each named file in a practice folder. Every example is independent. Run each file with `python3 filename.py` on macOS/Linux or `py -3 filename.py` in Windows PowerShell.

You should already be comfortable with `for` and `while` loops from PY-13 and with writing functions from PY-17. Four statements control a loop:

| Statement | Effect |
| --- | --- |
| `break` | leave the loop now; skip everything remaining |
| `continue` | skip the rest of this pass; jump to the next one |
| `pass` | do nothing: an empty-body placeholder |
| `else` | runs when the loop ends without a `break` |

## Step 1: Stop early with break
`break` leaves the nearest loop immediately. Nothing after it in the loop body runs, and no further items are visited. Execution continues with the first statement after the loop. Use it when you have found what you were looking for and more work is wasted effort.

```python title="break_basics.py" file
for n in [3, 8, 12, 5]:
    if n > 10:
        print("found", n)
        break
    print("checked", n)

print("after the loop")
```

```bash title="Terminal" verify="run"
python3 break_basics.py
```

```text title="Expected output"
checked 3
checked 8
found 12
after the loop
```

The value `5` is never checked: once `12` triggers `break`, the loop is over. Notice that `"checked 12"` is not printed either, because `break` skipped the rest of that pass.

## Step 2: Skip one pass with continue
`continue` abandons only the current pass and jumps straight to the next item. The loop itself keeps running. It is the cleanest way to ignore items you do not want to process, and it avoids wrapping the whole body in a big `if`.

```python title="continue_basics.py" file
for n in range(1, 8):
    if n % 2 == 0:
        continue  # skip evens
    print(n, end=" ")
print("<- odd numbers")

names = ["ann", "", "bob", "", "cy"]
for name in names:
    if not name:
        continue
    print("hello", name)
```

```bash title="Terminal" verify="run"
python3 continue_basics.py
```

```text title="Expected output"
1 3 5 7 <- odd numbers
hello ann
hello bob
hello cy
```

`end=" "` keeps each number on the same line. The second loop skips empty names, so `print` only runs for real ones.

## Step 3: Use pass as a placeholder
`pass` does nothing at all. Python needs at least one statement in every body, so `pass` fills a function, class, or `if` block that you will write later. It is not the same as `continue`: after `pass` the loop body carries on with the next line.

```python title="pass_placeholder.py" file
def send_email(address):
    pass  # body comes later

for n in range(3):
    if n == 1:
        pass
    print("pass:", n)

for n in range(3):
    if n == 1:
        continue
    print("continue:", n)

print(send_email("ann@example.com"))
```

```bash title="Terminal" verify="run"
python3 pass_placeholder.py
```

```text title="Expected output"
pass: 0
pass: 1
pass: 2
continue: 0
continue: 2
None
```

With `pass`, the value `1` is still printed. With `continue`, it is skipped. A function whose body is only `pass` returns `None`.

## Step 4: Add a fallback with loop else
A loop can have an `else` block. It runs only if the loop finished naturally, meaning it was not ended by `break`. Read it as "no break". It is the built-in place for "I searched everything and found nothing".

```python title="loop_else.py" file
for n in [3, 8, 12]:
    if n > 20:
        print("found", n)
        break
else:
    print("nothing above 20")

for n in [3, 8, 25]:
    if n > 20:
        print("found", n)
        break
else:
    print("nothing above 20")
```

```bash title="Terminal" verify="run"
python3 loop_else.py
```

```text title="Expected output"
nothing above 20
found 25
```

The first loop never hits `break`, so its `else` runs. The second loop breaks on `25`, so its `else` is skipped. The `else` lines up with `for`, not with the `if`.

## Step 5: Search with a fallback
Inside a function, `return` is another way to leave a loop early. Returning from inside the loop reports a match, and a final `return` after the loop is the fallback. You get the same "found or not found" behaviour without needing `else`.

```python title="find_user.py" file
def find(users, name):
    for u in users:
        if u == name:
            return f"{u} found"
    return f"{name} not found"

print(find(["ann", "bob"], "bob"))
print(find(["ann", "bob"], "cy"))
```

```bash title="Terminal" verify="run"
python3 find_user.py
```

```text title="Expected output"
bob found
cy not found
```

The last line only runs when the loop ends without returning, which is exactly the "no break" case. Prefer this shape when the search already lives in a function.

## Step 6: Retry with a limit
A bounded retry is a perfect loop-else job. The loop makes up to three attempts. A success calls `break`, and running out of attempts falls through to `else`. The function below pretends the connection works on the attempt you pass in.

```python title="retry.py" file
def try_connect(success_on):
    for attempt in range(1, 4):
        if attempt == success_on:
            print("connected on", attempt)
            break
        print("retry", attempt)
    else:
        print("gave up")

try_connect(3)
try_connect(99)
```

```bash title="Terminal" verify="run"
python3 retry.py
```

```text title="Expected output"
retry 1
retry 2
connected on 3
retry 1
retry 2
retry 3
gave up
```

The first call succeeds on attempt 3, so `else` is skipped. The second call never succeeds, so all three retries print and `gave up` follows. No flag variable is needed.

## Step 7: Check for primes with nested loops
A number is prime when no smaller divisor from `2` upward divides it evenly. The inner `for` looks for a divisor and uses `break` when it finds one. If the inner loop finishes without breaking, no divisor exists, so its `else` reports a prime.

```python title="prime_check.py" file
for n in [7, 9, 2]:
    for d in range(2, n):
        if n % d == 0:
            print(n, "is not prime")
            break
    else:
        print(n, "is prime")
```

```bash title="Terminal" verify="run"
python3 prime_check.py
```

```text title="Expected output"
7 is prime
9 is not prime
2 is prime
```

For `9`, the divisor `3` triggers `break`, so the `else` is skipped. For `2`, `range(2, 2)` is empty, so the loop body never runs and the `else` still runs. This sketch is only correct for numbers of `2` and above.

## Step 8: Escape nested loops
`break` leaves only the nearest loop. To stop both loops, set a flag after the inner `break` and check it in the outer loop, or move the loops into a function and `return`. The first loop below shows that an inner `break` alone is not enough.

```python title="nested_break.py" file
for r in range(3):
    for c in range(3):
        if r * c == 2:
            break
    print("row", r, "stopped at c =", c)

found = False
for r in range(3):
    for c in range(3):
        if r * c == 2:
            found = True
            break  # leaves inner only
    if found:
        break  # leaves outer
print(r, c)


def first_pair():
    for r in range(3):
        for c in range(3):
            if r * c == 2:
                return r, c
    return None


print(first_pair())
```

```bash title="Terminal" verify="run"
python3 nested_break.py
```

```text title="Expected output"
row 0 stopped at c = 2
row 1 stopped at c = 2
row 2 stopped at c = 1
1 2
(1, 2)
```

Without an outer `break`, the outer loop keeps going to rows 1 and 2. The flag version stops at `1 2`, and the function version returns the pair directly, which is usually the neatest option.

## Step 9: Use else and continue in while loops
`while` loops also have an `else`, with the same "no break" meaning. Be careful with `continue` inside a `while`: it jumps back to the condition test, so any counter update written after it is skipped. Update the counter before `continue`, or you create an endless loop.

```python title="while_else.py" file
n = 0
while n < 3:
    n += 1
else:
    print("done, n =", n)

n = 0
while n < 10:
    n += 1
    if n == 2:
        break
else:
    print("no break happened")
print("stopped at n =", n)

i = 0
while i < 5:
    i += 1  # update first
    if i % 2 == 0:
        continue
    print("odd", i)

i = 0
guard = 0
while i < 5 and guard < 6:  # guard stops the demo
    guard += 1
    if i % 2 == 0:
        continue
    i += 1  # never reached while i is 0
print("bug: i =", i, "after", guard, "passes")
```

```bash title="Terminal" verify="run"
python3 while_else.py
```

```text title="Expected output"
done, n = 3
stopped at n = 2
odd 1
odd 3
odd 5
bug: i = 0 after 6 passes
```

The second loop breaks, so its `else` is silent. The last loop is the bug: `i` stays `0`, `continue` always fires, and only the extra `guard` ends it. Real code has no guard, so it would never stop.

## Step 10: Avoid the two else mistakes
An empty loop never runs its body, but it did finish without a `break`, so its `else` still runs. Also, an `else` indented under the `if` belongs to the `if`, not the loop. It then runs on every pass that fails the test, which is not a fallback at all.

```python title="else_mistakes.py" file
for item in []:
    print("never runs")
else:
    print("else still runs for an empty loop")

items = []
if not items:
    print("list was empty")
else:
    for item in items:
        print(item)

for n in [3, 8, 12]:
    if n > 20:
        print("found", n)
        break
    else:
        print(n, "is not above 20")
```

```bash title="Terminal" verify="run"
python3 else_mistakes.py
```

```text title="Expected output"
else still runs for an empty loop
list was empty
3 is not above 20
8 is not above 20
12 is not above 20
```

Check for an empty input before the loop when "nothing to search" must be treated differently from "searched and not found". In the last loop the `else` is lined up with the `if`, so it prints once per item. Move it left to line up with `for` to make it loop-else.

## How it works
`break` ends the nearest enclosing `for` or `while` loop at once, and `continue` ends only the current pass and goes to the next item (or back to the `while` test). Neither one reaches outer loops, which is why nested loops need a flag or a `return`. `pass` is only a statement that does nothing so that a body is not empty.

A loop `else` block runs when the loop condition becomes false or the iterator is exhausted, which includes loops that never ran at all. A `break` skips it, and so does a `return` or an exception that leaves the loop. That is why `else` means "no break happened". The same rule holds for `while` and for `for`.

## Common errors
### The program never stops after a `continue` in a `while` loop
`continue` jumps back to the loop test and skips the rest of the body, including a `i += 1` written below it. Put the counter update before the `continue`, or use a `for` loop over a `range` instead.

### The `else` message prints on every pass
An `else` indented under the `if` runs whenever the test is false. Line the `else` up with the `for` or `while` keyword so it runs once, after the loop.

### "Nothing found" prints for an empty list
An empty loop finishes without a `break`, so its `else` runs. Test `if not items:` before the loop when an empty input needs its own message.

### `break` stops only the inner loop
`break` leaves the nearest loop only. Set a flag and `break` again in the outer loop, or move both loops into a function and use `return`.

### `IndentationError: expected an indented block`
An `if`, `for`, or `def` with no body is a syntax error. Write `pass` as a placeholder body until you fill it in.

### `else` after a `break` never runs
That is the intended behaviour: the `else` only runs when the loop ends without `break`. If you need code that always runs, put it after the loop instead of in `else`.

## Recap
- `break` leaves the nearest loop at once, `continue` skips to the next pass, and `pass` is a do-nothing placeholder.
- Loop `else` means "no break happened", so it suits searches and bounded retries, and it also runs for an empty loop.
- Escape nested loops with a flag or a `return`, and in a `while` loop never let `continue` jump over the counter update.

## Final practice: Order Desk
The cheat sheet has no single closing program, so this one combines its ideas. Create `order_desk.py`; it uses `continue` to skip bad orders, `break` and `else` to find a bulk order and to retry a payment, `return` to escape nested loops, `while` with `else` for stock, and `pass` as a placeholder. All data is hardcoded, so the output is the same on every run.

```python title="order_desk.py" file
# Order Desk - break, continue, pass and loop else together
def refund(order_id):
    pass  # placeholder for a later feature


orders = [("A100", 3), ("A101", 0), ("A102", 5), ("A103", -1), ("A104", 2)]

print("Report 1: process orders")
total = 0
for order_id, qty in orders:
    if qty <= 0:
        print("skip", order_id)
        continue
    total += qty
    print("ok", order_id, qty)
print("total items:", total)

print("Report 2: first bulk order")
for order_id, qty in orders:
    if qty >= 5:
        print("bulk order:", order_id)
        break
else:
    print("no bulk orders")

print("Report 3: stock search")
shelves = [["pen", "ink"], ["tape", "glue"], ["clip"]]


def locate(item):
    for row, shelf in enumerate(shelves):
        for col, name in enumerate(shelf):
            if name == item:
                return row, col
    return None


print(locate("glue"))
print(locate("stapler"))

print("Report 4: payment retries")


def pay(responses):
    for attempt, status in enumerate(responses, start=1):
        if status == "ok":
            print("paid on attempt", attempt)
            break
        print("attempt", attempt, status)
    else:
        print("payment failed")


pay(["timeout", "timeout", "ok"])
pay(["timeout", "timeout", "timeout"])

print("Report 5: sell out")
stock = 3
while stock > 0:
    stock -= 1
    print("sold one, left", stock)
else:
    print("sold out")

print(refund("A103"))
```

```bash title="Terminal" verify="run"
python3 order_desk.py
```

```text title="Expected output"
Report 1: process orders
ok A100 3
skip A101
ok A102 5
skip A103
ok A104 2
total items: 10
Report 2: first bulk order
bulk order: A102
Report 3: stock search
(1, 1)
None
Report 4: payment retries
attempt 1 timeout
attempt 2 timeout
paid on attempt 3
attempt 1 timeout
attempt 2 timeout
attempt 3 timeout
payment failed
Report 5: sell out
sold one, left 2
sold one, left 1
sold one, left 0
sold out
None
```

- Report 1 uses `continue` to skip the orders whose quantity is `0` or negative, so they never reach the total.
- Reports 2 and 4 pair `break` with loop `else`: the `else` runs only when no bulk order or successful payment was found.
- Report 3 escapes two nested loops with `return`, and Report 5 shows that a `while` loop's `else` runs when the condition becomes false.
