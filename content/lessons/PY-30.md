## Why this matters
Class methods and static methods both avoid a normal instance requirement, but they serve different purposes. Choosing correctly preserves subclass behavior and makes alternate constructors explicit.

## What you will build
A `User` class with a class-method factory and a static normalization helper.

## Before you start
Create `class_vs_static.py` and run it with Python 3.10 or newer.

## Step 1: Receive cls with a class method
`@classmethod` receives the class used for the call as `cls`.

```python title="class_vs_static.py" file
class User:
    def __init__(self, name):
        self.name = name

    @classmethod
    def from_email(cls, email):
        return cls(email.split("@")[0])

    @staticmethod
    def normalize_email(email):
        return email.strip().lower()


user = User.from_email("Mina@Example.com")
print(user.name)
print(User.normalize_email("  A@B.COM "))
```

```bash title="Terminal" verify="run"
python3 class_vs_static.py
```

```text title="Expected output"
Mina
a@b.com
```

## Step 2: Preserve subclasses
Calling `cls(...)` lets a subclass inherit the factory and receive a subclass instance.

```python title="subclass_factory.py" file
class User:
    def __init__(self, name):
        self.name = name

    @classmethod
    def guest(cls):
        return cls("guest")


class Admin(User):
    pass


admin = Admin.guest()
print(type(admin).__name__, admin.name)
```

```bash title="Terminal" verify="run"
python3 subclass_factory.py
```

```text title="Expected output"
Admin guest
```

## Step 3: Compare the bindings
The three method forms differ in what Python supplies.

```python title="bindings.py" file
class Demo:
    def instance(self):
        return type(self).__name__

    @classmethod
    def class_name(cls):
        return cls.__name__

    @staticmethod
    def fixed():
        return "no implicit argument"


demo = Demo()
print(demo.instance(), Demo.class_name(), demo.fixed())
```

```bash title="Terminal" verify="run"
python3 bindings.py
```

```text title="Expected output"
Demo Demo no implicit argument
```

## How it works
Instance methods receive `self`, class methods receive `cls`, and static methods receive neither. Use a class method for factories or operations that need the class; use a static method for a related operation that needs only explicit arguments.

## Verify against the requirements
- [x] A class method receives the calling class → Step 1
- [x] A static method receives no implicit object → Step 3
- [x] A factory preserves subclass construction → Step 2

## Common errors
### Using `User(...)` inside an inherited factory
That hard-codes the base type. Use `cls(...)` when subclasses should participate.

### Calling a static helper when class state is required
Use a class method if the operation needs `cls`.

### Confusing class methods with singleton state
A class method receives a class; it does not automatically make global state safe.

## Recap
- Instance, class, and static methods have different bindings.
- Class methods are useful for subclass-aware factories.
- Static methods are stateless helpers with a class namespace.
