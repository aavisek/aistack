## Why this matters
Many programs compute a value, test it, and then need the same value again: the length of a list, the result of a regex search, or the next chunk of a file. Without help you either call the function twice or add a separate assignment line. The walrus operator `:=` assigns and returns a value in one expression, so conditions and loops stay short and nothing is computed twice.

## What you will build
Small, standalone Python scripts that use `:=` in `if` tests, `while` loops, comprehensions, regex matches, and `any()`/`all()` calls. You also meet the syntax rules, the precedence gotcha, and the cases where a plain assignment reads better. You finish with a log scanner that uses the operator in five places.

## Before you start
Use Python 3.10 or newer; the operator itself arrived in Python 3.8. Create each named file in a practice folder and run it with `python3 filename.py` on macOS/Linux or `py -3 filename.py` in Windows PowerShell. Every example is independent and uses hardcoded data instead of keyboard input, so the output is the same on every run.

The operator is written `name := expression`. It is called the walrus because `:=` looks like a pair of eyes and tusks. You will need `if` and `while` from the conditionals and loops lessons (PY-10 and PY-17) and a little list and string work from earlier lessons.

## Step 1: Assign and return in one step
A normal assignment `n = 10` is a statement and has no value. An assignment expression `n := 10` does two things: it stores the value in `n`, and the whole expression evaluates to that value. That is why it can sit inside another expression such as a `print()` call or a sum.

```python title="walrus_basics.py" file
print(n := 10)
print(n)

result = (total := 3 + 4) * 2
print(result, total)

print((x := 5))
```

```bash title="Terminal" verify="run"
python3 walrus_basics.py
```

```text title="Expected output"
10
10
14 7
5
```

`print(n := 10)` prints the returned value, and `n` still holds it afterwards. In the second example `total` keeps `7` while the multiplication uses the same value.

## Step 2: Learn the syntax rules
The operator is picky about where it may appear. A bare `x := 5` as a whole statement is a `SyntaxError`; wrap it in parentheses to make it legal. In the condition of an `if` or `while` no extra parentheses are needed. The target must be a plain name, so subscripts, attributes, and tuples are rejected. This script feeds each form to `compile()` so a failure is reported instead of stopping the program.

```python title="syntax_rules.py" file
forms = [
    "x := 5",
    "(x := 5)",
    "if x := len('ab'): pass",
    "while x := 0: pass",
    "d[k] := 1",
    "obj.a := 1",
    "(a, b) := (1, 2)",
]

for source in forms:
    try:
        compile(source, "<form>", "exec")
        verdict = "OK"
    except SyntaxError:
        verdict = "SyntaxError"
    print(f"{source:<26} {verdict}")
```

```bash title="Terminal" verify="run"
python3 syntax_rules.py
```

```text title="Expected output"
x := 5                     SyntaxError
(x := 5)                   OK
if x := len('ab'): pass    OK
while x := 0: pass         OK
d[k] := 1                  SyntaxError
obj.a := 1                 SyntaxError
(a, b) := (1, 2)           SyntaxError
```

Use `d[k] = v` or `obj.a = v` with a normal assignment when the target is not a plain name.

## Step 3: Avoid calling a function twice
A common pattern is to compute a value, test it, and then use it in the body. Written without `:=`, you either call the function twice or add a line before the `if`. The walrus keeps the call and the test together. This script counts how often an expensive function runs so you can see the difference.

```python title="avoid_twice.py" file
calls = []

def load():
    calls.append(1)
    return [3, 9, 4]

if len(load()) > 2:
    print(f"{len(load())} items is a lot")
print("calls without walrus:", len(calls))

calls.clear()
if (n := len(load())) > 2:
    print(f"{n} items is a lot")
print("calls with walrus:", len(calls))

data = [3, 9, 4]
if (count := len(data)) > 2:
    print(f"{count} items is a lot")
```

```bash title="Terminal" verify="run"
python3 avoid_twice.py
```

```text title="Expected output"
3 items is a lot
calls without walrus: 2
3 items is a lot
calls with walrus: 1
3 items is a lot
```

The second version calls `load()` once and reuses `n`. The last lines repeat the cheat sheet's `len(data)` example.

## Step 4: Write an input loop without repeating yourself
A loop that reads until an empty value used to need the read twice: once before the loop and once at the bottom. With `:=` the read happens in the `while` condition, so there is one line. The input is simulated here with `iter()` and `next()` instead of `input()`, so the script runs without a keyboard.

```python title="input_loop.py" file
lines = iter(["a", "b", ""])
line = next(lines)
while line != "":
    print("before:", line)
    line = next(lines)

lines = iter(["a", "b", ""])
while (line := next(lines)) != "":
    print("got", line)
```

```bash title="Terminal" verify="run"
python3 input_loop.py
```

```text title="Expected output"
before: a
before: b
got a
got b
```

The first loop repeats `next(lines)` twice. In the second loop the parentheses are needed because the comparison `!= ""` must apply to the value stored in `line`; the rule is explained in Step 9.

## Step 5: Read chunks until the end
Reading a file or stream in fixed-size pieces is the classic use. `f.read(3)` returns an empty string at the end, and an empty string is falsy, so the loop condition needs no comparison at all. `io.StringIO` stands in for a real file here so nothing is written to disk.

```python title="read_chunks.py" file
import io

f = io.StringIO("abcdefg")
while chunk := f.read(3):
    print(chunk)

f = io.StringIO("abcdefg")
sizes = []
while chunk := f.read(4):
    sizes.append(len(chunk))
print(sizes)
```

```bash title="Terminal" verify="run"
python3 read_chunks.py
```

```text title="Expected output"
abc
def
g
[4, 3]
```

When the whole condition is just the walrus, parentheses are not needed. The last chunk can be shorter than the size you asked for, and the next read returns `""`, which ends the loop.

## Step 6: Filter and keep the computed value
In a comprehension you often want to filter on a computed value and also keep it in the result. Without `:=` you would call `len(w)` twice per word. With it, the value is computed once per item and reused. A name assigned this way in a comprehension belongs to the enclosing scope, so it is still there after the comprehension finishes, unlike the loop variable.

```python title="comprehension_filter.py" file
words = ["hi", "hello", "yo", "world"]
pairs = [(w, n) for w in words if (n := len(w)) > 2]
print(pairs)

print(n)
try:
    print(w)
except NameError:
    print("w is not defined outside the comprehension")
```

```bash title="Terminal" verify="run"
python3 comprehension_filter.py
```

```text title="Expected output"
[('hello', 5), ('world', 5)]
5
w is not defined outside the comprehension
```

After the comprehension, `n` still holds `5`, the value from the last word tested. The loop variable `w` does not leak, but the walrus name does. Use the walrus only in the condition or the result part, not in the first `for ... in` iterable.

## Step 7: Match a regex, then use the match
`re.search()` returns a match object or `None`. A match is truthy and `None` is falsy, so you can assign and test in one `if`. Inside the body, `m` is the match. When nothing matches the body is skipped, and `m` is `None`.

```python title="regex_match.py" file
import re

if m := re.search(r"(\d+)-(\d+)", "tel 555-1234"):
    print(m.group(1), m.group(2))

if m := re.search(r"(\d+)-(\d+)", "no digits here"):
    print("unexpected match")
else:
    print("no match, m is", m)
```

```bash title="Terminal" verify="run"
python3 regex_match.py
```

```text title="Expected output"
555 1234
no match, m is None
```

Without the walrus you would write `m = re.search(...)` on one line and `if m:` on the next. Both work, but the walrus keeps the match next to the code that depends on it.

## Step 8: Capture the item with any() and all()
`any()` and `all()` return only `True` or `False`, so they hide which item decided the result. Putting a walrus inside the generator expression stores each item as it is tested. Because these functions stop early, the name holds the item where the search stopped. Wrap the walrus in parentheses inside the generator.

```python title="any_all.py" file
nums = [1, 4, 9, 12]

if any((big := n) > 8 for n in nums):
    print("first big:", big)

if not all((small := n) < 10 for n in nums):
    print("first not small:", small)

short = [1, 2]
print(any((last := n) > 8 for n in short), last)
```

```bash title="Terminal" verify="run"
python3 any_all.py
```

```text title="Expected output"
first big: 9
first not small: 12
False 2
```

`any()` stops at the first `True` (`9`), and `all()` stops at the first `False` (`12`). When `any()` never finds a match, the name holds the last item tested, as the final line shows, so check the result before trusting the name.

## Step 9: Watch the precedence gotcha
The walrus has the lowest precedence of all operators. Without parentheses, `x := len("ab") > 1` assigns the result of the whole comparison, so `x` is `True` instead of `2`. Parenthesise the assignment whenever it is only part of a larger expression: `(x := len("ab")) > 1`.

```python title="precedence.py" file
if x := len("ab") > 1:
    print(x)

if (x := len("ab")) > 1:
    print(x)

print(type(x := len("ab") > 1).__name__)
```

```bash title="Terminal" verify="run"
python3 precedence.py
```

```text title="Expected output"
True
2
bool
```

The first form is valid Python, so no error warns you: the code just stores the wrong value. Parenthesise unless the assignment is the whole condition, as in `if m := re.search(...)`.

## Step 10: Keep it readable
The operator is a convenience, not a goal. Packing several walruses into one line hurts readability. If a plain assignment on its own line reads better, use that. Both versions below give the same result; the second is easier to scan and debug.

```python title="readability.py" file
prices = [5, 12, 30, 7]

if (hi := max(prices)) > 20 and (lo := min(prices)) < 10 and (avg := sum(prices) / len(prices)) > 10:
    print(hi, lo, avg)

high = max(prices)
low = min(prices)
average = sum(prices) / len(prices)
if high > 20 and low < 10 and average > 10:
    print(high, low, average)
```

```bash title="Terminal" verify="run"
python3 readability.py
```

```text title="Expected output"
30 5 13.5
30 5 13.5
```

A good rule: use `:=` for one simple case per line, such as `while chunk := f.read(n)` or `if m := re.search(...)`, and switch back to normal assignment when the line needs a second look.

## How it works
`name := expression` evaluates the expression, binds the result to the name, and then yields that same value to the surrounding code. Because it is an expression, it can appear where a statement cannot: in a condition, a comprehension, or a function argument. A bare `x := 5` as a whole statement is rejected, and the target must be a plain name, not `d[k]`, `obj.attr`, or a tuple.

Its precedence is lower than comparison operators, so an unparenthesised walrus captures the whole comparison. A name bound inside a comprehension is bound in the enclosing scope, which is why it stays visible afterwards. Loops that test for an empty result work because empty strings, lists, and `None` are falsy.

## Common errors
### `SyntaxError: invalid syntax` on `x := 5`
An assignment expression cannot be a whole statement. Write `x = 5`, or use `(x := 5)` when you really need the value as part of an expression.

### `if x := len(s) > 1` leaves `True` in `x`
Without parentheses the walrus captures the whole comparison. Write `if (x := len(s)) > 1:` to keep the length.

### `SyntaxError` on `d[k] := v` or `(a, b) := (1, 2)`
The target of `:=` must be a plain name. Use a normal assignment for items, attributes, and tuple unpacking.

### A name from a comprehension is still defined afterwards
A name assigned with `:=` inside a comprehension is bound in the enclosing scope, so it can clash with another variable. Pick a distinct name, and remember that the loop variable itself does not leak.

### `any()` or `all()` leaves an unexpected value in the name
These functions stop early, and the name holds the last item tested. When `any()` returns `False`, the name is the final item, not a match. Check the result first.

## Recap
- `name := expression` assigns the value and returns it, so you can test and reuse a result without computing it twice.
- It must be parenthesised unless it is the whole condition, and its target must be a plain name, never `d[k]`, `obj.attr`, or a tuple.
- Use it for `while chunk := f.read(n)`, `if m := re.search(...)`, and filters, and switch to a plain assignment when the line becomes hard to read.

## Final practice: Log Line Scanner
The cheat sheet has no single example program, so this one combines its ideas. Create `log_scanner.py`; it reads simulated log lines in a `while` loop, matches users with a regex, filters names in a comprehension, checks the batch with `any()`, and reads a report in chunks.

```python title="log_scanner.py" file
import io
import re

# Simulated log input: the empty line marks the end
log = iter([
    "INFO 12:01 user=ann id=42",
    "WARN 12:03 disk=91%",
    "ERROR 12:07 user=bob id=17",
    "",
    "INFO 12:09 ignored",
])
pattern = re.compile(r"user=(\w+) id=(\d+)")

# 1. while loop with := (no repeated next() call)
users = []
while (line := next(log)) != "":
    # 2. regex match then use it
    if m := pattern.search(line):
        users.append((m.group(1), int(m.group(2))))
    # 3. compute once, test, reuse
    elif (n := len(line)) > 15:
        print(f"unmatched line ({n} chars): {line}")

print("users:", users)

# 4. filter and keep the computed value
long_names = [(name, size) for name, _ in users if (size := len(name)) > 2]
print("long names:", long_names)

# 5. capture the item that satisfied any()
if any((found := name).startswith("b") for name, _ in users):
    print("first name starting with b:", found)

# chunk reading
report = io.StringIO("ann:42;bob:17;")
while chunk := report.read(8):
    print("chunk:", chunk)
```

```bash title="Terminal" verify="run"
python3 log_scanner.py
```

```text title="Expected output"
unmatched line (19 chars): WARN 12:03 disk=91%
users: [('ann', 42), ('bob', 17)]
long names: [('ann', 3), ('bob', 3)]
first name starting with b: bob
chunk: ann:42;b
chunk: ob:17;
```

- The `while` loop stops at the empty string, so the last log line is never read.
- `m` and `n` are bound inside the `if` and `elif` conditions and used right away in the bodies.
- `size` and `found` stay defined after the comprehension and the `any()` call because walrus names belong to the enclosing scope.
- The chunk loop needs no `!= ""` test because an empty string is falsy.
