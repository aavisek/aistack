## Why this matters
TypeScript is JavaScript with a way to describe the kind of value a variable should hold. For example, a person's name is text and their age is a number. TypeScript can warn you when you mix those up, before you run your program.

You do not need to know functions, arrays, loops, or web servers to begin this lesson.

## What you will build
Start with four tiny programs: print a greeting, store your name, add two numbers, and display a true/false value. Each program introduces one idea.

**First session:** finish Steps 1–6. Pause there and repeat the examples with your own values.

**Second session:** Steps 7–11 introduce the remaining types and the checks required by the course specification. You do not need to memorize those on your first reading.

## Step 3: Store your name with string
A variable is a name for a stored value. `let` creates a variable you can change. `string` means text. The colon introduces the type; the equals sign gives the variable its value.

Read the first line as: "Create a variable called learnerName, containing text, with the value Ada."

console.log(learnerName);

## Step 4: Add two numbers
`number` stores numbers, including decimals. Numbers do not need quotation marks. The `+` operator adds the two values below.

`const` creates a variable you will not reassign. We use it for values that stay the same in this example.

```ts title="src/add.ts" file
const firstNumber: number = 5;
const secondNumber: number = 3;
const total: number = firstNumber + secondNumber;

console.log(total);
```

```bash title="Terminal" verify="manual" manual review required 2026-10-18 Linux
npm run build
node dist/add.js
```

```text title="Expected output"
8
```

> **Checkpoint:** change the inputs to 10 and 2. Predict the result before running. `"5"` is text; `5` is a number.

## Step 7: Recognize the other primitive types
A primitive is a basic kind of value. You have used the three most common ones. The remaining four are shown here for recognition, not memorization.

- `null`: an intentionally empty value.
- `undefined`: a value that has not been provided.
- `bigint`: an integer type for very large whole numbers; the `n` suffix marks it.
- `symbol`: a unique identifier created with `Symbol(...)`.

```ts title="src/more-types.ts" file
const emptyValue: null = null;
const missingValue: undefined = undefined;
const hugeCount: bigint = 9007199254740993n;
const uniqueKey: symbol = Symbol("learner");

console.log(typeof emptyValue);
console.log(typeof missingValue);
console.log(typeof hugeCount);
console.log(typeof uniqueKey);
```

```bash title="Terminal" verify="manual" manual review required 2026-10-18 Linux
npm run build
node dist/more-types.js
```

```text title="Expected output"
object
undefined
bigint
symbol
```

`typeof` asks JavaScript for a value's runtime type name. `typeof null` returns `"object"` because of a historical JavaScript quirk, even though null is a primitive.

## Step 8: Make one small reusable function
A function is a named set of instructions you can call again. This one takes two inputs, called parameters, and returns text.

`name: string` means the first input is text. `value: unknown` lets us inspect an input without assuming its type. The `: string` after the parentheses says the result is text. `return` gives that result to the caller.

```ts title="src/describe.ts" file
export function describe(name: string, value: unknown): string {
  return name + ": " + typeof value;
}
```

`export` lets another file use this function. You do not need arrays, loops, or union types to write or call it.

## Step 9: Call the function with each type
`import` brings the function into this file. Each call gives it a label and a value; `console.log` displays the returned text.

The import ends in `.js` because that is the file Node will run after compilation. TypeScript finds the matching `.ts` source while checking.

```ts title="src/describe-demo.ts" file
import { describe } from "./describe.js";

console.log(describe("name", "Ada"));
console.log(describe("age", 20));
console.log(describe("ready", true));
console.log(describe("empty", null));
console.log(describe("missing", undefined));
console.log(describe("large", 12n));
console.log(describe("key", Symbol("key")));
```

```bash title="Terminal" verify="manual" manual review required 2026-10-18 Linux
npm run build
node dist/describe-demo.js
```

```text title="Expected output"

age: number
ready: boolean
empty: object
missing: undefined
large: bigint
key: symbol
```

## Step 10: Keep two deliberate errors as compiler checks
The course specification asks us to keep examples of wrong assignments. Put them in a separate file so they do not distract from the small programs.

`@ts-expect-error` tells TypeScript that the following line must have an error. This is for testing type rules, not a way to fix real mistakes. `strict: true` includes the rule that null cannot be assigned to an ordinary string.

```ts title="src/type-checks.ts" file
// @ts-expect-error Text cannot be assigned to a number.
const wrongNumber: number = "x";

// @ts-expect-error A string cannot hold null under strictNullChecks.
const wrongString: string = null;
```

```bash title="Terminal" verify="manual" manual review required 2026-10-18 Linux
npm run check
```

```text title="Expected output"
The check finishes without type errors because both expected errors are accounted for.
```

Only compile this file; do not run it. Removing either comment makes the corresponding error visible. Restore both comments before moving on.

## Step 11: Check the helper automatically
A test compares an actual result with an expected result. Here `assert.equal` checks each returned string. The test is JavaScript so you can focus on the comparisons rather than more TypeScript syntax.

Save it as `test/describe.test.js`. The imports load Node's test tools and the compiled helper. `() => { ... }` groups the checks into one test; later lessons explain this function syntax in detail.

```js title="test/describe.test.js" file
import test from "node:test";
import assert from "node:assert/strict";
import { describe } from "../dist/describe.js";

test("describe handles all seven primitive types", () => {
  assert.equal(describe("name", "Ada"), "name: string");
  assert.equal(describe("age", 20), "age: number");
  assert.equal(describe("ready", true), "ready: boolean");
  assert.equal(describe("empty", null), "empty: object");
  assert.equal(describe("missing", undefined), "missing: undefined");
  assert.equal(describe("large", 12n), "large: bigint");
  assert.equal(describe("key", Symbol("key")), "key: symbol");
});
```

npm test
```

pass 1
fail 0
```

## How it works
The learning cycle is **write → check/build → run → inspect the output**.

| Idea | Meaning | Example |
| --- | --- | --- |
| Variable | A name for a stored value | `let age: number = 20;` |
| Type annotation | The kind of value allowed | `: number` |
| String | Text inside quotation marks | `"Ada"` |
| Number | A numeric value | `20` |
| Boolean | A true/false value | `true` |
| Compiler | Checks types and produces JavaScript | `npm run build` |

TypeScript checks your source before execution. Node runs the generated JavaScript. `npm run check` checks only; it does not update the generated files.

## Common errors
### The terminal says node or npm is not recognized
Install Node.js, then close and reopen the terminal so it can find the installed commands.
### Type 'string' is not assignable to type 'number'
Check quotation marks. Use `5` for a number and `"5"` for text. Restore the deliberate mistake from Step 6 before continuing.
### My output did not change
Save the `.ts` file and run `npm run build` again before running its `.js` file.
### Cannot find module dist/hello.js
Run the commands from the project folder, create `src/hello.ts`, and build before running it.
### An unused @ts-expect-error directive appears
The line below it no longer has the intended type error. In Step 10, restore the deliberate error; in real code, remove an unnecessary directive.
