## Why this matters
Relational databases keep related facts in separate tables. Joins reconnect those facts, while grouping and subqueries answer questions that span many records.

## Step 1: Add a relationship table
An enrollment connects one student to one course. A composite primary key prevents the same student/course pair from being added twice; foreign keys prevent dangling references.

```sql title="schema.sql" file
DROP TABLE IF EXISTS enrollments;
CREATE TABLE enrollments (
  student_id integer NOT NULL REFERENCES students(id),
  course_id integer NOT NULL REFERENCES courses(id),
  grade numeric(5, 2) NOT NULL CHECK (grade BETWEEN 0 AND 100),
  enrolled_on date NOT NULL DEFAULT CURRENT_DATE,
  PRIMARY KEY (student_id, course_id)
);

INSERT INTO enrollments (student_id, course_id, grade) VALUES
  (1, 1, 90), (2, 1, 80), (3, 1, 70), (4, 1, 100),
  (5, 2, 88), (6, 2, 92), (7, 2, 84),
  (8, 3, 95);
```

## Step 2: Compare join results
An inner join keeps matches only. A left join preserves all students; a right join preserves all courses; a full join preserves both sides, filling unmatched columns with NULL.

Append each SQL block in Steps 2–6 to `queries.sql` in order.

```sql title="Join examples - append to queries.sql"
-- INNER: only enrollment pairs. Expected: 8 rows.
SELECT s.id, c.id AS course_id
FROM students AS s
INNER JOIN enrollments AS e ON e.student_id = s.id
INNER JOIN courses AS c ON c.id = e.course_id;

-- LEFT: every student, including 12 with no enrollment. Expected: 20 rows.
SELECT s.id, e.course_id
FROM students AS s
LEFT JOIN enrollments AS e ON e.student_id = s.id;

-- RIGHT: every course, including five courses without enrollments. Expected: 13 rows.
SELECT c.id, e.student_id
FROM enrollments AS e
RIGHT JOIN courses AS c ON c.id = e.course_id;

-- FULL: every student and every course, including unmatched rows. Expected: 25 rows.
SELECT s.id, c.id AS course_id
FROM students AS s
FULL JOIN enrollments AS e ON e.student_id = s.id
FULL JOIN courses AS c ON c.id = e.course_id;

-- Which students have no enrollment? Expected: 12 rows.
SELECT s.id, s.name
FROM students AS s
LEFT JOIN enrollments AS e ON e.student_id = s.id
WHERE e.student_id IS NULL;
```

## Step 3: Group and summarize
`GROUP BY` creates one group per course. `HAVING` filters groups after aggregation; `WHERE` filters individual rows before aggregation.

```sql title="Aggregate queries - append to queries.sql"
-- What is each enrolled course's average grade? Expected: course 1=85, 2=88, 3=95.
SELECT course_id, ROUND(AVG(grade), 2) AS average_grade
FROM enrollments
GROUP BY course_id
ORDER BY course_id;

-- Which courses have more than three students? Expected: course 1 with 4.
SELECT course_id, COUNT(*) AS student_count
FROM enrollments
GROUP BY course_id
HAVING COUNT(*) > 3;

-- Which are the top three enrolled students by average grade? Expected IDs: 4, 8, 6.
SELECT student_id, ROUND(AVG(grade), 2) AS average_grade
FROM enrollments
GROUP BY student_id
ORDER BY average_grade DESC, student_id
LIMIT 3;
```

## Step 4: Use subqueries, EXISTS, and a CTE
Subqueries can filter rows, act as a temporary table in `FROM`, or provide a selected value. `EXISTS` checks whether a related row is present; a CTE names a query for the next statement.

```sql title="Nested queries - append to queries.sql"
-- WHERE: students with a grade above the overall mean. Expected: 5 rows.
SELECT DISTINCT student_id FROM enrollments
WHERE grade > (SELECT AVG(grade) FROM enrollments);

-- FROM: average grades as a derived table. Expected: 3 course rows.
SELECT course_id, average_grade
FROM (
  SELECT course_id, AVG(grade) AS average_grade
  FROM enrollments
  GROUP BY course_id
) AS course_averages
ORDER BY course_id;

-- SELECT: show each course and its enrollment count. Expected: 8 rows.
SELECT c.id, c.title,
       (SELECT COUNT(*) FROM enrollments e WHERE e.course_id = c.id) AS students
FROM courses AS c
ORDER BY c.id;

-- EXISTS and IN find enrolled students. Both should return the same 8 IDs.
SELECT s.id FROM students AS s
WHERE EXISTS (SELECT 1 FROM enrollments e WHERE e.student_id = s.id);
SELECT id FROM students
WHERE id IN (SELECT student_id FROM enrollments);

-- CTE: readable average-grade query. Expected: course 1 has average 85.
WITH course_averages AS (
  SELECT course_id, AVG(grade) AS average_grade
  FROM enrollments GROUP BY course_id
)
SELECT course_id, average_grade FROM course_averages ORDER BY course_id;
```

## Step 5: Create a view and inspect an index
A view stores a query definition, not a second copy of the rows. An index can help a lookup, but the planner may still choose a sequential scan for a tiny table.

```sql title="View and index - append to queries.sql"
CREATE OR REPLACE VIEW course_grade_summary AS
SELECT c.id AS course_id, c.title, COUNT(e.student_id) AS student_count,
       ROUND(AVG(e.grade), 2) AS average_grade
FROM courses AS c
LEFT JOIN enrollments AS e ON e.course_id = c.id
GROUP BY c.id, c.title;

CREATE INDEX IF NOT EXISTS enrollments_course_id_idx ON enrollments(course_id);

-- Expected: 8 course rows, including courses with zero enrollments.
SELECT * FROM course_grade_summary ORDER BY course_id;

-- Inspect the planner's chosen strategy; do not assume an index scan on tiny data.
EXPLAIN SELECT * FROM enrollments WHERE course_id = 1;
```

```text title="Expected output"
course_grade_summary returns 8 rows; course 1 has 4 students and average 85.00.
EXPLAIN returns a query plan; its scan type depends on table size and planner statistics.
```

## Step 6: Confirm foreign keys reject missing records
Use a savepoint so the expected invalid insert does not leave the session in an aborted transaction.

```sql title="Foreign key check - append to queries.sql"
BEGIN;
SAVEPOINT before_bad_enrollment;
INSERT INTO enrollments (student_id, course_id, grade) VALUES (9999, 1, 80);
ROLLBACK TO SAVEPOINT before_bad_enrollment;
ROLLBACK;
```

```text title="Expected output"
ERROR: insert or update on table "enrollments" violates foreign key constraint
The session can continue after ROLLBACK.
```

## How it works
Join predicates connect matching keys. Outer joins preserve rows on one or both sides even when no match exists. Aggregates summarize groups, and a foreign key makes the database enforce valid relationships regardless of which application sends the insert.

## Common errors
### Join rows multiply unexpectedly
Check whether either side has multiple matching rows and verify the join keys.
### A RIGHT JOIN looks confusing
Read it as preserving every row from the table on the right side of the keyword.
### EXPLAIN does not show the new index
Small tables often make a sequential scan cheaper; an index is not a promise of index usage.

## Recap
- Join related tables by keys and choose join types based on which unmatched rows to preserve.
- Use GROUP BY and HAVING for summaries, with subqueries and CTEs for nested questions.
- Constraints protect relationships; views and indexes provide reusable query structures.
