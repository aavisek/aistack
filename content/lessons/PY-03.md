## Why this matters
Names, messages, file contents, and API responses all involve text. Indexing and slicing help you select parts of a string; encoding lets you exchange that text as bytes without corrupting accented characters or symbols.

## What you will build
Small, standalone Python programs that select and rebuild strings, search text, convert between Unicode text and bytes, and save a UTF-8 file.

This lesson follows the Python Strings: Index, Slice & Encoding cheat sheet, which you can open at the end of the lesson.

## Before you start
Use Python 3.10 or newer and create each named file in a practice folder. Every example is independent. Run each file with `python3 filename.py` on macOS/Linux or `py -3 filename.py` in Windows PowerShell.

The examples use escapes such as `\u00e9` for accented characters so you can copy the code even with an English-only keyboard. Python interprets these escapes as Unicode characters.

## Step 1: Read characters by index
A `str` is an immutable sequence of Unicode code points. Indexes start at zero; negative indexes count from the end. For `"PYTHON"`, valid indexes are `0` through `5` or `-6` through `-1`.

```python title="string_indexes.py" file
text = "PYTHON"

print(len(text))
print(text[0], text[5])
print(text[-1], text[-6])
print(type(text[0]).__name__)
```

```bash title="Terminal" verify="run"
python3 string_indexes.py
```

```text title="Expected output"

P N
N P
str
```

Indexing returns a one-character string. `text[len(text)]` raises `IndexError`, and `text[-0]` means `text[0]`, not the last character.

## Step 2: Find text and visit its positions
Use `in` for membership, `find` for a position or `-1`, and `index` when a missing substring should raise `ValueError`. `rfind` searches from the right; `rindex` is its exception-raising counterpart.

```python title="string_search.py" file
text = "banana"

print(text.find("an"), text.rfind("an"))
print(text.find("a", 2), text.index("an"))
print(text.find("x"), "x" in text)
print(text.count("an"), text.count("ana"))
print(text.startswith(("ba", "pa")), text.endswith("na"))

for index, character in enumerate("cat"):
    print(index, character)
```

```bash title="Terminal" verify="run"
python3 string_search.py
```

```text title="Expected output"

True True
0 c
1 a
2 t
```

Counts are non-overlapping: `"banana"` contains only one non-overlapping `"ana"`. Never write `if text.find("x"):`: a match at zero is falsy, while `-1` is truthy.

## Step 3: Slice with an exclusive stop
`text[start:stop:step]` selects code points starting at `start`, excluding `stop`. With a positive step, omitted bounds mean the beginning and the end. Bounds beyond the string are clipped.

```python title="string_slices.py" file
text = "PYTHON"

print(text[2:5])
print(text[:3], text[3:])
print(text[-3:], text[:-1], text[1:-1])
print(text[::2], text[1::2])
print(text[2:100])
print(repr(text[5:2]))
print(repr(""[:1]))
print(text[:3] + text[3:] == text)
```

python3 string_slices.py
```

THON
''
''
True
```

`repr` makes empty strings visible. Unlike `text[0]`, `text[:1]` is safe for an empty string. A zero step still raises `ValueError`; slicing is not error-free for every argument.

## Step 4: Reverse and reuse a slice
A negative step walks left. The stop remains exclusive. With a negative step, an omitted stop means before the first character; an explicit `-1` means the last character, so they are not interchangeable.

```python title="reverse_slices.py" file
text = "PYTHON"
middle = slice(2, 5)

print(text[::-1])
print(text[4:1:-1])
print(repr(text[4:-1:-1]))
print(text[middle], middle.indices(len(text)))
print("level" == "level"[::-1])
```

Reversing code points is useful for simple examples, but it does not reliably reverse user-perceived characters containing combining marks or multi-code-point emoji.

## Step 5: Build a new string instead of changing one
Strings do not support item assignment. Rebuild them with slices, `replace`, or `join`. The original string remains unchanged.

```python title="rebuild_strings.py" file
text = "PYTHON"
message = "Hello, World"
half = len(message) // 2

print("J" + text[1:])
print(text.replace("P", "J", 1))
print(text)
print(message[:5] + "!" + message[5:])
print(repr(message[:half]), repr(message[half:]))
print(message[2:] + message[:2])
print([message[i:i + 4] for i in range(0, len(message), 4)])
print(message.removeprefix("Hello, "))
print(repr(message.removesuffix("World")))
print(" ".join(["Learn", "Python", "strings"]))
```

`removeprefix` and `removesuffix` remove a matching whole prefix or suffix, not an arbitrary set of characters. Prefer `join` when assembling many string pieces.

## Step 6: Encode text and decode bytes
`str` holds text; `bytes` holds integer values from 0 to 255. Encode to send or store text; decode to read it. Both directions must use the encoding that actually produced the bytes.

```python title="encode_text.py" file
text = "caf\u00e9 \u20ac"
data = text.encode("utf-8")

print(text)
print(data)
print(len(text), len(data))
print(data.decode("utf-8") == text)
print(ord("A"), ord("\u20ac"))
print(chr(8364))
print([len(character.encode("utf-8"))
       for character in ("A", "\u00e9", "\u20ac", "\U0001f600")])
```

`len(str)` counts code points, not bytes or displayed characters. UTF-8 uses one to four bytes per code point. `encode()` and `decode()` default to UTF-8; naming it explicitly makes the contract clear.

## Step 7: Handle encoding mismatches explicitly
Strict error handling is the default. Use a known legacy encoding only when the source specifies it; successfully decoding arbitrary bytes as Latin-1 does not prove that Latin-1 was intended.

```python title="encoding_errors.py" file
legacy_data = b"caf\xe9"

try:
    legacy_data.decode("utf-8")
except UnicodeDecodeError:
    print("Cannot decode Latin-1 bytes as UTF-8.")

print(legacy_data.decode("latin-1"))

try:
    "\u20ac".encode("latin-1")
except UnicodeEncodeError:
    print("Latin-1 cannot encode the euro sign.")

print("caf\u00e9".encode("ascii", errors="backslashreplace"))
```

```bash title="Terminal" verify="run"
python3 encoding_errors.py
```

ASCII covers 128 code points; Latin-1 covers 256. CP1252 is a different legacy Windows encoding. UTF-16 uses two or four bytes per code point, with a BOM for `utf-16`; `utf-16-le` and `utf-16-be` select byte order explicitly.

`errors="ignore"` silently drops data. `replace` also loses information. Prefer correcting the encoding; use lossy handlers only when data loss is explicitly acceptable.

## Step 8: Keep byte indexing separate from text indexing
Indexing bytes returns an integer, while slicing bytes returns bytes. A byte slice can split a UTF-8 character. Decode valid complete bytes before slicing text.

```python title="byte_indexes.py" file
data = "caf\u00e9".encode("utf-8")

print(data[0], data[:1])
print(data.hex())
print(bytes.fromhex("c3a9").decode("utf-8"))
print(data.decode("utf-8")[-1])

try:
    data[3:4].decode("utf-8")
except UnicodeDecodeError:
    print("The byte slice contains an incomplete UTF-8 character.")

editable = bytearray(data)
editable[0] = 67
print(editable.decode("utf-8"))
print(str(b"hi"), b"hi".decode("utf-8"))
print("a" == b"a")
```

## Step 9: Normalize Unicode before comparing text
Identical-looking text can have different code-point sequences. NFC normalization can combine a base character and accent; `casefold` supports caseless matching better than `lower`.

```python title="normalize_text.py" file
import unicodedata

composed = "\u00e9"
decomposed = "e\u0301"

print(composed == decomposed)
print(len(composed), len(decomposed))
print(unicodedata.normalize("NFC", decomposed) == composed)
print(unicodedata.name(composed))
print("Stra\u00dfe".casefold())
```

Normalization does not make all lookalikes equal or turn all emoji into single code points. User-perceived characters are called grapheme clusters; code-point indexing is not grapheme segmentation.

## Step 10: Read and write UTF-8 files
Text mode reads and writes strings with an encoding. Binary mode reads and writes bytes without decoding. Specify an encoding instead of relying on a version- or platform-dependent default.

```python title="text_files.py" file
from pathlib import Path

path = Path("string_example.txt")
text = "caf\u00e9"

with path.open("w", encoding="utf-8") as file:
    file.write(text)

with path.open("r", encoding="utf-8") as file:
    print(file.read() == text)

with path.open("rb") as file:
    print(file.read())

bom_data = b"\xef\xbb\xbfhello"
print(bom_data.decode("utf-8-sig"))
```

```bash title="Terminal" verify="run"
python3 text_files.py
```

```text title="Expected output"

hello
```

This creates or overwrites `string_example.txt` in the practice folder. `utf-8-sig` removes a leading UTF-8 BOM while decoding. Garbled text such as `cafÃ©` indicates a likely encoding mismatch; reread the original bytes with the correct encoding rather than guessing or discarding errors.

## Step 11: Check search bounds and predictable exceptions
Search methods accept optional start and exclusive end bounds. Returned positions refer to the original string, not to the start of the search window.

```python title="string_boundaries.py" file
text = "banana"
print(text.find("an", 2, 5), text.rindex("an"))
print(text.count("x"), text.endswith(("na", "ny")))
print(len(text[1:4]) == 4 - 1)
print(all(text[:n] + text[n:] == text for n in range(-10, 11)))

try:
    print(text[len(text)])
except IndexError:
    print("IndexError: index outside the string")

try:
    text[0] = "B"
except TypeError:
    print("TypeError: strings do not support item assignment")

for method in (text.index, text.rindex):
    try:
        method("x")
    except ValueError:
        print("ValueError: substring not found")

try:
    print(text[::0])
except ValueError:
    print("ValueError: slice step cannot be zero")
```

## Step 13: Compare common encodings and byte-order marks
Choose the encoding required by the data format, not whichever one avoids an exception.

| Encoding | Bytes per code point | Coverage and typical use |
| --- | --- | --- |
| UTF-8 | 1–4 | Unicode; ASCII-compatible; files, web, APIs |
| ASCII | 1 | U+0000–U+007F; restricted text |
| Latin-1 | 1 | U+0000–U+00FF; legacy Western text |
| CP1252 | 1 | Windows Western text; differs from Latin-1 |
| UTF-16 | 2 or 4, plus BOM | Unicode; some Windows/Java formats |
| UTF-32 | 4, plus BOM | Unicode; fixed-width, rarely used |

```python title="encoding_choices.py" file
import codecs

print("\u00e9".encode("latin-1"))
print("\u20ac".encode("cp1252"))
print("A".encode("utf-16-le"), "A".encode("utf-16-be"))
print("A".encode("utf-16").startswith(
    (codecs.BOM_UTF16_LE, codecs.BOM_UTF16_BE)
))
print(len("A".encode("utf-16")), len("\U0001f600".encode("utf-16")))
print(len("A".encode("utf-32")))
print("A".encode("utf-32-le").hex())
print([len(chr(point).encode("utf-8"))
       for point in (0x007F, 0x07FF, 0xFFFF, 0x10FFFF)])
```

`utf-16` and `utf-32` emit a byte-order mark (BOM); explicit `-le`/`-be` variants omit it. UTF-8 widths change after U+007F, U+07FF, and U+FFFF. Surrogate code points U+D800–U+DFFF are not valid Unicode scalar values and cannot be strictly UTF-8 encoded.

## Step 14: Explore every error handler in the sheet
These examples intentionally show loss or escaping; they are not recommended defaults for application data.

| Handler | Direction | Effect |
| --- | --- | --- |
| `strict` | Both | Raise an encoding or decoding error |
| `ignore` | Both | Drop unconvertible content |
| `replace` | Both | Encode as `?`; decode as U+FFFD |
| `backslashreplace` | Both | Insert Python-style escapes |
| `xmlcharrefreplace` | Encode | Insert numeric XML/HTML references |
| `namereplace` | Encode | Insert Unicode-name escapes |
| `surrogateescape` | Both | Preserve undecodable high bytes for round trips |

```python title="encoding_handlers.py" file
text = "caf\u00e9"
for handler in ("ignore", "replace", "backslashreplace",
                "xmlcharrefreplace", "namereplace"):
    print(handler, text.encode("ascii", errors=handler))

bad = b"caf\xe9"
print("decode replace", ascii(bad.decode("utf-8", errors="replace")))
print("decode ignore", bad.decode("utf-8", errors="ignore"))
print("decode backslashreplace",
      ascii(bad.decode("utf-8", errors="backslashreplace")))
preserved = bad.decode("utf-8", errors="surrogateescape")
print("surrogateescape", ascii(preserved))
print(preserved.encode("utf-8", errors="surrogateescape") == bad)
```

## Step 15: Diagnose garbled text without guessing
Mojibake is text decoded using the wrong encoding. Undoing it is safe only when the exact mistaken conversion is known and no content was lost.

print(ascii(windows_quotes.decode("cp1252")))

## Step 17: Distinguish code points from visible characters
An accented letter can use two code points; a family emoji can use several joined code points. NFC helps with equivalent accent sequences but cannot turn every grapheme cluster into a single code point.

```python title="visible_characters.py" file
import unicodedata

accented = "e\u0301"
family = "\U0001f468\u200d\U0001f469\u200d\U0001f467"
normalized = unicodedata.normalize("NFC", accented)

print(len(accented), len(normalized))
print(ascii(accented[::-1]))
print(ascii(normalized[::-1]))
print(len(family), len(unicodedata.normalize("NFC", family)))
print("Stra\u00dfe".lower(), "Stra\u00dfe".casefold())
print(unicodedata.normalize("NFD", normalized) == accented)
```

## How it works
An index selects one code point; a slice selects code points according to its start, exclusive stop, and nonzero step. Slicing and rebuilding do not mutate the original string.

Encoding maps Unicode code points to bytes. UTF-8 is variable-width, so text length and byte length can differ. Decode at input boundaries, work with strings, then encode at output boundaries. Normalization addresses equivalent Unicode representations, not incorrect decoding.

## Common errors
### Reading past the final index
`"PYTHON"[6]` raises `IndexError`. Use `[-1]` for the final character and account for empty strings. Slice bounds are clipped, but a zero slice step raises `ValueError`.

### Assigning to a string character
`text[0] = "J"` raises `TypeError`. Build a replacement string such as `"J" + text[1:]`.

### Treating a search result as a Boolean
`find` returns zero for a match at the start and `-1` for no match. Use `"x" in text` or `text.find("x") != -1`.

### Confusing bytes with text
`str(b"hi")` is not a decode operation. Use `b"hi".decode("utf-8")`. Decode complete byte sequences before selecting characters.

### Hiding an encoding error
Do not use `errors="ignore"` to make a failed read appear successful. Confirm the original encoding and reread the source bytes. Replacement characters may mean information has already been lost.

## Recap
- Strings are immutable; indexes select code points and slices use an exclusive stop and a nonzero step.
- Encode strings to bytes and decode bytes to strings with the correct encoding; UTF-8 byte length can differ from string length.
- Normalize equivalent Unicode text when appropriate, specify file encodings, and surface encoding failures instead of silently losing data.

- `not` flips a Boolean, so `not is_sunny` is `False` and `not have_umbrella` is `True`.
- `and` needs both conditions to be true: `is_sunny and not have_umbrella` is `True`.
- `or` needs at least one condition to be true: `is_sunny or have_umbrella` is `True`.

The third message follows the cheat sheet's wording: it uses `not have_umbrella` for "don't need an umbrella." Not having an umbrella does not actually establish whether one is needed; these flags are only a Boolean exercise, not a weather recommendation.
