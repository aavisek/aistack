## Why this matters
Infinite Generators makes Python programs concise while keeping data flow explicit and testable. The examples use small inputs so you can inspect each result.

## What you will build

## Before you start

## Step 1: Define an intentionally infinite generator

This example focuses on how to define an intentionally infinite generator.

```python title="infinite_generators_1.py" file
from itertools import islice, count

print(list(islice(count(1), 5)))
```

```bash title="Terminal" verify="run"
python3 infinite_generators_1.py
```

```text title="Expected output"
[1, 2, 3, 4, 5]
```
## Step 2: Take a finite prefix safely

This example focuses on how to take a finite prefix safely.

```python title="infinite_generators_2.py" file
values = ["A", "a", "B", "b"]
result = sorted({value.lower() for value in values})
print(result)
```

```bash title="Terminal" verify="run"
python3 infinite_generators_2.py
```

```text title="Expected output"

```
## Step 3: Avoid eagerly materializing infinite data

This example focuses on how to avoid eagerly materializing infinite data.

```python title="infinite_generators_3.py" file
names = ["Ada", "Guido", "Linus"]
result = {name: len(name) for name in names if len(name) >= 4}
print(result)
```

```bash title="Terminal" verify="run"
python3 infinite_generators_3.py
```

```text title="Expected output"
{'Guido': 5, 'Linus': 5}
```
## Step 4: Print the requested prefix

This example focuses on how to print the requested prefix.

```python title="infinite_generators_4.py" file
def make_values():
    for number in range(1, 4):
        yield number * 10

values = make_values()
print(list(values))
```

```bash title="Terminal" verify="run"
python3 infinite_generators_4.py
```

```text title="Expected output"
[10, 20, 30]
```
## How it works
The syntax `yield from itertools.count(1)` describes the central idea, but the surrounding function or loop determines when work happens. Keep transformations readable, consume iterators deliberately, and make wrapper behavior explicit.

## Common errors
### Building the wrong collection
Choose the collection type from the required output: lists preserve order, sets enforce uniqueness, dictionaries name values, and generators defer work.

### Consuming a generator twice
A generator is an iterator and is normally exhausted after one pass. Create a new generator or materialize intentionally when repeated access is required.

### Hiding behavior in a wrapper
Use `functools.wraps`, preserve arguments, and raise a clear exception when a decorator rejects a call.
