## Why this matters
Argument rules let one function accept required values, optional values, many positional values, and many keyword values without losing clarity.

A runnable set of examples about handling arguments in functions.

## Step 3: Collect keyword arguments

```python title="py_39_3.py" file
def settings(**options):
    return sorted(options.items())

print(settings(theme="dark", compact=True))
```

```bash title="Terminal" verify="run"
python3 py_39_3.py
```

```text title="Expected output"

```

## Step 4: Validate a flexible call

```python title="py_39_4.py" file
def label(name, *tags, **meta):
    return name, tags, meta

print(label("task", "python", done=False))
```

```bash title="Terminal" verify="run"
python3 py_39_4.py
```

```text title="Expected output"
('task', ('python',), {'done': False})
```

## How it works
Required parameters come before optional ones.
`*args` is a tuple and `**kwargs` is a dictionary.
Keyword-only parameters can make flexible APIs safer.

## Common errors
### Repeating code instead of extracting a function
Give a helper one responsibility and return its result.

### Confusing a return value with printed output
Use `return` for callers and `print` only at the boundary.

### Hiding state or dependencies
Prefer explicit parameters and imports over surprising global behavior.
