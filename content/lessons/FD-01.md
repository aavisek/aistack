## Why this matters
Git records how your files change so you can inspect or restore earlier work. npm manages the JavaScript packages your project uses. Think of Git as a rewindable project diary and npm as a carefully labeled toolbox.

## What you will build
You will create `fd-01-git-npm`, run a Node.js program, record at least five commits, merge a feature branch, resolve a deliberate conflict, keep `.env` out of Git, and publish a copy to GitHub.

```text title="Folder structure"
fd-01-git-npm/
├─ .git/                  Git history; Git manages this folder
├─ .env                   local secret; never commit
├─ .env.example           safe settings template
├─ .gitignore
├─ index.js
├─ package.json
└─ package-lock.json
```

## Before you start
Install Git from <https://git-scm.com/downloads>, Node.js 20 LTS from <https://nodejs.org>, and create an account at <https://github.com/signup>. A terminal is a text window where you run commands. In VS Code choose **Terminal → New Terminal**; on Windows choose **PowerShell**, and on macOS/Linux choose **bash** or **zsh**.

```bash title="Terminal" verify="manual" manual review required 2026-10-18 Linux
git --version
node --version
npm --version
```

```text title="Expected output"
git version 2.43.0
v20.20.2
11.19.0
```

> **Your output will differ:** these are the versions available in the verification environment. Use Node 20 or newer.

## Step 1: Start a repository
Create one project folder, move into it, then ask Git to begin keeping history. A repository is a folder whose changes Git tracks.

```bash tab="macOS / Linux" title="Terminal" verify="run"
mkdir fd-01-git-npm
cd fd-01-git-npm
git init -b main
```

```powershell tab="Windows PowerShell" title="Terminal" verify="manual" manual review required 2026-10-18 Windows
New-Item -ItemType Directory fd-01-git-npm
Set-Location fd-01-git-npm
git init -b main
```

```text title="Expected output"
Initialized empty Git repository
```

> **Why it works:** `git init` creates the hidden `.git` history folder. The `main` branch is the default name for the first line of work.

> **Checkpoint:** enter `git status`. Git should say `On branch main` and `No commits yet`.

## Step 2: Set your commit name
Git stores an author name and email with each saved snapshot, called a commit. Configure these settings only for this project so the lesson does not change global computer settings.

```bash title="Terminal" verify="run"
git config user.name "Your Name"
git config user.email "you@example.com"
git config --list --local
```

```text title="Expected output"
user.name=Your Name
user.email=you@example.com
```

> **Checkpoint:** replace the sample name and email with your own before making a commit.

## Step 3: Create the npm project
`package.json` is the project's description: it lists the name, commands, and dependencies. `npm init -y` writes one using default answers.

```bash title="Terminal" verify="run"
npm init -y
```

```text title="Expected output"
Wrote to .../fd-01-git-npm/package.json
```

Now create the complete program file. A file is a saved set of text; in VS Code choose **File → New Text File**, paste this content, and save it as `index.js` inside the project folder.

You can also open or create the file from the terminal with `code index.js`, then paste and save the same content.

```js title="index.js" file
console.log("Hello from fd-01-git-npm!");
```

Add the `start` command and run it.

```bash title="Terminal" verify="run"
npm pkg set scripts.start="node index.js"
npm start
```

```text title="Expected output"
> fd-01-git-npm@1.0.0 start
> node index.js

Hello from fd-01-git-npm!
```

> **Checkpoint:** you see `Hello from fd-01-git-npm!`.

## Step 4: Add ignore rules and safe settings
Git reads `.gitignore` to decide which files not to add. Never commit `.env`: it is where a real project would keep private values.

Open the file from the terminal with `code .gitignore`, then paste the complete rules below.

```text title=".gitignore" file
node_modules/
.env
dist/
```

Create the safe template and local settings. `NOTES_FILE` here is only a sample setting, not a secret.

```text title=".env.example" file
NOTES_FILE=notes.json
```

```bash title="Terminal" verify="run"
git check-ignore -v .env
```

```text title="Expected output"
.gitignore:2:.env	.env
```

> **Checkpoint:** `git check-ignore` prints the `.gitignore` rule that excludes `.env`.

## Step 5: Understand package versions
Install one runtime dependency and one development dependency. A runtime dependency is needed by the app; a development dependency is used while building or testing it. The lock file records the exact package versions npm selected.

```bash title="Terminal" verify="manual" manual review required 2026-10-18 Linux
npm install dayjs
npm install --save-dev nodemon
```

```text title="Expected output"
added packages
```

Add the remaining project commands. `dev` restarts the program when files change; `test` and `build` are simple working placeholders until you add tests and a build step.

```bash title="Terminal" verify="run"
npm pkg set scripts.dev="nodemon index.js"
npm pkg set scripts.test="node --test"
npm pkg set scripts.build="node --check index.js"
npm run build
```

```text title="Expected output"
> fd-01-git-npm@1.0.0 build
> node --check index.js
```

## Step 6: Make your first two commits
The staging area is Git's waiting room: `git add` selects changes, and `git commit` saves a snapshot. Make a first snapshot, then change the program and make another.

```bash title="Terminal" verify="run"
git add .
git commit -m "chore: create npm project"
```

```text title="Expected output"
[main (root-commit) ...] chore: create npm project
```

For commit two, edit `index.js` in VS Code to this full content:

```js title="index.js" file
console.log("Hello from fd-01-git-npm!");
console.log("Git saved my first project.");
```

```bash title="Terminal" verify="run"
git add index.js
git commit -m "feat: add a second greeting"
```

```text title="Expected output"
[main ...] feat: add a second greeting
```

> **Checkpoint:** run `git log --oneline`. The newest commit appears first.

## Step 7: Create and merge a feature branch
A branch is a separate line of changes. Use one for a greeting feature, then merge it into `main`.

```bash title="Terminal" verify="run"
git switch -c feature/greeting
```

```text title="Expected output"
Switched to a new branch 'feature/greeting'
```

Edit `index.js` and save the complete file:

```js title="index.js" file
console.log("Hello from fd-01-git-npm!");
console.log("A feature branch keeps this change separate.");
```

```bash title="Terminal" verify="run"
git add index.js
git commit -m "feat: improve the greeting"
git switch main
git merge feature/greeting
```

```text title="Expected output"
Fast-forward
Switched to branch 'main'
```

> **Checkpoint:** `git branch --merged` lists `feature/greeting`.

## Step 8: Resolve a merge conflict
A merge conflict means two branches changed the same part of a file. Git pauses so you can choose the final content.

```bash title="Terminal" verify="run"
git switch -c feature/alternate
```

```text title="Expected output"
Switched to a new branch 'feature/alternate'
```

Change `index.js` on this branch to this complete file:

```js title="index.js" file
console.log("Hello from the alternate branch.");
console.log("Git saved my first project.");
```

```bash title="Terminal" verify="run"
git add index.js
git commit -m "feat: add alternate greeting"
git switch main
```

```text title="Expected output"
Switched to branch 'main'
```

On `main`, change the same first line to `console.log("Hello from main.");` and save this complete file:

```js title="index.js" file
console.log("Hello from main.");
console.log("Git saved my first project.");
```

```bash title="Terminal" verify="run" expect="failure"
git add index.js
git commit -m "feat: update main greeting"
git merge feature/alternate
```

```text title="Expected output"
CONFLICT (content): Merge conflict in index.js
Automatic merge failed; fix conflicts and then commit the result.
```

Open `index.js`. Delete the lines beginning `<<<<<<<`, `=======`, and `>>>>>>>`, and keep this full resolved file:

```js title="index.js" file
console.log("Hello from both branches.");
console.log("Git saved my first project.");
```

```bash title="Terminal" verify="run"
git add index.js
git commit -m "fix: resolve greeting conflict"
```

```text title="Expected output"
[main ...] fix: resolve greeting conflict
```

> **Checkpoint:** `git status` says the working tree is clean.

## Step 9: Add three meaningful commits
Meaningful commit messages tell a future reader what changed. Add small project files so the history has at least five commits.

```bash title="Terminal" verify="run"
npm pkg set description="A beginner Node.js project for learning Git and npm"
git add package.json
git commit -m "docs: describe the project"
git log --oneline
```

```text title="Expected output"
... docs: describe the project
... fix: resolve greeting conflict
... feat: update main greeting
... feat: add alternate greeting
... feat: improve the greeting
... feat: add a second greeting
... chore: create npm project
```

> **Checkpoint:** the history now contains at least five commits. The `...` prefixes stand for unique commit IDs.

## Step 10: Keep a real secret out of history
Create a local `.env` file, but do not add it to Git. Node.js 20 can load this file with `--env-file`.

```text title=".env" file
GREETING_NAME=Ada
```

Update the full `index.js` file so it reads the setting:

```js title="index.js" file
const name = process.env.GREETING_NAME ?? "friend";
console.log(`Hello, ${name}!`);
```

```bash title="Terminal" verify="run"
node --env-file=.env index.js
git check-ignore -v .env
test -z "$(git log --all -- .env --format=%H)" && echo "No commits contain .env"
git status --short
```

```text title="Expected output"
Hello, Ada!
.gitignore:2:.env	.env
No commits contain .env
 M index.js
```

Do not run `git add .env`. If a real secret is committed, deleting the file later does not remove it from old commits; revoke that secret.

## Step 11: Publish the repository
GitHub is a website for hosting Git repositories. Create an empty remote repository using GitHub's interface; a remote is another copy of your repository.

1. Open <https://github.com/new>.
2. Set the name to `fd-01-git-npm`.
3. Choose **Private** or **Public**.
4. Leave **Add a README**, **.gitignore**, and **license** unchecked so the remote starts empty.
5. Choose **Create repository**.

Connect and publish. Replace the URL with the HTTPS URL shown on the new repository page.

```bash title="Terminal" verify="manual" manual review required 2026-10-18 Linux
git remote add origin https://github.com/YOUR-USER/fd-01-git-npm.git
git push -u origin main
```

```text title="Expected output"
branch 'main' set up to track 'origin/main'.
```

> **Warning:** never put a password or token in the remote URL. When GitHub asks you to sign in, use the browser sign-in flow or a credential manager.

## Step 12: Prove a fresh clone works
A clone is a new local copy downloaded from a remote. Open a second terminal outside the original project folder.

```bash title="Terminal" verify="manual" manual review required 2026-10-18 Linux
git clone https://github.com/YOUR-USER/fd-01-git-npm.git fd-01-git-npm-copy
cd fd-01-git-npm-copy
npm install
npm start
```

```text title="Expected output"
Hello, friend!
```

> **Your output will differ:** if you create `.env` in the clone with `GREETING_NAME=Ada`, the output is `Hello, Ada!`. The secret file was intentionally not cloned.

## How it works
Git saves local snapshots; `git push` sends them to GitHub. npm uses `package.json` to understand project intent and `package-lock.json` to repeat the exact dependency selection.

```text title="The three areas of Git"
Working folder  --git add-->  Staging area  --git commit-->  Repository history
                                                              |
                                                         git push
                                                              v
                                                           GitHub
```

## Common errors
### `fatal: not a git repository (or any of the parent directories): .git`
The terminal is outside the project folder. Run `cd fd-01-git-npm`, then retry the Git command.

### `fatal: unable to auto-detect email address`
Git does not know the author identity for this repository. Repeat Step 2 with your real name and email.

### `error: failed to push some refs to 'https://github.com/...'`
The remote has a commit your local copy does not have. If you intentionally created a remote README, run `git pull --rebase origin main`, resolve any conflict, and push again.

### `'node' is not recognized as an internal or external command`
Node.js is missing or the terminal was open before installation. Install Node.js 20 LTS and open a new terminal.

## Recap
- Git records local snapshots; branches let you work separately and merge changes.
- npm describes dependencies and scripts in `package.json` and locks versions in `package-lock.json`.
