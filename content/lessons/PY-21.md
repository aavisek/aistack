## Why this matters
Almost every program repeats work: totalling prices, scanning lines of a file, retrying a task, or building a new list from an old one. Python gives you two loop statements, `for` and `while`, plus a family of helpers such as `range()`, `enumerate()`, `zip()`, and comprehensions. Choosing the right one makes code shorter and avoids the classic bugs: off-by-one errors, endless loops, and lists changed while you walk over them.

## What you will build
Small, standalone Python scripts that cover every part of the loops cheat sheet: `for` and `while`, `range()`, the helper functions, `break`, `continue`, `else` and `pass`, common patterns, loops over dictionaries, strings, and files, comprehensions, nested loops with `itertools`, the pitfalls checklist, and the walrus operator. You finish with the cheat sheet's common-patterns program.

## Before you start
Use Python 3.10 or newer and create each named file in a practice folder. Every example is independent and uses hardcoded data instead of typing at a prompt. Run each file with `python3 filename.py` on macOS/Linux or `py -3 filename.py` in Windows PowerShell.

This lesson builds on the earlier Python lessons in this track: loops use conditions and comparisons, and they walk over lists, tuples, dictionaries, sets, and strings. A short rule of thumb: use `for` when you have a collection or a known count, and `while` when you repeat until a condition changes.

## Step 1: for and while at a glance
A `for` loop takes each item of an iterable in turn. A `while` loop repeats as long as its condition is true, so something inside the body must change the condition. Both loops accept an optional `else` clause that runs only when the loop ends without `break`.

```python title="for_while.py" file
for item in ["tea", "milk", "jam"]:
    print("for:", item)

count = 3
while count > 0:
    print("while:", count)
    count -= 1

for n in [1, 2, 3]:
    print("checking", n)
else:
    print("for finished without break")

attempts = 0
while attempts < 2:
    attempts += 1
else:
    print("while finished, attempts =", attempts)
```

```bash title="Terminal" verify="run"
python3 for_while.py
```

```text title="Expected output"
for: tea
for: milk
for: jam
while: 3
while: 2
while: 1
checking 1
checking 2
checking 3
for finished without break
while finished, attempts = 2
```

The line `count -= 1` is the "update something" step from the cheat sheet. Without it the `while` condition never changes and the loop never ends.

## Step 2: range() cheats
`range()` produces numbers lazily. One argument is the stop, two arguments are start and stop, and three arguments add a step. The stop value is always excluded, a negative step counts down, and a range that cannot produce anything is simply empty. A step of `0` is an error.

```python title="range_cheats.py" file
print(list(range(5)))
print(list(range(2, 6)))
print(list(range(0, 10, 3)))
print(list(range(5, 0, -1)))
print(list(range(0)), list(range(3, 3)), list(range(5, 2)))

r = range(2, 6)
print(r, len(r), r[0], r[-1], 4 in r)

for i in range(3):
    print("loop", i)
print(sum(range(1, 6)))

try:
    range(0, 5, 0)
except ValueError as error:
    print("ValueError:", error)
```

```bash title="Terminal" verify="run"
python3 range_cheats.py
```

```text title="Expected output"
[0, 1, 2, 3, 4]
[2, 3, 4, 5]
[0, 3, 6, 9]
[5, 4, 3, 2, 1]
[] [] []
range(2, 6) 4 2 5 True
loop 0
loop 1
loop 2
15
ValueError: range() arg 3 must not be zero
```

`range` is not a list: it stores only start, stop, and step, so it can describe a huge sequence cheaply. Wrap it in `list()` when you want to see the numbers.

## Step 3: Pick the right tool for a for loop
The cheat sheet's "Pick the right tool" table maps each need to one loop form. `enumerate()` adds a position (start it at 1 with `start=1`), `zip()` walks sequences in parallel and stops at the shortest, `reversed()` walks backward without copying, and `.items()` gives key and value pairs.

```python title="pick_the_tool.py" file
items = ["pen", "ink", "pad"]
prices = [3, 5]

for x in items:
    print("item:", x)

for i, x in enumerate(items):
    print(i, x)

for i, x in enumerate(items, start=1):
    print(i, x)

for a, b in zip(items, prices):
    print(a, b)

for x in reversed(items):
    print("back:", x)

stock = {"pen": 3, "ink": 5}
for k, v in stock.items():
    print(k, "->", v)
```

```bash title="Terminal" verify="run"
python3 pick_the_tool.py
```

```text title="Expected output"
pen 3
ink 5
back: pad
back: ink
back: pen
pen -> 3
ink -> 5
```

`zip(items, prices)` stopped after two pairs because `prices` has only two values, and `"pad"` was silently dropped. The `while` rows of the table are the next step.

## Step 4: while loops and while True
Use `while condition:` to repeat until something changes, and `while True:` to loop until a `break` decides to stop. A non-empty list is truthy, so `while stack:` runs until the list is empty. To keep the script deterministic, the commands below come from a hardcoded list instead of typing.

```python title="while_loops.py" file
balance = 100
months = 0
while balance < 130:
    balance += 10
    months += 1
print("months:", months, "balance:", balance)

commands = iter(["add", "add", "quit", "add"])
while True:
    cmd = next(commands)
    if cmd == "quit":
        break
    print("handling", cmd)
print("stopped at quit")

stack = [1, 2, 3]
while stack:
    print("pop", stack.pop())
print("stack is empty:", stack)
```

```bash title="Terminal" verify="run"
python3 while_loops.py
```

```text title="Expected output"
months: 3 balance: 130
handling add
handling add
stopped at quit
pop 3
pop 2
pop 1
stack is empty: []
```

The last `"add"` was never handled because `break` ended the `while True` loop at `"quit"`. Every `while True:` needs a reachable `break` (or a `return`), or it runs forever.

## Step 5: Loop control with break, continue, else, and pass
`break` exits the loop immediately, `continue` jumps to the next iteration, and `else` runs only when no `break` happened. `pass` is an empty placeholder body. The loop `else` is a "not found" branch: it is skipped when `break` fires.

```python title="loop_control.py" file
for n in range(1, 8):
    if n == 3:
        continue
    if n == 6:
        break
    print("n =", n)
print("after loop")

for n in [3, 5, 8, 9]:
    if n % 2 == 0:
        print("found even", n)
        break
else:
    print("no even number")

for n in [3, 5, 7]:
    if n % 2 == 0:
        print("found even", n)
        break
else:
    print("no even number")

for n in range(3):
    pass
print("n after loop:", n)
```

```bash title="Terminal" verify="run"
python3 loop_control.py
```

```text title="Expected output"
n = 1
n = 2
n = 4
n = 5
after loop
found even 8
no even number
n after loop: 2
```

In the first loop, `3` was skipped by `continue` and `6` stopped the loop. The second loop found `8`, so its `else` was skipped; the third loop never broke, so its `else` ran. The loop variable stays available after the loop ends.

## Step 6: Common patterns
Four patterns cover most loops. Accumulate keeps a running total, transform builds a new list from every item, filter keeps only items that pass a test, and count uses a dictionary with `get(key, 0) + 1`. Finding the largest value is an accumulate variant.

```python title="common_patterns.py" file
prices = [12, 7, 30, 4]

total = 0
for p in prices:
    total += p

doubled = [p * 2 for p in prices]
cheap = [p for p in prices if p < 10]

counts = {}
for word in "a b a c b a".split():
    counts[word] = counts.get(word, 0) + 1

largest = prices[0]
for p in prices[1:]:
    if p > largest:
        largest = p

print(total, doubled, cheap)
print(counts, largest)
```

```bash title="Terminal" verify="run"
python3 common_patterns.py
```

```text title="Expected output"
53 [24, 14, 60, 8] [7, 4]
{'a': 3, 'b': 2, 'c': 1} 30
```

`counts.get(word, 0)` returns `0` for a word not seen yet, so one line handles both the first and later occurrences. The cheat sheet's own version of this program is the final practice.

## Step 7: Loop over dictionaries, strings, and files
Looping over a dictionary gives its keys; use `.values()` for values and `.items()` for both. A string yields one character at a time, and an open file yields one line at a time, including the trailing newline. The script writes its own file first so it runs anywhere.

```python title="dict_str_files.py" file
import os

d = {"a": 1, "b": 2}
for k in d:
    print("key", k)
for v in d.values():
    print("value", v)
for k, v in d.items():
    print(k, "->", v)

for ch in "hey":
    print(ch, end=" ")
print()

with open("f.txt", "w") as out:
    out.write("one\ntwo\nthree\n")

for line in open("f.txt"):
    print(repr(line))

with open("f.txt") as f:
    for line in f:
        print(line.rstrip("\n"))

os.remove("f.txt")
```

## Step 8: The comprehension family
A comprehension builds a list, dictionary, or set from a loop in one expression. Square brackets make a list, braces with `key: value` make a dictionary, and braces with one value make a set. A generator expression inside `sum()` adds numbers without building a list first.

```python title="comprehensions.py" file
print([x * 2 for x in range(3)])
print({x: x * x for x in range(3)})
print({x % 3 for x in range(6)})
print(sum(x * x for x in range(4)))

words = ["tea", "coffee", "milk"]
print([w.upper() for w in words if len(w) > 3])
print([n if n % 2 == 0 else -n for n in range(5)])
print([(a, b) for a in "ab" for b in (1, 2)])

gen = (x * x for x in range(3))
print(type(gen).__name__, list(gen))
```

```bash title="Terminal" verify="run"
python3 comprehensions.py
```

```text title="Expected output"
[0, 2, 4]
{0: 0, 1: 1, 2: 4}
{0, 1, 2}
14
['COFFEE', 'MILK']
[0, -1, 2, -3, 4]
[('a', 1), ('a', 2), ('b', 1), ('b', 2)]
generator [0, 1, 4]
```

The set prints as `{0, 1, 2}` because small integers keep a stable order. A generator expression is used up once you turn it into a list. An `if` at the end filters items, while a conditional expression before `for` (`a if test else b`) transforms each item. Several `for` clauses nest left to right.

## Step 9: Nested loops and itertools
A loop inside a loop runs the inner loop completely for each outer item. `itertools.product()` replaces two nested loops with one, and `islice()` takes the first few items of anything iterable, including a long range. A `break` only leaves the innermost loop.

```python title="nested_itertools.py" file
from itertools import product, islice

for a, b in product("ab", [1, 2]):
    print(a, b, end=" | ")
print(list(islice(range(100), 3)))

for row in range(1, 4):
    line = ""
    for col in range(1, 4):
        line += str(row * col) + " "
    print(line.strip())

for i in range(3):
    for j in range(3):
        if j == 1:
            break
        print("i, j =", i, j)
```

```bash title="Terminal" verify="run"
python3 nested_itertools.py
```

```text title="Expected output"

1 2 3
2 4 6
3 6 9
i, j = 0 0
i, j = 1 0
i, j = 2 0
```

The first line matches the cheat sheet output. The `break` stopped each inner loop at `j == 1`, but the outer loop carried on through `i = 2`.

## Step 10: The pitfalls checklist
Four bugs appear again and again. Removing items from a list while looping over it skips items, so build a new list. `range(1, 5)` stops at 4, so add one for an inclusive end. An iterator such as `map()` is empty the second time you loop over it, so wrap it in `list()`. And `range(len(x))` is better written with `enumerate(x)`. An infinite `while` is fixed by updating its condition.

```python title="pitfalls.py" file
nums = [1, 2, 2, 3]
for n in nums:
    if n == 2:
        nums.remove(n)
print("bug:", nums)

nums = [1, 2, 2, 3]
nums = [n for n in nums if n != 2]
print("fix:", nums)

print(list(range(1, 5)), list(range(1, 5 + 1)))

squares = map(lambda n: n * n, [1, 2, 3])
print(list(squares))
print(list(squares))
squares = list(map(lambda n: n * n, [1, 2, 3]))
print(squares, squares)

names = ["ann", "bob"]
for i in range(len(names)):
    print(i, names[i])
for i, name in enumerate(names):
    print(i, name)

n = 3
while n > 0:
    n -= 1
print("while ended at", n)
```

```bash title="Terminal" verify="run"
python3 pitfalls.py
```

```text title="Expected output"
bug: [1, 2, 3]
fix: [1, 3]
[1, 2, 3, 4] [1, 2, 3, 4, 5]
[1, 4, 9]
[]
[1, 4, 9] [1, 4, 9]
0 ann
1 bob
0 ann
1 bob
while ended at 0
```

The buggy loop left one `2` behind because removing an item shifted the next one into the position the loop had just passed. Delete the line `n -= 1` in the last loop and it would never end.

## Step 11: The walrus operator in a loop test
The assignment expression `:=` stores a value and tests it in the same line. It is the idiomatic way to read a stream in chunks: the loop ends when `read()` returns an empty string, which is falsy. This script reads from an in-memory text stream, but the same loop works with `open("f.txt")`.

```python title="walrus_loop.py" file
import io

f = io.StringIO("abcdefgh")
while chunk := f.read(3):
    print(repr(chunk))

values = [y for x in [1, 2, 3] if (y := x * x) > 1]
print(values)
```

```bash title="Terminal" verify="run"
python3 walrus_loop.py
```

```text title="Expected output"
'abc'
'def'
'gh'
[4, 9]
```

The loop stops when `read()` returns an empty string. In the comprehension, `(y := x * x)` computes each square once and reuses it in the test and in the result, so `1` is filtered out.

## Step 12: Combine the loop tools
This script mixes `for`, `while`, `range`, `enumerate`, `zip`, `break`, `continue`, loop `else`, and comprehensions on hardcoded gradebook data. It is a good model of how the pieces fit together in one program.

```python title="loop_report.py" file
students = ["Ana", "Ben", "Cy", "Dee"]
scores = [88, 52, 97, 70]

for rank, (name, score) in enumerate(zip(students, scores), start=1):
    if score < 60:
        print(f"{rank}. {name} skipped (below 60)")
        continue
    print(f"{rank}. {name} scored {score}")

passed = [name for name, score in zip(students, scores) if score >= 60]
print("passed:", passed)

for name, score in zip(students, scores):
    if score > 95:
        print("top scorer:", name)
        break
else:
    print("no score above 95")

for name, score in zip(students, scores):
    if score > 99:
        print("perfect score:", name)
        break
else:
    print("no perfect score")

bands = {}
for score in scores:
    band = score // 10 * 10
    bands[band] = bands.get(band, 0) + 1
print("bands:", bands)

retries = 0
pending = 52
while pending < 60:
    pending += 5
    retries += 1
print("retries needed:", retries, "final score:", pending)

for cutoff in range(100, 50, -20):
    count = sum(1 for score in scores if score >= cutoff)
    print(f"{count} at or above {cutoff}")
```

```bash title="Terminal" verify="run"
python3 loop_report.py
```

```text title="Expected output"

2. Ben skipped (below 60)
3. Cy scored 97
4. Dee scored 70
passed: ['Ana', 'Cy', 'Dee']
top scorer: Cy
no perfect score
bands: {80: 1, 50: 1, 90: 1, 70: 1}
retries needed: 2 final score: 62
0 at or above 100
2 at or above 80
3 at or above 60
```

Each loop uses the form that fits its job: `enumerate` with `zip` for ranked rows, a comprehension for filtering, loop `else` for "none found", `while` for an unknown number of retries, and a negative-step `range` for descending cutoffs.

## How it works
A `for` loop asks its iterable for an iterator and calls `next()` until the iterator is exhausted. Lists, strings, dictionaries, files, `range`, `enumerate`, `zip`, and generators are all iterables. A `while` loop re-tests its condition before every pass, so the body must change what the condition looks at.

`break` leaves the nearest loop, `continue` skips to its next pass, and the loop `else` runs only if the loop finished without `break`. Iterators such as `zip`, `map`, and generators are used up after one pass, which is why `list()` helps when you need two. Comprehensions are loops written as expressions; they build the result in one step and are the idiomatic way to transform or filter. Never change a collection while iterating over it: build a new one instead.

## Common errors
### The loop runs forever
A `while` loop whose condition never changes never ends. Update a variable the condition uses, as in `count -= 1`, and make sure every `while True:` has a reachable `break`. Press Ctrl+C to stop a running script.

### Items are skipped when removing from a list in a loop
Removing items from the list you are looping over shifts later items into positions already passed. Build a new list with `[n for n in nums if n != 2]`, or loop over a copy such as `nums[:]`.

### An off-by-one error with `range`
`range(1, 5)` yields `1, 2, 3, 4` and never `5`. Use `range(1, 6)` to include 5, and remember that `range(5)` starts at 0.

### A second loop over `map`, `zip`, or a generator is empty
Iterators are used up after one pass. Store the result with `list(...)` when you need to loop twice.

### `ValueError: too many values to unpack (expected 2)`
`for k, v in d:` loops over keys, not pairs. Use `for k, v in d.items():` to get key and value together.

### `RuntimeError: dictionary changed size during iteration`
Adding or deleting keys while looping over a dictionary raises this error. Loop over `list(d)` or build a new dictionary instead.

## Recap
- Use `for` for collections and known counts and `while` for open-ended conditions, with `range()`, `enumerate()`, `zip()`, and `.items()` as the helpers for numbers, positions, parallel lists, and dictionary pairs.
- `break` stops a loop, `continue` skips an iteration, and a loop `else` means "no break"; comprehensions are the idiomatic way to transform or filter.
- Never modify a collection while iterating over it, remember that the `range` stop is excluded, and wrap one-shot iterators in `list()` before reusing them.

## Final practice: Common Patterns
The cheat sheet's example program combines accumulate, transform, filter, and count in one short script. Create `loop_patterns.py` and compare your output with the sheet.

```python title="loop_patterns.py" file
    counts[ch] = counts.get(ch, 0) + 1      # count
print(total, squares, big)
print(counts)
```
