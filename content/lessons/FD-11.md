## Why this matters
Containers package an application and its runtime in a repeatable environment. Docker Compose also gives related services stable network names, health checks, and shared configuration.

## What you will build
You will start PostgreSQL and Redis, inspect and stop containers, then containerize the Node API with a cached dependency layer, a non-root runtime user, and a three-service Compose stack.

## Step 1: Run PostgreSQL and Redis directly
`-p` maps a host port to a container port; `-v` attaches a named volume. The password below is for a throwaway local exercise only.

```bash title="Terminal" verify="manual" manual review required 2026-10-18 Linux
docker volume create fd11-pgdata
docker run -d --name fd11-db -e POSTGRES_PASSWORD=local-only -p 5433:5432 -v fd11-pgdata:/var/lib/postgresql/data postgres:16-alpine
docker run -d --name fd11-redis -p 6380:6379 redis:7-alpine
docker ps
docker logs fd11-db
docker exec -it fd11-redis redis-cli ping
```

```text title="Expected output"
Both containers are running and Redis replies PONG.
```

Stop and remove a named demo container when finished; the database volume remains until explicitly removed.



## Step 2: Write a layered application image
Docker executes each instruction as a layer. Copying package manifests before source code lets Docker reuse the dependency-install layer when only application code changes.

```dockerfile title="Dockerfile" file
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev && npm cache clean --force
ENV NODE_ENV=production
COPY src ./src
USER node
EXPOSE 3000
CMD ["node", "src/server.js"]
```

```text title=".dockerignore" file
node_modules
npm-debug.log
.env
.git
coverage
dist
```

## Step 3: Define app, database, and Redis services
Inside a Compose network, service names are DNS names: configure the app to connect to `db` and `redis`, not `localhost`. Health checks let the app wait until dependencies are ready.

```yaml title="docker-compose.yml" file
services:
  app:
    build: .
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgres://${POSTGRES_USER}:${POSTGRES_PASSWORD}@db:5432/${POSTGRES_DB}
      REDIS_URL: redis://redis:6379
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_healthy
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: ${POSTGRES_DB}
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
      interval: 5s
      timeout: 3s
      retries: 10
  redis:
    image: redis:7-alpine
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 10
volumes:
  pgdata:
```

## Step 4: Build, start, and check the stack
Place `.env` beside the Compose file using the local values from FD-10. Compose starts the dependencies first; then check the API health endpoint and verify the process user inside the container.

```bash tab="macOS / Linux" title="Terminal" verify="manual" manual review required 2026-10-18 Linux
docker compose up --build -d
docker compose ps
curl -i http://localhost:3000/health
docker compose exec app id
docker image ls
```

```powershell tab="Windows PowerShell" title="Terminal" verify="manual" manual review required 2026-10-18 Windows
docker compose up --build -d
docker compose ps
Invoke-WebRequest http://localhost:3000/health

```

```text title="Expected output"
The app health endpoint succeeds, app runs as the node user, and the built image appears in docker image ls.
```

## Step 5: Record what Docker is doing
Save these explanations and your observed image size in `NOTES.md`; the terms describe separate parts of the container workflow.

```markdown title="NOTES.md" file
# Docker notes

- Image: immutable template built from layers.
- Container: a running process created from an image.
- Layer cache: unchanged earlier layers can be reused during a rebuild.
- Named volume: Docker-managed persistent data, such as PostgreSQL files.
- Bind mount: a host path mounted into a container, often for local development.
- Port mapping: host port forwarded to a container port, for example 3000:3000.
- Service hostname: Compose service name used for container-to-container traffic.
- Image size from `docker image ls`: record your measured value here.
```

## How it works
An image is a layered filesystem and startup configuration; a container is an isolated process created from it. Compose creates a private network and DNS entries for services. Volumes persist separately from a container's writable layer.

## Common errors
### The app cannot connect to PostgreSQL
Use `db` as the hostname from a Compose container; `localhost` points back to the app container.
### Compose starts the app before its dependency is ready
Add a health check and use `condition: service_healthy`.
### Every code change reinstalls dependencies
Copy `package*.json` and run `npm ci` before copying application source.

## Recap
- Images define layers and containers run processes from those images.
- Named volumes preserve data; Compose service names connect containers on a shared network.
- Order Dockerfile steps for cache reuse and run the application as a non-root user.
