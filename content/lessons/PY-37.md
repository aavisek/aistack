## Why this matters
A function reads names through local, enclosing, global, and built-in scopes. Understanding lookup prevents accidental dependencies and makes closures predictable.

## What you will build
A runnable set of examples about scope and namespace in functions.

## Before you start
Create each named script in a Python 3.10+ environment and run the commands below.

## Step 1: Observe local scope

```python title="py_37_1.py" file
label = "global"
def show():
    label = "local"
    return label

print(show(), label)
```

```bash title="Terminal" verify="run"
python3 py_37_1.py
```

```text title="Expected output"
local global
```

## Step 2: Read a global constant

```python title="py_37_2.py" file
RATE = 0.2
def total(amount):
    return amount * (1 + RATE)

print(total(10))
```

```bash title="Terminal" verify="run"
python3 py_37_2.py
```


## Step 3: Create a closure

```python title="py_37_3.py" file
def make_multiplier(factor):
    def multiply(value):
        return value * factor
    return multiply

double = make_multiplier(2)
print(double(6))
```

```bash title="Terminal" verify="run"
python3 py_37_3.py
```

```text title="Expected output"
12
```

## Step 4: Inspect a function namespace

```python title="py_37_4.py" file
def add(a, b):
    return a + b

add.calls = 1
print(add.__name__, add.calls)
```

```bash title="Terminal" verify="run"
python3 py_37_4.py
```

```text title="Expected output"
add 1
```

## How it works
Local names hide outer names.
Closures retain enclosing values after the outer call returns.
Function objects can carry attributes, though a separate object is often clearer.

## Common errors
### Repeating code instead of extracting a function
Give a helper one responsibility and return its result.

### Confusing a return value with printed output
Use `return` for callers and `print` only at the boundary.

### Hiding state or dependencies
Prefer explicit parameters and imports over surprising global behavior.
