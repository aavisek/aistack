## Why this matters
Functions package reusable behavior behind a clear name. Splitting a long task into small functions makes each rule testable and keeps callers readable.

    return sum(prices)

## Step 3: Pass data through a pipeline

```python title="py_35_3.py" file
def normalize(items):
    return [item.strip().lower() for item in items]

def count_words(items):
    return sum(len(item.split()) for item in items)

words = normalize([" Red apple ", "Blue pear"])
print(words, count_words(words))
```

```bash title="Terminal" verify="run"
python3 py_35_3.py
```

```text title="Expected output"

```

## Step 4: Compose the final program

```python title="py_35_4.py" file
def normalize(items):
    return [item.strip().lower() for item in items]

def count_words(items):
    return sum(len(item.split()) for item in items)

def receipt(items):
    clean = normalize(items)
    return f"{count_words(clean)} words: {', '.join(clean)}"

print(receipt([" Red apple ", "Blue pear"]))
```

```bash title="Terminal" verify="run"
python3 py_35_4.py
```

```text title="Expected output"
4 words: red apple, blue pear
```

## How it works
A named function captures one responsibility.
Helpers can pass return values to other helpers.
A small public function can compose private steps.

## Common errors
### Repeating code instead of extracting a function
Give a helper one responsibility and return its result.

### Confusing a return value with printed output
Use `return` for callers and `print` only at the boundary.

### Hiding state or dependencies
Prefer explicit parameters and imports over surprising global behavior.
