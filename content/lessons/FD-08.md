## Step 1: Create tables with constraints
Primary keys uniquely identify rows. `NOT NULL` prevents missing required values; defaults fill a value when an insert omits it. `enrolled_at` is nullable so the lesson can demonstrate SQL `NULL`.

```sql title="schema.sql" file
DROP TABLE IF EXISTS enrollments;
DROP TABLE IF EXISTS courses;
DROP TABLE IF EXISTS students;

CREATE TABLE students (
  id integer PRIMARY KEY,
  name text NOT NULL,
  email text NOT NULL UNIQUE,
  age integer NOT NULL CHECK (age >= 0),
  enrolled_at date DEFAULT CURRENT_DATE
);

CREATE TABLE courses (
  id integer PRIMARY KEY,
  title text NOT NULL,
  credits integer NOT NULL DEFAULT 3 CHECK (credits > 0)
);
```

## Step 3: Ask focused SELECT questions
Each comment names the question and an expected result. `WHERE` filters rows; `ORDER BY`, `LIMIT`, and `OFFSET` shape the result; aggregates summarize a set.

```sql title="Read queries - append to queries.sql"
-- 1. How many students are seeded? Expected: 20.
SELECT COUNT(*) AS student_count FROM students;

-- 2. How many courses are seeded? Expected: 8.
SELECT COUNT(*) AS course_count FROM courses;

-- 3. Which students are 20 or older and have IDs below 10? Expected: 9 rows.
SELECT id, name FROM students WHERE age >= 20 AND id < 10;

-- 4. Which students are ID 1 or ID 20? Expected: 2 rows.
SELECT id FROM students WHERE id = 1 OR id = 20;

-- 5. Which course IDs are in the first, third, or fifth position? Expected: 3 rows.
SELECT id FROM courses WHERE id IN (1, 3, 5);

-- 6. Which students are between 20 and 22 years old? Expected: 7 rows.
SELECT id, age FROM students WHERE age BETWEEN 20 AND 22;

-- 7. Which names start with Student 1? Expected: 10 rows (IDs 10–19).
SELECT id, name FROM students WHERE name LIKE 'Student 1%';

-- 8. Which students have no enrollment date? Expected: student 20.
SELECT id FROM students WHERE enrolled_at IS NULL;

-- 9. What does equality with NULL find? Expected: zero rows; use IS NULL instead.
SELECT id FROM students WHERE enrolled_at = NULL;

-- 10. Which courses are ordered by credits then title? Expected: 8 rows.
SELECT title, credits FROM courses ORDER BY credits DESC, title ASC;

-- 11. Which are the first three course titles alphabetically? Expected: 3 rows.
SELECT title FROM courses ORDER BY title LIMIT 3;

-- 12. Which are the next two course titles alphabetically? Expected: 2 rows.
SELECT title FROM courses ORDER BY title LIMIT 2 OFFSET 3;

-- 13. Which distinct student ages occur? Expected: ages 18 through 27.
SELECT DISTINCT age FROM students ORDER BY age;

-- 14. What is the total course-credit count? Expected: 27.
SELECT SUM(credits) FROM courses;

-- 15. What is the average student age? Expected: 22.60.
SELECT ROUND(AVG(age), 2) FROM students;

-- 16. What are the minimum and maximum ages? Expected: 18 and 27.
SELECT MIN(age), MAX(age) FROM students;
```

## Step 4: Change rows safely
Always add a `WHERE` clause to targeted updates and deletes. To observe the danger of omitting it, use a temporary copy inside a transaction and roll it back.

```sql title="Safe changes - append to queries.sql"
-- Expected: one row updated and one row deleted from a temporary copy.
CREATE TEMP TABLE student_changes AS TABLE students;
UPDATE student_changes SET age = age + 1 WHERE id = 1;

DELETE FROM student_changes WHERE id = 1;

-- Expected inside transaction: all 20 copied rows are set to zero.
CREATE TEMP TABLE student_safety AS TABLE students;
BEGIN;
UPDATE student_safety SET age = 0;
SELECT COUNT(*) AS changed_rows FROM student_safety WHERE age = 0;
ROLLBACK;

-- Expected after rollback: original minimum age remains 18.
SELECT MIN(age) FROM student_safety;
```

```text title="Expected output"
SELECT 20
UPDATE 1
DELETE 1
SELECT 20
BEGIN
UPDATE 20
changed_rows: 20
ROLLBACK
min age after rollback: 18
```

## Step 5: Demonstrate the unique constraint
The duplicate email attempt is enclosed in a PL/pgSQL exception block so the script continues after PostgreSQL rejects the duplicate.

```sql title="Unique constraint check - append to queries.sql"
DO $$
BEGIN
  INSERT INTO students (id, name, email, age)
  VALUES (99, 'Duplicate Email', 'student2@example.test', 22);
EXCEPTION WHEN unique_violation THEN
  RAISE NOTICE 'Unique email rejected as expected';
END $$;
```

DO

## How it works
SQL statements operate on sets of rows. Constraints are rules enforced by PostgreSQL, not just notes for application developers. A transaction groups operations; `ROLLBACK` discards the experiment and restores the original copy.

## Common errors
### A NULL comparison returns no matches
Use `IS NULL` or `IS NOT NULL`; ordinary equality does not test null values.
### An UPDATE changes every row
Stop and inspect the statement. Use a transaction and a temporary copy for experiments.
### An insert violates the unique constraint
Use a new email address; duplicates are intentionally rejected.

## Recap
- Define data rules with primary keys, NOT NULL, UNIQUE, DEFAULT, and checks.
- Filter and summarize rows with SELECT, WHERE, sorting, paging, and aggregates.
- Use a WHERE clause for changes and transactions for safe experiments.
