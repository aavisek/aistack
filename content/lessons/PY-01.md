## Why this matters
When a list changes in one part of a program, another part may see that change too. Understanding whether names refer to the same object helps prevent surprising bugs and makes it easier to reason about functions, data structures, and state.

## What you will build
A small Python script that compares an aliased list, an integer that gets rebound, and a tuple that contains a mutable list.

## Before you start
Use Python 3.11 or newer and open a terminal in a new folder. In VS Code, create a file named `mutable_immutable.py`. Python variables are names bound to objects; assigning one name to another does not automatically copy the object.

## Step 1: Give one list two names
Start with a mutable list and assign a second name to it. Both names refer to the same list object.

```python title="mutable_immutable.py" file
colors = ["blue", "green"]
favorite_colors = colors

favorite_colors.append("purple")

print(colors)
print(favorite_colors)
print(colors is favorite_colors)
```

```text title="Expected output"
['blue', 'green', 'purple']
['blue', 'green', 'purple']
True
```

`append` changes the existing list. Since `colors` and `favorite_colors` refer to that same object, reading either name shows the added color. `is` checks object identity; `==` checks whether values compare equal.

## Step 2: Rebind an immutable value
Integers are immutable: their value cannot be changed in place. An assignment such as `score += 1` binds `score` to an integer value representing the result; it does not edit the original integer object.

```python title="mutable_immutable.py" file
score = 10
previous_score = score

score += 1

print(previous_score)
print(score)
```

```text title="Expected output"
10
11
```

The old value remains available through `previous_score`. Strings and booleans are immutable too. Rebinding a name is different from mutating an object that multiple names share.

## Step 3: Notice the same behavior in a function
A function can mutate a mutable object passed to it. Passing the list does not make an automatic copy.

```python title="mutable_immutable.py" file
def add_tag(tags):
    tags.append("python")


skills = ["learning"]
add_tag(skills)
print(skills)
```

```text title="Expected output"
['learning', 'python']
```

If a function should leave its input unchanged, make an intentional copy or return a new value. For a nested structure, a shallow copy only copies the outer container; inner mutable objects may still be shared.

## Step 4: Put a mutable value inside a tuple
A tuple is immutable as a container: its slots cannot be reassigned. But immutability is not automatically recursive. A tuple can refer to a list, and that list can still change.

```python title="mutable_immutable.py" file
colors = ["blue", "green"]
favorite_colors = colors
favorite_colors.append("purple")

score = 10
previous_score = score
score += 1

profile = ("Alex", ["learning"])
profile[1].append("python")

print(colors)
print(colors is favorite_colors)
print(previous_score, score)
print(profile)
```

```bash tab="macOS / Linux" title="Terminal" verify="manual" manual review required 2026-11-05 Linux
python3 mutable_immutable.py
```

```powershell tab="Windows PowerShell" title="Terminal" verify="manual" manual review required 2026-11-05 Windows
py -3 mutable_immutable.py
```

```text title="Expected output"
['blue', 'green', 'purple']
True
10 11
('Alex', ['learning', 'python'])
```

The tuple still contains the same list object; the list's contents changed. Assigning a new value to `profile[1]` is not allowed, but calling a mutating method on the list stored there is allowed.

## How it works
Python objects have identity, type, and value. Names are references to objects. A mutable object's value can be changed in place; an immutable object's value cannot. Assignment changes which object a name refers to, and assignment to another name does not imply a copy.

Use `is` when identity is what you mean, such as checking for `None`. Use `==` to compare values. Do not use `id()` as a persistent identifier: an object's identity number is only meaningful during its lifetime in the current process.

## Common errors
### Expecting assignment to copy a list
`other = original` creates another name for the same object. Use `original.copy()` for a shallow list copy when that is what the task requires.

### Treating `is` as a value comparison
Two different lists can compare equal with `==` while not being the same object. Use `==` to compare their contents.

### Assuming every part of a tuple is immutable
A tuple's references cannot be replaced, but a referenced mutable value such as a list may still change.

## Recap
- Assignment adds or rebinds names; it does not automatically copy objects.
- Lists are mutable, while integers and strings are immutable.
- An immutable container such as a tuple can still refer to mutable objects.
