## Why this matters
Every useful program makes decisions: grant or deny access, pick a price, handle an empty result, or react to a command. Conditionals are how Python chooses which code runs. Most bugs here come from a handful of habits, such as `== None`, `x == 1 or 2`, and overlapping `if` statements, so learning the safe patterns early saves hours of debugging.

## What you will build
Small, standalone Python scripts that cover `if`/`elif`/`else`, truthy and falsy values, comparison and logical operators, flat versus nested tests, the one-line ternary, membership and `None` checks, and `match`/`case`. You finish with a cinema desk program that uses all of them to price tickets and set access levels.

## Before you start
Use Python 3.10 or newer, because `match`/`case` was added in 3.10. Create each named file in a practice folder. Every example is independent. Run each file with `python3 filename.py` on macOS/Linux or `py -3 filename.py` in Windows PowerShell.

You should already know booleans, numbers, and comparison operators from PY-02. A condition is any expression Python can treat as true or false. Every `if`, `elif`, and `else` line ends with a colon, and its body is indented by 4 spaces.

## Step 1: Choose a branch with if, elif, and else
An `if` statement runs its indented body only when its test is true. Add `elif` for more tests and `else` as the catch-all. Python checks the tests from top to bottom and runs only the first true branch, so order `elif` branches from most specific to most general.

```python title="if_elif_else.py" file
def grade_for(score):
    if score >= 90:
        grade = "A"
    elif score >= 70:
        grade = "B"
    else:
        grade = "C"
    return grade


score = 72
if score >= 90:
    grade = "A"
elif score >= 70:
    grade = "B"
else:
    grade = "C"
print(grade)

for s in [95, 90, 72, 70, 69]:
    print(s, grade_for(s))

# Both tests are true for 72, but only the first true branch runs
if score >= 0:
    print("first test wins")
elif score >= 70:
    print("never reached")
```

```bash title="Terminal" verify="run"
python3 if_elif_else.py
```

```text title="Expected output"
B
95 A
90 A
72 B
70 B
69 C
first test wins
```

The boundary values 90 and 70 fall into the higher grade because the tests use `>=`. The last `if`/`elif` pair shows why order matters: the broad test `score >= 0` matches first, so the more specific branch never runs.

## Step 2: Use truthy and falsy values as conditions
Any object can be a condition. The falsy values are `0`, `0.0`, `""`, `[]`, `{}`, `()`, `set()`, `None`, and `False`. Everything else is truthy. This lets you write `if items:` instead of `if len(items) > 0:` and `if not name:` for an empty string.

```python title="truthy_falsy.py" file
name = ""
if not name:
    name = "Guest"
print(name)

items = [3, 4]
if items:
    print(len(items))

for value in [0, 0.0, "", [], {}, (), set(), None, False]:
    print(repr(value), bool(value))

for value in [1, -1, "0", " ", [0], "False"]:
    print(repr(value), bool(value))
```

```text title="Expected output"
'False' True
```

`bool(value)` shows how Python reads a value as a condition. Watch the surprises in the second loop: the string `"0"`, a single space, the list `[0]`, and the text `"False"` are all truthy because they are not empty.

## Step 3: Compare values with the comparison operators
`==` and `!=` test equality, `<`, `<=`, `>`, and `>=` order values, `is` and `is not` test whether two names refer to the same object, and `in` and `not in` test membership. A chained comparison such as `1 < x < 10` needs no `and` and evaluates `x` once.

```python title="comparisons.py" file
x = 5
print(x == 5, x != 5)
print(x < 5, x <= 5)
print(x > 5, x >= 5)
print(1 < x < 10)
print(1 < x < 3)

print("abc" == "abc", "apple" < "banana")
print(2 == 2.0, 3 != 3.0)

a = [1, 2]
b = [1, 2]
c = a
print(a == b, a is b, a is c, a is not b)

print("a" in "cat", "z" not in "cat")
print(3 in [1, 2, 3], "k" in {"k": 1}, 9 in {1, 2})
```


`a == b` is true because the lists hold equal items, while `a is b` is false because they are two separate objects. Use `==` to compare values and keep `is` for identity checks such as `None`. Membership works on lists, strings, dictionaries (keys), and sets.

## Step 4: Combine tests with and, or, and not
`and` needs both sides true, `or` needs either side, and `not` flips the result. They short-circuit: evaluation stops as soon as the answer is known. They also return one of their operands, not always `True` or `False`, so `0 or 5` gives `5`. `and` binds tighter than `or`.

```python title="logic.py" file
age, member = 25, True
if age >= 18 and member:
    print("Access granted")
if not member or age < 18:
    print("Denied")

print(True and False, True or False, not True)

# 0 or 5 returns an operand, not True/False
print(0 or 5)
print(3 and 7)
print("" or "default")
print(0 and 5)

# short-circuit: the right side is never evaluated
def noisy():
    print("noisy ran")
    return True


print(False and noisy())
print(True or noisy())
print(True and noisy())

# and binds tighter than or
print(True or False and False)
print((True or False) and False)
```


```text title="Expected output"
False
True

False
```

`noisy ran` appears only once, for `True and noisy()`, because the first two lines already knew their answer. `"" or "default"` is a handy way to supply a fallback. The last two lines differ only by parentheses, so add them whenever `and` and `or` are mixed.

## Step 5: Prefer flat conditions over nested ones
Nested `if` statements form a pyramid that is hard to read. A single combined test, often a chained comparison, gives the same result in fewer lines. In a function, early `return` statements keep a long decision chain flat as well.

```python title="nested_flat.py" file
temp = 25
if temp > 0:
    if temp < 100:
        print("liquid")

if 0 < temp < 100:
    print("liquid")

# early return keeps long chains flat
def describe(temp):
    if temp <= 0:
        return "frozen"
    if temp >= 100:
        return "gas"
    return "liquid"


for t in [-5, 25, 100]:
    print(t, describe(t))
```

```bash title="Terminal" verify="run"
python3 nested_flat.py
```

```text title="Expected output"
liquid
liquid
-5 frozen
25 liquid
100 gas
```

Both versions print `liquid`, but the flat one states the whole rule on one line. Nesting is still right when the inner test only makes sense after the outer one passes, for example checking a key only after confirming a record exists.

## Step 6: Write a one-line ternary expression
The ternary form is `value_if_true if condition else value_if_false`. It is an expression, so you can assign it, print it, or pass it to a function. Keep it for simple choices between two values and use a normal `if` statement when each branch does real work.

```python title="ternary.py" file
age = 20
status = "adult" if age >= 18 else "minor"
print(status)
fee = 0 if age < 5 else 10
print(fee)

# an expression can be passed straight to a function
print("even" if age % 2 == 0 else "odd")

for a in [3, 20, 70]:
    label = "child" if a < 13 else "adult" if a < 65 else "senior"
    print(a, label)
```

```bash title="Terminal" verify="run"
python3 ternary.py
```

```text title="Expected output"
adult
10
even
3 child
20 adult
70 senior
```

The condition is in the middle, which reads differently from other languages. Ternaries can be chained, as the last loop shows, but more than two levels quickly becomes harder to read than `if`/`elif`/`else`.

## Step 7: Check membership and None correctly
To compare one value with several options, use `in` with a tuple instead of repeating `==`. To test for `None`, use `is None` or `is not None`, because `None` is a single object and `is` checks identity. Remember that `None`, `0`, and `""` are all falsy, so `if not value` cannot tell them apart.

```python title="membership_none.py" file
role = "admin"
if role in ("admin", "owner"):
    print("full access")

data = None
if data is None:
    print("no data")

if role not in ("guest", "banned"):
    print("not restricted")

# None is falsy, but so are 0 and "": only `is None` tells them apart
for value in [None, 0, ""]:
    print(repr(value), not value, value is None)
```

```bash title="Terminal" verify="run"
python3 membership_none.py
```

```text title="Expected output"
full access
no data
not restricted
None True True
0 True False
'' True False
```

All three values make `not value` true, but only `None` makes `value is None` true. Use `is None` whenever "no value yet" must be treated differently from a real `0` or empty string.

## Step 8: Match fixed alternatives with match and case
`match` compares a value against `case` patterns from top to bottom (Python 3.10+). A `|` joins alternatives, `_` is the default that matches anything, and `case pattern if condition:` adds a guard so the branch runs only when the extra test is also true. Use `match` for many fixed choices and `if`/`elif` for ranges and complex tests.

```python title="match_case.py" file
cmd = "halt"
match cmd:
    case "go":
        print("Moving")
    case "stop" | "halt":
        print("Stopping")
    case _:
        print("Unknown")


def respond(command, speed):
    match command:
        case "go" if speed > 0:
            return "Moving"
        case "go":
            return "Cannot move at speed 0"
        case "stop" | "halt":
            return "Stopping"
        case _:
            return "Unknown"


print(respond("go", 5))
print(respond("go", 0))
print(respond("halt", 0))
print(respond("jump", 0))
```

```bash title="Terminal" verify="run"
python3 match_case.py
```

```text title="Expected output"
Stopping
Moving
Cannot move at speed 0
Stopping
Unknown
```

The first `case "go"` has a guard, so with speed 0 Python falls through to the plain `case "go"`. Put the guarded case before the unguarded one, or the plain case would always win.

## Step 9: Avoid the classic mistakes
Five habits cause most conditional bugs: using `=` instead of `==`, writing `x == 1 or 2`, comparing with `== True`, comparing with `== None`, and using separate `if` statements where `elif` is meant. This script shows the symptoms next to the fixes.

```python title="mistakes.py" file
try:
    compile("if x = 5:\n    pass", "<demo>", "exec")
except SyntaxError as error:
    print(type(error).__name__, "caught")

x = 7
print(x == 1 or 2)
print(bool(x == 1 or 2))
print(x in (1, 2))

flag = 2
print(flag == True, bool(flag))
if flag:
    print("flag is truthy")

# two separate ifs that overlap both run
n = 15
if n % 3 == 0:
    print("Fizz")
if n % 5 == 0:
    print("Buzz")
if n % 3 == 0:
    print("first only")
elif n % 5 == 0:
    print("never reached")
```

```bash title="Terminal" verify="run"
python3 mistakes.py
```

```text title="Expected output"
SyntaxError caught
2
True
False
False True
flag is truthy
Fizz
Buzz
first only
```

`if x = 5:` is a `SyntaxError` (compiled from a string here so the script keeps running). `x == 1 or 2` parses as `(x == 1) or 2`, and `2` is truthy, so it is always true; `x in (1, 2)` is the fix. `flag == True` is false for `2` even though `flag` is truthy, so write `if flag:`. Write `if x is None:`, never `x == None`. Overlapping `if` statements both run, while `if`/`elif` runs one.

## How it works
Python evaluates the test after `if` or `elif`, converts the result to true or false using truthiness, and runs the indented block of the first true branch. The rest of the chain is skipped, and `else` runs only when nothing matched. Indentation, not braces, marks the body, so a missing colon or wrong indent is a `SyntaxError` or `IndentationError`.

`and` and `or` return one of their operands and stop early, so the right side may never run. Comparisons can be chained, and the middle value is evaluated once. `is` compares object identity, which is why it is the right check for `None`. A ternary is an expression with a value, while `match` compares the subject with each pattern in order and uses `_` as the default.

## Common errors
### `SyntaxError: invalid syntax` on `if x = 5:`
A single `=` assigns, and `==` compares. Write `if x == 5:`. Also check that every `if`, `elif`, and `else` line ends with a colon.

### `IndentationError: expected an indented block`
The line after the colon must be indented, and all lines of one body must use the same indent. Use 4 spaces and never mix tabs and spaces.

### `if x == 1 or 2:` is always true
Python reads this as `(x == 1) or 2`, and `2` is truthy. Write `if x == 1 or x == 2:` or, better, `if x in (1, 2):`.

### `if x == None:` or `if flag == True:`
Test `None` with `if x is None:` and booleans with `if flag:` or `if not flag:`. Comparing with `== True` fails for truthy values such as `2` or `"yes"`.

### Two `if` statements both run
Separate `if` statements are independent, so overlapping tests can print or change things twice. Use `if ... elif ... else` when only one branch should run.

### `SyntaxError: invalid syntax` on `match`
`match`/`case` needs Python 3.10 or newer. Run `python3 --version` and use `if`/`elif` on older versions.

## Recap
- `if`/`elif`/`else` runs only the first true branch, any object can be a condition, and empty values such as `0`, `""`, `[]`, and `None` are falsy.
- Use `==` for values, `is None` for `None`, `in` for several options, and chained comparisons for ranges; `and` and `or` short-circuit, return an operand, and `and` binds tighter than `or`.
- A ternary is a one-line `if`/`else` expression, `match`/`case` handles many fixed alternatives with `|`, `_`, and guards, and overlapping `if` statements should become `if`/`elif`.

## Final practice: Cinema Desk
The cheat sheet has no single program, so this one combines its ideas. Create `cinema_desk.py`; it prices tickets with `if`/`elif`/`else`, labels ages with a chained ternary, applies coupons with `match`, checks for `None`, and sets an access level with `in`, `and`, `or`, and `not`.

```python title="cinema_desk.py" file
# Cinema Desk - if/elif/else, logic, ternary, None checks, and match in one program
def age_label(age):
    return "child" if age < 13 else "teen" if age < 18 else "adult" if age < 65 else "senior"


def base_price(age):
    if age < 5:
        price = 0
    elif age < 13:
        price = 6
    elif age >= 65:
        price = 7
    else:
        price = 10
    return price


def apply_coupon(price, coupon):
    if coupon is None:
        return price
    match coupon:
        case "FREE" | "VIP":
            return 0
        case "HALF":
            return price // 2
        case _:
            return price


def access_level(role, age, member):
    if role in ("admin", "owner"):
        return "full access"
    if age >= 18 and member:
        return "member lounge"
    if not member or age < 18:
        return "standard seats"
    return "unknown"


def report(visitors):
    if not visitors:
        print("No visitors")
        return
    total = 0
    for name, age, member, role, coupon in visitors:
        price = apply_coupon(base_price(age), coupon)
        total += price
        print(f"{name}: {age_label(age)}, ${price}, {access_level(role, age, member)}")
    average = total / len(visitors)
    print(f"Total ${total} for {len(visitors)} visitors, average ${average:.2f}")


visitors = [
    ("Ana", 25, True, "guest", None),
    ("Ben", 4, False, "guest", None),
    ("Cleo", 9, False, "guest", "HALF"),
    ("Dev", 70, True, "owner", None),
    ("Eli", 30, False, "guest", "VIP"),
    ("Fay", 16, True, "guest", "BOGUS"),
]
report(visitors)
report([])
```

```bash title="Terminal" verify="run"
python3 cinema_desk.py
```

```text title="Expected output"
Ana: adult, $10, member lounge
Ben: child, $0, standard seats
Cleo: child, $3, standard seats
Dev: senior, $7, full access
Eli: adult, $0, standard seats
Fay: teen, $10, standard seats
Total $30 for 6 visitors, average $5.00
No visitors
```

- `base_price` orders its branches by age, and the first true test wins, so each visitor gets exactly one price.
- `apply_coupon` checks `is None` first, then `match` handles `"FREE" | "VIP"` and `"HALF"`; the unknown coupon `"BOGUS"` falls through to `case _` and leaves Fay's price unchanged.
- `report([])` hits the `if not visitors:` guard, which avoids dividing by zero for an empty list.
- Dev gets full access because `role in ("admin", "owner")` is tested before the age and membership rules.
