## Why this matters
Programs constantly turn a value into a result: a day name into a label, a menu choice into an action, a command into a function. A long `if/elif` or `match` chain does this, but every new case means new code. A dictionary lookup keeps the cases as data, so adding one is a single line and the lookup stays fast however many cases you have.

## What you will build
Small, standalone Python scripts that replace a day-type `if/elif` chain with a dictionary, handle missing keys as a default case, compare the result with `match/case`, store functions in dispatch tables, and group many keys under one value. You finish with an order router that combines these ideas.

## Before you start
Use Python 3.10 or newer, because the `match/case` examples need it, and create each named file in a practice folder. Every example is independent. Run each file with `python3 filename.py` on macOS/Linux or `py -3 filename.py` in Windows PowerShell.

You need dictionaries from PY-10 (keys, values, `get()`) and functions from PY-06. A dictionary maps each key to one value, and looking up a key does not scan the whole dictionary.

## Step 1: See the problem with a long chain
The starting point is a function that classifies a day with a chain of `if/elif` tests. It works, but each new day or label means editing the logic, and the chain grows longer with every case.

```python title="day_chain.py" file
def day_type(day):
    if day == "sat" or day == "sun":
        return "weekend"
    elif day == "fri":
        return "almost weekend"
    elif day in ("mon", "tue", "wed", "thu"):
        return "weekday"
    else:
        return "unknown"


for d in ["sat", "fri", "mon", "xyz"]:
    print(d, "->", day_type(d))
```

```bash title="Terminal" verify="run"
python3 day_chain.py
```

```text title="Expected output"
sat -> weekend
fri -> almost weekend
mon -> weekday
xyz -> unknown
```

Notice that the logic is only a lookup from a day to a label. The chain mixes that data into code, which is what the rest of this lesson separates.

## Step 2: Replace the chain with a dictionary
Make the keys the cases and the values the results. Then `get(key, default)` replaces the whole chain. Adding a case is adding a line of data, not a new `elif`.

```python title="day_lookup.py" file
DAY_TYPE = {
    "mon": "weekday", "tue": "weekday",
    "wed": "weekday", "thu": "weekday",
    "fri": "almost weekend",
    "sat": "weekend", "sun": "weekend",
}

print(DAY_TYPE.get("sat", "unknown"))
print(DAY_TYPE.get("xyz", "unknown"))

DAY_TYPE["hol"] = "holiday"
print(DAY_TYPE.get("hol", "unknown"))
print(len(DAY_TYPE))
```

```bash title="Terminal" verify="run"
python3 day_lookup.py
```

```text title="Expected output"
weekend
unknown
holiday
8
```

Each day appears as its own key, so there is no `or` and no `in (...)` test. The dictionary also grew from seven to eight entries without touching any logic.

## Step 3: Choose how a missing key behaves
The default case is decided by how you read the dictionary. `d[key]` raises `KeyError` on a miss, `d.get(key)` returns `None`, and `d.get(key, default)` returns your own default, which is the dictionary version of `case _:`. An explicit `if key in d:` test lets you branch before reading.

```python title="default_case.py" file
DAY_TYPE = {"fri": "almost weekend", "sat": "weekend"}

print(DAY_TYPE["sat"])
print(DAY_TYPE.get("xyz"))
print(DAY_TYPE.get("xyz", "unknown"))

try:
    DAY_TYPE["xyz"]
except KeyError as error:
    print("KeyError:", error)

key = "fri"
if key in DAY_TYPE:
    print("found", DAY_TYPE[key])
else:
    print("missing", key)
```

```bash title="Terminal" verify="run"
python3 default_case.py
```

```text title="Expected output"
weekend
None
unknown
KeyError: 'xyz'
found almost weekend
```

Use `d[key]` when a miss is a bug that should stop the program, and `d.get(key, default)` when a miss is a normal outcome with a fallback answer.

## Step 4: Compare with match/case
The same lookup written with `match/case` uses `|` to join several values into one case and `case _:` as the catch-all. Running both side by side shows they give the same answers. The dictionary version holds the cases as data, while `match` holds them as code.

```python title="day_match.py" file
def day_match(day):
    match day:
        case "sat" | "sun":
            r = "weekend"
        case "fri":
            r = "almost weekend"
        case "mon" | "tue" | "wed" | "thu":
            r = "weekday"
        case _:
            r = "unknown"
    return r


DAY_TYPE = {
    "mon": "weekday", "tue": "weekday",
    "wed": "weekday", "thu": "weekday",
    "fri": "almost weekend",
    "sat": "weekend", "sun": "weekend",
}

same = True
for d in ["mon", "fri", "sun", "xyz"]:
    from_match = day_match(d)
    from_dict = DAY_TYPE.get(d, "unknown")
    print(d, from_match, from_dict)
    same = same and from_match == from_dict
print("same results:", same)
```

```bash title="Terminal" verify="run"
python3 day_match.py
```

```text title="Expected output"
mon weekday weekday
fri almost weekend almost weekend
sun weekend weekend
xyz unknown unknown
same results: True
```

A `case "sat" | "sun":` line becomes two dictionary keys with the same value. `case _:` becomes the second argument of `get()`.

## Step 5: Store functions in a dispatch table
A dictionary value can be a function. Map each command to the function to call, then look it up and call it. Store the function itself, so there are no parentheses in the dictionary. A lambda is a handy one-line function for a tiny case.

```python title="calc_dispatch.py" file
def add(a, b): return a + b
def sub(a, b): return a - b


OPS = {"+": add, "-": sub,
       "*": lambda a, b: a * b}


def calc(a, op, b):
    func = OPS.get(op)
    if func is None:
        return "bad operator"
    return func(a, b)


print(calc(6, "+", 3), calc(6, "*", 3), calc(6, "/", 3))
print(calc(6, "-", 3))
print(OPS["+"](2, 5))
```

```bash title="Terminal" verify="run"
python3 calc_dispatch.py
```

```text title="Expected output"
9 18 bad operator
3
7
```

`OPS.get(op)` returns `None` for an unknown operator, so the `is None` test is the default case. `OPS["+"](2, 5)` shows the two steps in one line: pick the function, then call it.

## Step 6: Build a menu with actions
A menu is a dispatch table whose keys are what the user chooses. Give `get()` a lambda as the default so the result is always callable, and the call can never fail on a bad choice.

```python title="menu_actions.py" file
def start(): return "Starting"
def stop():  return "Stopping"


MENU = {"1": start, "2": stop}
choice = "2"
action = MENU.get(choice, lambda: "Invalid")
print(action())

for choice in ["1", "9"]:
    print(choice, MENU.get(choice, lambda: "Invalid")())
```

```bash title="Terminal" verify="run"
python3 menu_actions.py
```

```text title="Expected output"
Stopping
1 Starting
9 Invalid
```

The key `"2"` is a string, so the tested value must also be the string `"2"`. This script uses fixed choices so it needs no typing at the keyboard.

## Step 7: Group many keys with one value
When several keys share a value, a loop can expand a short list of groups into a flat dictionary. Each group is a tuple of keys plus one value. This avoids writing the same value over and over by hand.

```python title="group_keys.py" file
RATE = {}
for keys, v in [(("A", "B"), 10), (("C",), 20)]:
    for k in keys:
        RATE[k] = v
print(RATE)
print(RATE["B"], RATE.get("D", 0))
```

```bash title="Terminal" verify="run"
python3 group_keys.py
```

```text title="Expected output"
{'A': 10, 'B': 10, 'C': 20}
10 0
```

This is the dictionary form of `case "A" | "B":`. Note that `("C",)` needs the trailing comma to be a one-item tuple.

## Step 8: Decide between a dictionary and match
A dictionary needs keys that are hashable and equal to the tested value. It cannot test a range such as `score >= 90`, a type, or a shape. Keep `if/elif` or `match` for those, and use a dictionary when the cases are fixed values. Because the table is plain data, you can also load it from JSON or a config file.

```python title="dict_or_match.py" file
import json


def grade(score):
    if score >= 90:
        return "A"
    elif score >= 80:
        return "B"
    return "C"


def describe(value):
    match value:
        case int():
            return "an integer"
        case str():
            return "a string"
        case [x, y]:
            return f"a pair {x},{y}"
        case _:
            return "something else"


print(grade(95), grade(85), grade(40))
print(describe(7), describe("hi"), describe([1, 2]), describe(2.5))

text = '{"mon": "weekday", "sat": "weekend"}'
table = json.loads(text)
print(table.get("sat", "unknown"), table.get("tue", "unknown"))

POINTS = {(0, 0): "origin", (0, 1): "up"}
print(POINTS.get((0, 1), "far"))

try:
    bad = {["a"]: 1}
except TypeError as error:
    print("TypeError:", error)

print({1: "int"}.get("1", "no match"))
```

```bash title="Terminal" verify="run"
python3 dict_or_match.py
```

```text title="Expected output"
A B C
an integer a string a pair 1,2 something else
weekend unknown
up
TypeError: unhashable type: 'list'
no match
```

Ranges and type checks stay in `grade()` and `describe()`. Tuples work as keys, lists do not, and the integer `1` does not equal the string `"1"`.

## Step 9: Avoid the dispatch mistakes
The classic mistake is writing parentheses in the dictionary. `{"1": start()}` calls `start()` immediately while the dictionary is built and stores its result, a string, instead of the function. Every function runs at build time, even if you never pick it.

```python title="dict_pitfalls.py" file
calls = []


def start():
    calls.append("start")
    return "Starting"


def stop():
    calls.append("stop")
    return "Stopping"


wrong = {"1": start(), "2": stop()}
print(calls)
print(wrong["1"])

calls.clear()
right = {"1": start, "2": stop}
print(calls)
print(right["1"]())
print(calls)

try:
    print(wrong["1"]())
except TypeError as error:
    print("TypeError:", error)
```

```bash title="Terminal" verify="run"
python3 dict_pitfalls.py
```

```text title="Expected output"
['start', 'stop']
Starting
[]
Starting
['start']
TypeError: 'str' object is not callable
```

With the correct table nothing runs until you pick a key and add the call parentheses: `right["1"]()`. Calling the stored string fails because a string is not callable.

## How it works
A dictionary is a hash table. Python hashes the key to find its slot, so a lookup takes about the same time whether the table holds five cases or five thousand; this is O(1) on average. A `match` or `if/elif` chain instead tests the cases in order, so a case near the end costs more.

For the lookup to work, a key must be hashable and must equal the value you test. Strings, integers, and tuples of those qualify; lists and dictionaries do not. `d.get(key, default)` plays the role of `case _:`, and `d[key]` is the choice when a miss should raise `KeyError`. When the values are functions, you store the function object without parentheses and call the one you pick with `OPS[op](a, b)`. Dictionaries cannot test ranges, guards, or shapes, so those cases stay in `if/elif` or `match`.

## Common errors
### `KeyError: 'xyz'`
`d[key]` raises this error when the key is absent. Use `d.get(key, default)` when a miss is normal, or test `if key in d:` first.

### `TypeError: 'str' object is not callable`
You stored the result of a call instead of the function, for example `{"1": start()}`. Remove the parentheses inside the dictionary and call the chosen function afterwards, as in `MENU["1"]()`.

### `TypeError: unhashable type: 'list'`
Dictionary keys must be hashable. Use a tuple instead of a list, such as `("a", "b")`.

### The lookup always returns the default
The tested value must equal the key exactly. `1` and `"1"` are different keys, and `"Sat"` does not equal `"sat"`. Convert the input first, for example with `str(value)` or `value.lower()`.

question: Which dictionary call is the equivalent of `case _:` in a `match` statement?
options:
  - `d[key]`
  - `d.get(key)`
  - `d.get(key, default)`
answer: 2
explanation: `d.get(key, default)` returns your fallback when the key is missing, which is what the catch-all case does. `d[key]` raises `KeyError` and `d.get(key)` returns `None`.

question: In a dispatch table, you store the function by writing its name followed by parentheses, such as `{"1": start()}`.

explanation: Parentheses call the function and store its result. Store `start` without parentheses and call the chosen function after the lookup.

## Recap
- A dictionary turns cases into data: keys are the cases, values are the results, and lookups stay fast however many cases you add.
- `d.get(key, default)` mimics `case _:`, while `d[key]` raises `KeyError` when a miss should be an error.
- Store functions without parentheses and call the one you pick, and keep `if/elif` or `match` for ranges, conditions, and shape tests.

## Final practice: Order Router
The cheat sheet has no single combined program, so this one uses its ideas together. Create `order_router.py`; it groups shipping zones with one price, dispatches each order command to a function, falls back to a default for unknown commands and zones, and uses an `if` chain for the range-based customer tier.

```python title="order_router.py" file
# Order Router - dictionaries in place of match / case
SHIPPING = {}
for zones, price in [(("north", "south"), 5), (("east",), 8), (("west", "islands"), 12)]:
    for zone in zones:
        SHIPPING[zone] = price


def total(subtotal, discount):
    return subtotal - discount


def refund(subtotal, discount):
    return -subtotal


def ship(subtotal, discount):
    return 0


COMMANDS = {"pay": total, "refund": refund, "ship": ship}


def handle(order):
    func = COMMANDS.get(order["cmd"])
    if func is None:
        return "unknown command"
    return func(order["subtotal"], order["discount"])


def tier(subtotal):
    if subtotal >= 100:
        return "gold"
    elif subtotal >= 50:
        return "silver"
    return "basic"


orders = [
    {"cmd": "pay", "zone": "north", "subtotal": 120, "discount": 20},
    {"cmd": "refund", "zone": "east", "subtotal": 60, "discount": 0},
    {"cmd": "ship", "zone": "islands", "subtotal": 30, "discount": 0},
    {"cmd": "swap", "zone": "moon", "subtotal": 10, "discount": 0},
]

for number, order in enumerate(orders, start=1):
    result = handle(order)
    fee = SHIPPING.get(order["zone"], "n/a")
    print(number, order["cmd"], result, "fee:", fee, "tier:", tier(order["subtotal"]))

print(SHIPPING)
```

```bash title="Terminal" verify="run"
python3 order_router.py
```

```text title="Expected output"
1 pay 100 fee: 5 tier: gold
2 refund -60 fee: 8 tier: silver
3 ship 0 fee: 12 tier: basic
4 swap unknown command fee: n/a tier: basic
{'north': 5, 'south': 5, 'east': 8, 'west': 12, 'islands': 12}
```

- `SHIPPING` is built with the grouping loop from Step 7, so `"north"` and `"south"` share one price, and the unknown zone `"moon"` falls back to `"n/a"` through `get()`.
- `COMMANDS` is a dispatch table from Step 5: the functions are stored without parentheses, and the unknown command `"swap"` returns `"unknown command"` instead of raising an error.
- `tier()` stays an `if/elif` chain because it tests ranges, which a dictionary cannot do.
