## Why this matters
Docstrings explain a function’s contract, while built-ins provide tested operations for common tasks. Good documentation and the right built-in reduce duplicated code.

## What you will build
A runnable set of examples about documenting functions and built-in functions.

## Before you start
Create each named script in a Python 3.10+ environment and run the commands below.

## Step 1: Write and read a docstring

```python title="py_43_1.py" file
def clamp(value, low, high):
    """Return value limited to the inclusive range."""
    return max(low, min(value, high))

print(clamp.__doc__)
```

```bash title="Terminal" verify="run"
python3 py_43_1.py
```

```text title="Expected output"
Return value limited to the inclusive range.
```

## Step 3: Inspect a signature contract

```python title="py_43_3.py" file
def greet(name: str = "friend") -> str:
    return f"Hello, {name}"

print(greet.__annotations__)
```

```bash title="Terminal" verify="run"
python3 py_43_3.py
```


## Step 4: Combine documented behavior

## How it works
Document inputs, outputs, and important exceptions.
Prefer built-ins such as `sum`, `sorted`, and `enumerate` to handwritten loops.
Annotations and docstrings serve different purposes and can coexist.

## Common errors
### Repeating code instead of extracting a function
Give a helper one responsibility and return its result.

### Confusing a return value with printed output
Use `return` for callers and `print` only at the boundary.

### Hiding state or dependencies
Prefer explicit parameters and imports over surprising global behavior.
